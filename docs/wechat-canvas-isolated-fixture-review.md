# 独立匿名完整控制流画布诊断

## 范围与隔离

本阶段使用项目外的独立临时小程序，区别于前一阶段嵌入原项目的 30 条件诊断。构建者报告：27 个来源文件按 b96d1b1 原字节复制并以摘要核验，保留完整 board 控制流与四个组件；统一只读 fixture 禁止网络、storage 和业务写入，App 为空。仅使用匿名五棋子及本地样本，不登录、不启动业务后端、不读取真实业务数据。上述隔离属于构建事实，不等同本轮网络抓包证明。

首次用 touristappid 官方开窗返回 APPID_ERROR（不存在此 AppID），未绕过错误或修改安全设置。后按明确授权，只读比较原项目公开 AppID 标量与官方可管理清单，确认名称为“九州科技”；仅将该公开标量用于临时夹具配置后开窗成功。未复制 AppSecret、账号或私有配置，没有上传、发布、真实微信交换或新增自动化端口。本文不记录实际 AppID。

## 工具定位边界

CUA 明确显示独立窗口 anonymous-canvas-diagnostic、匿名首页与战术画布。官方 CLI 使用开窗时的项目路径执行只读表达式，却返回首页单层栈与 canvas 为 null，与当时实际可见 board 不符；路径被系统展开为另一等价前缀时另曾返回无法找到 runtime。

已检查 initializer、debugger、automator 文档、工具清单及本机帮助：相关工具仅公开 project 路径选择，没有 window ID/runtime ID 参数。因此没有猜测隐藏参数或关闭原项目来绕开定位。此后本轮交互完全使用 CUA，不使用该定位不符的 CLI 导航、刷新、点击或数值结果；未获得可靠的 canvas rect、节点位图尺寸、内页 scrollTop 或运行时栈数。

## 实际过程与结果

设备为 iPhone 14/15 Pro Max（430×932）。最初列表仅有一个入口，完成一次首页→列表→board 首屏观察正常，但不能算长列表条件。构建者随后仅补齐 80 条匿名占位行和顶部、底部入口；本轮实际确认更新后的可见标题、行 1 至 80 与两个按钮后执行以下两条路径：

| 条件 | 实际路径 | 首入 CUA 结果 |
| --- | --- | --- |
| 顶部入口 | 匿名首页按钮→匿名列表顶部按钮→完整 board | 场地可见且非空，位于工具区下方，未见覆盖；初始画布、0 / 2 秒显示 |
| 长列表底部入口 | 从 board 实际返回列表，滚到第 80 行及底部按钮，再实际点击进入 board | 场地及匿名棋子可见，仍在工具区下方，未见上移覆盖；初始画布、0 / 2 秒显示 |

两次均先观察真实窗口首次屏幕，没有先滚动目标画布页或通过延时、重开消除异常。底部路径中可见开发者工具外层预览上移，顶部设备导航区离开可见区；不能将外层移动等同于目标页 scrollTop 或画布错层。三层链指实际点击形成的首页→列表→board，不是 CLI 页栈测量结论。

本轮没有测试阶段切换、播放、编辑、导出或其他未注册目的页。截图证据仅在本机交互记录中，未入仓库。
