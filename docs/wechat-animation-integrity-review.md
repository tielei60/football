# 微信小程序动画编辑完整性复核

## 范围与证据口径

本记录使用独立动画验证副本。匿名战术 id=7 通过业务层初始化，不是通过小程序界面创建；初始包含 4 个阶段、3 条曲线、5 个初始球员及独立演示参与者。该编号仅用于标识隔离验证对象，不代表真实球队业务事实。

本轮通过实际界面导航进入阶段与属性编辑页（compose）。下文区分实际界面操作、受路由及对象编号守卫的只读对象核验，以及后端数据库比对，不以 VM 调用处理函数或模板渲染替代真实操作通过。界面阶段数量或保存计数也不等于持久化已成功。

## 第二阶段删除、取消与撤销

| 实际操作 | 已观察结果 |
| --- | --- |
| 删除第二阶段后取消确认 | 仍为 4 个阶段，界面保存计数为 0 |
| 再次删除并确认 | 草稿变为 3 个阶段，顺序为原第 1、3、4 阶段，界面保存计数为 1 |
| 撤销 | 恢复 4 个阶段，界面保存计数恢复为 0 |
| 再次删除 | 停留在删除后的草稿状态，尚未据此宣称持久化 |

此时独立后端核验初始战术对象及 24 张业务表均未变化，战术仍为初始第 1 版。确认删除只影响草稿的观察，与数据库未变化分别核验，不能混同为已经保存删除结果。

## 撤销后完整对象恢复

随后再次通过实际界面执行撤销。仅在路由和战术 id 守卫通过后只读导出该匿名 board，由后端与初始对象进行 deepStrictEqual 比对。完整对象相等，包括参与者、阶段、运行路径，以及全部端点和控制点；数据库仍未变化。

这证明本轮已观察的删除/撤销过程恢复了该匿名对象，而不只是恢复阶段数。它不代表所有动画组合、任意曲线或保存失败路径均已覆盖。

## 删除中间阶段后的保存与重入

实际删除中间阶段并确认后，只点击保存 1 次，随后返回列表并重新进入 compose。重入后显示 3 个阶段，顺序为原第 1、3、4 阶段，界面保存计数为 0。

后端独立按原阶段索引 [0, 2, 3] 复制并重新编号，构造预期完整 board；保存结果与该预期对象深等。匿名战术 id=7 恰好新增 1 个版本，总计 2 版，未出现重复保存版本。

细项核验如下：

- 删除与被移除阶段相邻的前两条运行路径（runs）。
- 原第三条曲线的全部 pieceId、bend 保持不变，仅 fromStage 从 2 改为 1；原第 3、4 阶段的端点保留。
- 初始棋子（pieces）、独立参与者（participants）及其他 board 元字段均未改变。
- 既有 6 套战术的 27 个版本、其余 22 张业务表均未改变；另一受保护验证副本的 25 张表及来源摘要也未改变。

以上是本组实际保存、重入与数据核验结果，仅覆盖指定匿名战术的中间阶段删除路径，不代表全部动画功能通过。

## 初始画布属性的作用范围

通过实际界面将“初始画布”范围中的第一个球员改为名称“初始验收一”、号码 0、位置 GK，应用后只保存 1 次。返回列表并重入后，这三项属性仍保留。切换到“演示参与者”范围，第一个参与者仍为“演示1”、号码 1、位置 MF，没有随初始画布修改。

后端独立构造仅改变 pieces[0] 上述三项属性的预期对象，与保存后的完整 board 深等。pieceId、其他初始棋子、参与者、阶段及运行路径均未改变。匿名战术 id=7 恰好新增 1 版，总计 3 版；既有记录、另一受保护验证副本及来源摘要保持不变。

本组核实了初始画布修改不会连带修改演示参与者，并覆盖号码 0 的保存重入；不将其外推为演示范围反向隔离或号码清空已经通过。

## 演示参与者属性的独立保存

通过实际界面将第一个演示参与者改为名称“演示验收一”、号码 0、位置 ST，应用后只保存 1 次。返回列表并重入后，三项属性仍保留；初始画布范围仍为“初始验收一”、号码 0、位置 GK，没有被演示范围的修改覆盖。

后端独立构造仅改变 participants[0] 上述三项属性的预期对象，与保存后的完整 board 深等。参与者标识、全部初始棋子、阶段及运行路径均未改变。匿名战术 id=7 恰好新增 1 版，总计 4 版；其他既有记录、另一受保护验证副本及来源摘要均保持不变。

至此，本次两个范围的指定属性修改分别完成真实保存、重入和完整对象核验，不混同为所有属性组合均已覆盖。

## 两个范围的号码清空

官方输入工具提交空字符串时返回参数错误 -32602，输入没有送达页面。这是本次工具调用限制，不作为产品输入失败。随后使用实际 CUA 操作，先确认号码框获得焦点，再全选并按 BackSpace，分别将初始画布和演示参与者两个范围的号码从 0 清空，界面显示未编号。

两个范围各应用一次，共 2 条命令，整体只保存 1 次。重新进入后，两个范围仍为未编号，先前的名称和位置保持不变。

后端独立预期对象仅删除 pieces[0].shirtNumber 与 participants[0].shirtNumber 两个键，不将它们设为 null 或空字符串。保存后的完整 board 与该预期深等，匿名战术 id=7 恰好新增 1 版，总计 5 版；其他历史记录、另一受保护验证副本及来源摘要没有变化。

## 未应用输入时切换页签

实际在演示参与者姓名框输入“未应用检验”，没有应用或保存。切换到阶段页签时出现统一的“尚未应用输入”确认提示。

- 取消：仍停留属性页签，输入草稿保留，界面保存计数为 0。
- 再次切换并确认丢弃：进入阶段页签。返回属性页签后，恢复已保存的“演示验收一”、未编号、位置 ST，界面保存计数为 0。

该组操作没有写入服务器，覆盖的是尚未应用的输入草稿及页签切换，不等同于已应用但未保存的命令退出保护。

## 已应用未保存时的系统返回保护

实际将演示参与者姓名改为“未保存检验”并应用，界面保存计数为 1，但没有点击保存。点击小程序导航返回后，出现平台提示“战术编排尚未保存，确定离开吗？”。

先取消返回，页面、草稿及保存计数 1 均保留。再次返回并确认离开后，实际落在战术画布页（board），不是列表页。随后从动画入口重新进入，演示范围恢复已保存的“演示验收一”、未编号、位置 ST，界面保存计数为 0。

系统返回后，后端进一步核验该战术整行、5 个历史版本及 24 张业务表，均与号码清空保存后的基线一致，没有额外写入。该数据比对与前述实际界面观察共同完成本组核验。

## 并发预置后的保存保护与取消重载

本组先在实际界面保留旧版本，将演示参与者姓名改为“冲突草稿”并应用，界面保存计数为 1。随后由第二个业务层客户端仅给匿名战术 id=7 的标题追加“·并发核验”，执行 1 次 CAS 保存，恰好生成第 6 版；完整 board 与其他记录不变。这次并发预置是业务层操作，不是小程序 UI 操作。

旧版本界面只点击保存 1 次后，出现核对结果、保留修改且不可直接重试的提示。界面保存及撤销禁用，状态为 conflict=true、busy=false、changes=1。打开重载对话框后取消，草稿仍保留。

后端核验该战术整行、6 个历史版本及 24 张业务表，均与第二客户端保存后的并发基线一致，没有额外写入。

本轮网络工具只支持整行 grep，未提供可安全排除潜在凭据的投影，因此没有读取相关网络记录。未实际读取 HTTP 状态，不能凭泛化界面提示或数据库不变断言已捕获 HTTP 409，也不能据一次点击推定网络请求数量。本节仅记录并发预置条件、实际界面保护行为与数据结果。

实际确认重载后，标题包含“并发核验”，演示参与者恢复已保存名称“演示验收一”、未编号、位置 ST，状态为 conflict=false、busy=false、changes=0。后端再次核验该战术整行、6 个历史版本及 24 张业务表，仍与并发基线一致，没有新增写入。本组完成实际确认重载与数据核验，但 HTTP 状态未读取的边界不变。
