# 本地虚构数据与完整演练

这是可以在自己电脑上重复执行的演练入口，不是需要复制进业务库的 SQL 或数据库附件。所有球员都是虚构成年人，无真实头像、联系方式或身份信息；账号密码每次随机生成，只保存在本次新建的独立演练目录中。无需生产账号，也不需要微信或 Docker。

## 1. 从干净项目启动

安装 **Node.js 24 LTS**（最低 22.13）和 Git。在终端运行：

```sh
git clone https://github.com/tielei60/football.git
cd football/app
npm ci
npm run build
npm run demo
```

已有仓库时，在现有开发分支更新后，从 `app` 目录运行后三条命令即可。不要清理或覆盖原有工作区/数据库。第一次安装和构建需要一些时间；以后代码没变时只需 `npm run demo`。

试用尚未合并的比赛日增强版本时，克隆后先在仓库目录执行 `git switch codex/matchday-experience`，再构建。以相应 PR 的分支与测试记录为准。

终端会给出：

- **网页地址**：`http://127.0.0.1:本次随机端口`，复制完整地址到浏览器。
- **独立数据库路径**与**账号清单路径**。
- 管理员 `demo-admin`，以及球员 `demo-linyuan`（林远）、`demo-zhouze`（周泽）、`demo-guchuan`（顾川）各自的随机密码。
- 本次演练的“继续运行”命令。

同一个服务提供已构建的网页和 API，不必另启前端，不必配置数据库或执行管理员初始化。不要用生产启动命令替代 `npm run demo`。服务固定只监听 `127.0.0.1`，自动选择空闲端口；生产 `FOOTBALL_*`、`HOST`、`PORT` 环境配置不会把它指向业务库或公网。

**停止与继续：**按 Ctrl+C 只停止服务，保留数据。在 `app` 目录复制终端打印的命令，例如：

```sh
npm run demo -- --resume "/本次实际目录/football-demo-随机后缀"
```

这会保留上次修改，不重新灌入数据或重置密码。继续入口只接受带有效演练标记、匹配清单和普通数据库文件的原目录，拒绝任意业务库、被替换的路径或文件符号链接。请勿移动目录或改写清单。

**重新开始：**再次运行 `npm run demo`。每次新建不同目录，不覆盖之前的演练。无需先删除任何库。两份演练建议用不同浏览器配置文件，避免同一 `127.0.0.1` 的登录 Cookie 相互影响。

Windows 请使用 PowerShell 运行终端打印的单引号续跑命令。若提示 `node` 或 `npm` 找不到，请先安装 Node.js 并重新打开终端，使用 `node --version` 确认版本。

系统可能清理临时目录；要长期保留进度请按下方步骤做备份。随机凭据仅用于本地虚构演练，勿公开、提交 Git 或部署到生产。更改密码后，清单中的初始密码不会自动更新。

## 3. 逐步走通业务

建议按顺序进行。**先完成第 1 步的初始对账，再改数据**；修改后统计变化是预期结果。随时可以重新运行 `npm run demo` 得到另一套初始数据。

1. **管理员登录、初始对账**：使用终端中的管理员凭据。查看球队、球员、赛季、两场完赛及统计，按上面的数值核对。分别切换赛季、2026 年、2027 年和对手交锋。
2. **球队与球员资料**：修改虚构球队名称；可用自己创建的非私人 PNG/JPEG/WebP 测试队徽和球员头像上传、预览、移除。新增一个虚构成年人、设置位置/惯用脚/备注，并绑定一个仅本地使用的测试账号。保存后刷新查看。
3. **赛季与号码**：打开跨年赛季名单，确认林远是 19 号而档案为 9 号。可以新建日期重叠的另一赛季，设置不同号码；比赛需显式选所属赛季，不能仅因日期重叠就归入两个赛季。
4. **球员登录与报名**：管理员退出，依次用三个球员账号登录，打开 2 月 7 日比赛，选择参加/不参加/待定。刷新确认各自结果保留，彼此不能替对方报名。球员看不到草稿，也没有管理保存按钮。先恢复初始 1/1/1，以便继续对账。
5. **发布比赛**：管理员打开 2 月 21 日草稿，补赛事、时间、地点、主客场并发布。球员重新登录后能看见；可完成报名后返回管理员。
6. **名单、位置与排阵**：在已发布比赛按报名选人，也可独立添加。设置首发/替补/未知、位置；先让实际出场保持未知。进入战术中心选 7 人制、排阵、拖动球员、画传球/跑动箭头，保存为新战术。打开动画编辑，加入或修改两步并播放，保存版本。将战术关联到比赛。保存、刷新后检查名单和快照。
7. **比分与个人数据**：在本轮新比赛录入本队 2:1，确认实际出场，填入合计 2 个进球和必要助攻、赛后总结，改为已结束。替补可以实际出场；报名不参加但后来到场的球员也可如实记录。未核实的人继续留未知，不要为了填满表格写 0。保存后检查单场、赛季和对应自然年统计变化。
8. **历史不变**：返回 12 月已结束比赛，记下林远 **19 号**和赛时战术。修改林远当前名字/号码、赛季号码，或者归档他；修改预建战术模板、保存新版本，必要时删除模板。回到旧比赛，历史名字、19 号、赛时战术仍应保留。修改比赛地点或赛后分析也不能自动重拍快照。显式移除再添加关联才是重新捕获。
9. **错误路径与并发**：尝试结束日期早于开始日期、负进球、个人总进球大于本队比分、未出场却填进球，应该拒绝且不写入。两个标签页打开同一比赛；A 保存地点，B 以旧版本保存，应该提示数据已更新，而非悄悄覆盖 A。刷新后重新编辑。
10. **取消与权限**：查看预置取消比赛，确认仍保留历史但不计完赛/报名统计；可取消另一场发布比赛。球员不可编辑球队/名单/比分/战术模板。管理员可重置**演练账号**密码，再用新密码登录验证；不用真实账号。球员可改本人密码。
11. **退出与恢复**：停止后用终端打印的 `--resume` 命令重开，确认刚才的名字、赛季、名单、比分及统计保持。备份及恢复副本按下一节验证。

原战术的导出 JSON、重新导入、版本切换、图片导出也可在本地继续试用。导入请仅使用自己从演练库导出的文件。系统打印/手机端不作为当前业务与数据验收的前置条件。

## 4. 备份与恢复副本

备份包含演练密码哈希和业务数据，即使是虚构数据也不要提交到 Git。`backup.mjs` 使用 SQLite 的一致性备份操作，**不要在服务运行时只复制 `demo.sqlite` 主文件**。

macOS/Linux，在仓库根目录，把路径替换为终端打印的本次路径；目标必须尚不存在：

```sh
FOOTBALL_DB_PATH='/本次实际目录/demo.sqlite' node scripts/backup.mjs '/自己选择的新目录/demo-backup.sqlite'
```

PowerShell：

```powershell
$env:FOOTBALL_DB_PATH = 'C:\本次实际目录\demo.sqlite'
node scripts/backup.mjs 'C:\自己选择的新目录\demo-backup.sqlite'
Remove-Item Env:FOOTBALL_DB_PATH
```

恢复演练不覆盖任何原库：先运行另一次 `npm run demo` 获得一个**全新的**演练目录并 Ctrl+C 停止；将其 `demo.sqlite` 改名保留后，把已验证的备份复制成该目录的 `demo.sqlite`，确认没有该目录的服务运行，再使用此新目录的 `--resume` 命令。只操作自己刚创建的新演练目录，不操作原库/生产目录。恢复后的登录密码、数据以**备份时的原演练库**为准，新目录生成的凭据清单不会替换备份里的密码。

恢复副本中改一个虚构球队名称，再回到原库确认未改变。只有备份完成之后再发生的原库修改，不应出现在该备份中。常规部署备份策略见 [部署说明](deployment.md)。

## 5. 自动核对与实现位置

在 `app` 目录：

```sh
npm run demo:check
npm run test:server
npm run check
```

- `demo:check`：独立新库连续验收（329 个 HTTP/SQLite 断言），覆盖权限、跨年/重叠赛季、缺失与零、历史快照、并发保护及真实备份恢复；不会读取当前演练库或生产库。
- `test:server`：含虚构种子及启动/继续/拒绝覆盖回归。
- `check`：构建、类型、单元、服务端及资源体积检查。
- 浏览器回归另用 `npx playwright install chromium && npm run test:e2e`，需要允许 Chromium 正常启动的本机环境。当前云电脑受浏览器进程启动策略限制，不能把“未运行”的自动浏览器用例写成通过；真实界面演练证据见 [最终业务演练](final-business-rehearsal.md)。

只生成数据、不启动服务：`npm run demo:seed`，或仓库根目录 `node scripts/create-demo.mjs`。输出是含随机演练密码的 JSON，请勿重定向进仓库或公开日志。

实现文件：`scripts/create-demo.mjs`（固定虚构场景+随机凭据）、`scripts/start-demo.mjs`（隔离启动/继续）、`server/demo-rehearsal.test.mjs`、`server/demo-launcher.test.mjs`。不提交二进制数据库，不提供固定公用密码，不接受自定义目标库路径。
