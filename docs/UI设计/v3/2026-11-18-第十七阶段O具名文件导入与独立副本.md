# 第十七阶段 O：具名文件导入去重与独立副本

## 修复背景及原生范围

原实现虽然解析备份中的collectionName，但创建导入任务时始终覆盖成随机名，同文件重新选择不会命中原收据。本轮经授权的最小修复：具名备份默认保留名称，同名相同内容核对去重，同名不同内容409停止；仅明确勾选“作为独立副本导入”才生成新任务名。无名文件保持追加语义，旧pending任务保留原名。

代码专项及独立审查已完成，全量1161项通过（代码级证据，不替代下述操作）。本批阶段25释放后同步已审四个相关源码文件，在新匿名隔离库实际操作；不接触正式球队数据。

## 真实文件操作

准备A、B两个匿名JSON，各1套战术和1个历史版本。两者collectionName相同，但B战术标题及球员坐标不同。实际点击选择JSON文件，在macOS系统文件选择器选择磁盘文件，未mock选择回调或用API导入代替操作。

1. **A首次导入**：预览显示小型复选项默认未选；确认框明确相同内容不重复、同名不同内容停止。确认后真实POST返回201，新增1套。
2. **重新选择A**：再次经真实选择器选同文件并确认，真实POST返回200、`receiptVerification=verified`、`repeated=true`、`importedCount=0`。UI显示“此前导入已确认，本次未重复新增战术”。全业务表快照与首次导入后完全一致。
3. **选择B，保持默认未选**：确认导入后真实POST返回409，UI显示名称已用于不同内容，不展示旧成功结果。全业务表与首次导入后完全一致。
4. **明确选择独立副本**：点击紧凑复选项，按钮变为“确认导入独立副本”，确认框明确即使此前导入过也会追加。先取消，零新增POST且全业务数据不变；再次打开并确认后真实返回201，新增1套B副本。
5. 实际进入A、B画布，读取完整模型及版本，分别对账SQLite与原文件。

首次系统路径输入中文出现输入工具丢字，改用内容完全相同的ASCII文件名a.json/b.json后选取成功。保留了操作问题，不将失败尝试算作文件已导入。

## 数据审计

- 重复A、冲突B、取消副本三处全业务表快照均等于A首次成功后的快照，不仅检查数量。
