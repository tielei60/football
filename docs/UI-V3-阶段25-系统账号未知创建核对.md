# UI V3 第二十五阶段：系统账号未知创建核对

## 实现检查与修复

系统账号创建的未知结果保存在模块内存中。刷新时应先查询用户名、明确找到已有账号，不能擅自重发或把查询失败当成未创建。

发现前端严格区分大小写，服务端 SQLite 使用 `COLLATE NOCASE`，可能错误提示“未查询到”。修复仅把 ASCII A–Z 折叠为小写，与 SQLite 规则一致。服务端允许 Unicode 用户名，所以不能对整个字符串做 Unicode 小写：`管理员A` 与 `管理员a` 同名，`Ädmin` 与 `ädmin` 不同名。独立审查用内存 SQLite 核对了这些事实。

新增 6 项页面行为回归：旧实现 2 项失败，修复后通过，覆盖大小写、未知锁禁止重复提交、查询失败保持锁定、解除取消/确认、解除后不自动创建。精确逆投影保持原 SHA，未放宽其他业务契约。独立专项 63/63 通过。

## 本地原生操作与数据库对账

新建匿名 SQLite 库和本机专用系统管理员；代理只干预本批 `/api/system/accounts` 创建请求，其他请求透传。未记录密码或 Authorization，未使用柏林正式数据。

### A：服务端已创建，回执丢失

- 原生填写 `stage25-created` 并确认创建。代理转发成功响应后断开客户端连接。
- 页面显示“创建结果未确认”，密码清空、再次创建及账号修改锁定。
- 点击“重新载入核对”，显示同用户名已有账号，并明确不确认上次密码是否一致。
- 数据库该用户名恰好 1 条，普通管理员、首次登录须改密。
- 代理累计 POST 1 次、实际转发 1 次、丢弃回执 1 次；核对没有自动重试。

### B：请求完全未送达

- 原生填写 `stage25-not-sent` 并确认创建。代理在转发前断开。
- 页面同样未知锁定；刷新后显示“已核对，确认未创建”。
- 取消解除：锁定保留。再次打开并明确确认：解除锁定，密码仍为空，没有自动创建。
- 数据库该用户名 0 条。两场景合计 POST 2 次、转发 1 次、断开 2 次。
- 本轮未再次输入密码发第三次创建，因此不把“解除后再次实际创建成功”标为原生通过。

原生证据在本地 `football-ui-v3-interaction/ui-stage25`，包括截图、请求计数和数据库断言结果。账号列表模拟回归与上述真实数据库创建分别记录，不混为同一种证据。

## 仍未覆盖

模块未知状态不跨进程持久化；同名唯一约束只能防数据库重复，不能等同重启后恢复体验完整。原生查询失败后的恢复仅自动回归覆盖；更多网络时序、跨进程、解除后再次创建等仍待补验。
