# 原生画布最小匿名诊断记录

## 范围与安全边界

本轮在微信开发者工具 2.02.2609250、基础库 SDK 3.17.6 的 430 宽模拟设备上执行，不是真机测试。诊断页仅含匿名占位行、普通色块和固定网格，不登录、不请求业务接口、不读写球队资料。

两条临时诊断路由及其代码只用于本机诊断，不随本记录提交。原业务页的尺寸与 loading 同次提交候选已因真实反例回退；本记录不代表该候选有效，也不代表 board 错层已经修复。

## 方法

匿名列表有 80 行，顶部和底部各有真实按钮。入口通过实际按钮点击，目标通过 navigateTo 创建新实例。顶部直接进入与实际滚至列表底部再进入分别比较。组间用系统返回或官方 navigateBack 返回列表，不调用页面 handler，不注入 data。

每次目标首次进入先观察 CUA 实际窗口，再用官方 CLI 截图及只读几何查询；目标页不先滚动、不增加延时、不重开项目以掩盖异常。截图只保留本机，不进入 Git，本记录不包含截图或私有路径。

三个渲染条件：
- plain：普通 view 色块，无 canvas。
- empty：原生 canvas，仅保留边框，不执行绘制。
- grid：普通 view 内的 canvas，仅 onReady 一次绘制绿色网格及上下紫条，无滚动重绘、计时器或业务状态。

## 工具与证据限制

长列表滚到底后继续滚动时，开发工具外层模拟器预览也发生上移，部分手机导航区离开可视窗口。它与目标页面的 scrollTop 是不同层级：底部入口目标的页面 scrollTop 实读仍为 0。屏幕绝对位置因此与顶部入口不同，但色块或网格相对于占位区未见错位。本轮只记录该现象，不据此推断业务异常根因。

只读 selector fields 的 node 查询返回“An object could not be cloned”。即使在回调仅提取 node.width/node.height 等 primitive 返回，仍失败。因此本轮没有取得 Canvas 节点位图尺寸，不将 DOM boundingClientRect 冒充位图尺寸。空画布的视觉空白是预期条件，也不据此证明底层位图状态。

## 当前结论与未验证项

430 宽的固定普通 view、一次绘制、无业务依赖模型，在这 12 次首次进入条件下未复现业务 board 的上移覆盖控件现象。大几何也未复现，说明“仅尺寸较大或部分离屏”在该最小模型里尚不足以触发问题。

这不是根因证明，不排除业务绘制路径、页面生命周期、工具合成或其他条件的组合，也不撤销此前真实 board 的 320/430 失败证据。未测本模型的 320、真实手机、长期稳定性及下一轮 renderer 条件。本轮记录冻结时设备仍为 430、临时诊断代码仍保留待后续单变量测试与最终精确恢复，不能提前声称设备或路由已恢复。
