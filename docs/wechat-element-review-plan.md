# 微信小程序全界面元素审查计划

## 1. 状态与范围

本文件先建立页面清单、元素清单、验收标准及证据矩阵，供后续逐项审查、修复、复测使用。**目前仅制定计划，不表示全站审查通过，不表示全部 WCAG 合规，也不表示所有输入已通过真机验证。**

以当前 `miniprogram/app.json` 的 25 个路由与 4 个共享组件为基线。使用隔离演练数据，不修改生产数据。保留既有业务、权限及设计配色，不以审查名义引入无关功能。此前局部截图、模板编译和逻辑测试可作为基线，不能替代本计划的完整验收。

角色：A 为管理员，P 为球员。只读页面仍需鉴权；表中角色描述不是授予访问权限。管理专用页面须分别验证合法入口与无权限直达。

## 4. 通用验收标准

### 4.1 布局与文字

- 320×640、375×812、较宽屏分别查看顶部、中段、底部；仅首尾截图不能声称完整连续覆盖。
- 不出现横向溢出、文字竖排、零宽控件、关键按钮被裁或滚动不可达。
- 键盘、胶囊、安全区、固定栏不能遮住当前输入及主要操作。
- 长姓名、队名、地址、选项、六位统计数字能够阅读；标题不靠省略隐藏关键信息。
- 标签和字段之间距离应小于字段组之间距离；对齐与间距统一，但不为统一强改已正常的原生控件。

### 4.2 按钮与触控

- 主次操作、危险操作及禁用状态明确，不能只靠颜色区分。
- 不继承原生默认固定宽度；并排按钮具有独立、不重叠的点击区域。
- 主要触控目标建议至少 44×44 实际像素；紧凑工具需单独测命中范围和相邻间距，并记录偏差。
- **84rpx 在 320px 宽屏约为 35.8px，不等于 44px。** 用实际边界测量，不凭 rpx 声称达标，也不一刀切放大所有视觉按钮。
- 快速重复点击不能重复提交；disabled 必须有相应逻辑保护。

### 4.3 表单与输入

- 逐个登记 34 处输入及循环实例，不仅验证共享 CSS。
- 空值、有值、中间插入、删除、粘贴、中文输入、焦点切换均正确；不每键 trim 或强制移动光标。
- 单行光标与文字对齐；多行首行、末行、换行、auto-height 分别核查。
- 标签持续可见，placeholder 只作补充；必填、格式要求和错误能够理解。
- 错误后保留非敏感输入；敏感内容按既定生命周期清理，不写日志、截图或持久化调试数据。
- 提交中防重复，冲突不盲覆盖，结果未知先核对；取消不写数据。
- 不能以静态高度公式替代实际原生光标验证。

### 4.4 选择组件

- 展示字段名称和当前值；长标签换行、长列表可滚动、确认/取消可达。
- 临时选择仅确认后生效；取消保留原值；滚动不随每次点选强制跳动。
- 日期明确周几；年份快速选择不提前提交；时间列不留大块空白。
- 普通列表、日期、月份、年份和时间分别测试，不相互代替。

### 4.5 配色与可访问性

- 普通文字目标对比度至少 4.5:1，大字至少 3:1；关键控件边界及状态至少 3:1。
- 按实际像素判断字号，不把小字加粗当作“大字”豁免；禁用元素单列检查，不能因此降低正常提示文字可读性。
- 紫色主题集中管理；状态配合文字/图形，不只变色。
- 操作元素具有可理解名称，选择/禁用状态可识别；装饰不重复朗读。
- 弹层无触摸穿透；焦点及取消/确认行为一致。VoiceOver/TalkBack 未实际测试则记“未测”，不宣称已符合标准。
- 不引入无必要弹窗或动效；成功反馈不阻断继续使用；必要风险提示不能为了简洁删除。

### 4.6 图片、地图、画布与导出

- 缺图、加载、解码失败、重试和预览失败都有可恢复状态。
- 地图无坐标不能跳默认位置；查看位置不额外索取当前位置。
- 地图/Canvas 不盖住弹层，关闭后恢复；触摸取消不遗留半次操作。
- 只读页面不承诺可编辑；未保存内容、历史快照和当前模板区分明确。
- 导出区分“临时生成”“另存成功”“平台不支持”，不得把临时文件称作已完成持久备份。

### 4.7 权限、异步与数据语义

- A/P 分别走真实入口；管理页面无权限直达也受保护，隐藏按钮不是权限校验替代品。
- 按适用性覆盖 loading/error/empty/success/disabled/busy/conflict/unknown。
- 离页、后台、换账号后旧响应不能修改新页面或跳走新账号。
- 报名不等于实际出场，未知不等于零，历史号码不等于当前号码，年份不等于赛季。
- 无权限、请求失败与真实空集合不能混为同一种空态。

## 5. 状态与证据矩阵

| 类型 | 标准场景 | 证据要求 |
| --- | --- | --- |
| 页面状态 | 首次加载、刷新、成功、错误重试、空集合 | 实际渲染截图；记录注入还是网络触发 |
| 内容边界 | 0/1/多条、长中文/英文、未知/零、大数字 | 顶/中/底截图及字段输入说明 |
| 表单 | 空/有值、聚焦、中间编辑、粘贴、中文、错误、保存中 | 真实点击输入；光标截图须捕获可见帧 |
| 选择器 | 短/长/空列表、已选、取消/确认、滚动、日期周几 | 实际交互与返回值断言 |
| 写操作 | 成功、4xx、409、网络未知、重复点击、离页晚回 | 隔离数据及请求/结果核对；模拟测试单独标注 |
| 权限 | A/P、只读、过期、换账号、无权限直达 | 各角色入口与服务端拒绝验证 |
| 原生能力 | 系统选图/选点/文件/另存、取消、拒绝、不支持 | 工具或真机实际结果；不可用明确记录 |
| 可访问性 | 名称、状态、焦点顺序、读屏、触控、对比 | 测量/实际辅助技术证据；未测不推定通过 |

每项记录字段：

`页面｜角色｜元素/选择器｜状态｜屏幕尺寸/设备/基础库｜步骤｜预期｜实际｜证据｜结论｜问题编号｜修复后复测`

结论使用“待审 / 通过 / 不通过 / 不适用 / 受工具限制未验证”，不使用含糊“基本正常”。

证据分层：
1. **静态/自动化逻辑**：模板和单元测试证明结构/逻辑，不证明真实排版与触控。
2. **工具注入状态渲染**：证明该输入状态的界面，不证明网络链路或数据库一致性。空数组注入必须同时检查相关计数，避免跨上下文数组和残留数字误导。
3. **实际操作**：点击、键入、取消、导航、真实隔离请求及数据核对。
4. **真机/辅助技术**：手机键盘、系统能力、读屏等独立记录，工具通过不自动继承。

## 6. 执行与修复顺序

1. 固定角色、演练数据、设备尺寸与版本；建立清单，不边采集边热重载。
2. 先审共享组件，再审常用球员页、管理表单、地图媒体、战术工具。
3. 每组先只读定位，再集中最小修复；保留 handler、权限和数据语义。
4. 修复后跑相关逻辑测试与官方模板编译，再由实际工具复验相同操作和相邻状态。
5. 优先级：权限/数据损坏或无法操作为 P1；截断、焦点、状态误导为 P2；一致性与非阻断视觉问题为 P3。
6. 分组记录剩余问题与未测项。不得用自动化全绿或少量截图替代全元素通过结论。

## 7. Modern Web Guidance 使用记录与原生适配

本次通过 `modern-web-guidance` 的广泛审查 `list`，检索并完整读取以下指南：

- `accessibility`：标签、名称、焦点、状态及手工验证。
- `forms`：持续可见标签、输入反馈时机、保留输入、提交防重。
- `color`：文字/非文字对比度、非纯颜色状态提示及集中配色。
- `form-factor-adaptation`：320px 内容边界、触控目标、安全区与长内容。
- `content-first-noise-reduction`：主内容优先、适度反馈、次要功能按需展开。

只把这些通用原则转化为原生验收标准。WXML 不是 DOM，WXSS 也不能按现代浏览器完整能力假设：不生搬 HTML dialog/popover/inert、DOM 焦点方法、容器查询、浏览器 polyfill、Lighthouse 或浏览器原生验证接口。原生输入类型、焦点、键盘、读屏属性与 Canvas/map 层级均须结合目标微信基础库实测。也不为了指南建议擅自新增深色主题、自动隐藏系统 TabBar、遥测或外部服务。

本阶段没有实施全站审查修复，也没有运行 legacy-scan；指南检索成功不构成应用已经符合其全部要求的证据。

## 9. 管理生命周期静态审查与修复（2026-11-14）

状态：**共享管理层静态修复及隔离逻辑回归通过；真实界面和原生选图仍待电脑解锁后验证。** 不据此宣称管理全流程或全站元素实测通过。

- **账号切换**：加载、写入及错误回调校验原账号与页面生命周期；旧账号迟到的 401 不再重定向新账号。新建赛季不复用旧账号草稿，球员、赛季的待确认状态按会话隔离。
