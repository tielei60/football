# 微信邀请内部基础模块（未接入业务入口）

> 本文保留第一阶段基础模块当时的验收记录。后续 HTTP 接线、确认编号及双归档撤销的当前实现见[接线说明](wechat-integration-contract.md)，不能把本文原“未接线”描述当作最新状态。

## 已实现边界

新增 `server/wechat-provider.mjs`、`server/wechat-invite-store.mjs` 和 `server/wechat-foundation.test.mjs`。默认关闭，不在现有服务启动时加载，不自动迁移数据库，不挂HTTP路由，不修改club_users/club_sessions、不签发应用会话，不提供微信登录按钮或小程序码。不能据此称球员已可扫码加入。

交换适配使用固定微信HTTPS地址，禁止重定向、限制超时和响应大小；缺失openid/session_key或非零错误拒绝，返回对象仅含appId/openid，不保留session_key。适配器签发的对象在本进程内部有来源标记，复制客户端字段不能伪造。错误不暴露URL、code、密钥或上游响应。测试只注入虚构fetch响应，未调用真实微信；官方接口和真实账号权限仍须按设计文档核验，未称实测。

邀请只存凭据摘要，原文创建成功返回一次。相同创建requestId重放不能恢复凭据；不同参数冲突，需撤销再生成。唯一范围含应用、球队、球员。同一邀请只能有一个待审核申请；认领只返回申请状态，未获业务访问权限。认领时发现目标已归档，会拒绝并撤销该旧邀请；此时恢复在队不会使该邀请复活。但如果球员先归档再恢复、期间没有认领请求，本基础模块尚不会撤销其旧邀请，不能宣称全局归档撤销已经实现。审批校验revision、有效期和最新授权，绑定与消费邀请处于同一SQLite事务。

## 必须由服务层提供的可信依赖

`authorize` 必须同步重新认证当前会话、管理员角色、球队和active球员，不能使用客户端传入角色。模块检查其输出范围，但该依赖本身是可信服务端代码，不是新的认证权威。

`isVerifiedIdentity` 来自同实例provider，不能换成接受任意对象的生产实现。

`bindIdentity` 必须同步且仅在传入的同一db当前事务内完成既有账号复用或受控创建、微信映射唯一校验；禁止外呼、异步、另开连接提交或独立提交事务。模块拒绝async函数及Promise结果；SQLite回滚测试证明同步绑定失败不会消费邀请或保留绑定。当前生产绑定函数尚未接入，不能将测试表当真实身份映射。

当前没有邀请列表HTTP接口、认领状态查询接口、持久限流或真实交换配置入口。管理员审批重复使用旧revision返回409供核对，不实现静默重复批准。归档时主动撤销全部邀请的集成钩子仍待实现；本模块仅在认领时拒绝/撤销已归档目标，不能声称完整归档生命周期已接线。

## 验证与后续

12项专项测试全部通过，覆盖默认关闭不建表不外呼、固定地址与脱敏、超时/大响应/缺字段、凭据摘要与重放、同ID不同球队、跨队/普通球员拒绝、身份来源标记、审批事务回滚、归档/过期/撤销、当前角色复验和初始化重复安全。所有SQLite使用内存、所有身份均虚构。未做真实微信、跨进程并发或生产迁移验收。

照片服务批冻结后另批接入：复用club-store统一账户与会话签发；新增会话字段前把无列名INSERT改为显式列；明确预认证路由保留原生/cookie来源隔离；事务化唯一身份绑定、归档/解绑会话撤销、限流和申请查询；最后再开发原生客户端和真实授权接入。仍保留原密码登录，不把基础模块完成等同邀请功能完整交付。
