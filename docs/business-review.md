## 确认的产品范围

- 当前管理一支业余球队，数据为未来多队保留归属边界；不要求本期提供多队切换。
- 使用 SQLite，保留既有战术、阵型、动画、版本、名单、导入导出和打印。
- 管理员与球员登录。管理员发布比赛、管理名单及赛后数据，球员提交自己的参加意愿。
- 主要比赛数据是比分、名单、位置、实际出场、进球和助攻，不强制记录逐次换人。
- 赛季由任意起止日期定义，可以跨自然年；赛季与自然年度分别查询。
- 球队基本资料和队徽、球队比赛场数及胜平负/进失球、对手交锋记录属于已接受的方案，不能因需求摘要未重复列出而排除。
- 不完整记录须显式标注，报名不等于实际出场，缺失比分或个人明细不能自动补零。
- 微信小程序本期只预留可复用 API 边界；不含小程序页面、微信登录或发布。不做费用、财务或训练签到。

## 五项修复的本轮复验结果

1. **球队统计缺失**：独立重建六场跨年完赛，比分为 3:1、0:0、0:2、未知:4、5:未知、未知:未知，实际为 1 胜 1 平 1 负、赛果覆盖 3/6、已知进球 8（4/6）、已知失球 7（4/6），与期望一致。边界外、非完赛和另一球队均不混入；空范围和全未知比分仍保留未知合计。
2. **旧编辑静默覆盖**：重新执行 A 发布、B 用旧草稿只改地点的复现，返回 409，状态保持已发布且地点未被改动。比赛信息和名单共享版本；球员、球队和赛季拒绝旧版本；缺失或非法版本返回 428。拒绝后实际数据保持不变，重启版本保留。
3. **删除战术抹去历史关联**：重建后的删除检查位于事务内，独立复现确认关联存在时返回 409 并保留战术及关联；使用当前比赛版本显式解绑后成功删除。该保护不把关联变成不可变快照。
4. **球队名称/队徽缺少管理入口**：HTTP 独立确认管理员可维护、球员只读，PNG 保存和移除正常，超 2 MiB、外部 URL、SVG、无效编码及伪 PNG 签名被拒绝且原数据不变。旧名称和成员关系经真实旧表迁移保留，保存后重启仍能读取；前端账号页入口已检查到，操作回归待 CI。
5. **对手交锋汇总缺失**：重做同周期 A/B/C 三组对手的完整、单边未知、全未知和明确零比对，赛季与年度范围结果正确，未知不计为平局或零球；排除非完赛、边界外及其他球队记录，重启结果一致。名称只去除首尾空白，不合并不同大小写、内部空白或别名。
