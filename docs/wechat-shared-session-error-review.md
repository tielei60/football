# 共享迟到会话错误与战术页加载保护

## 复现与修复范围

匿名 VM 加载实际 `shared.fail` 与战术编排/设置页后确认：旧账号 `ensureSession` 的迟到 401 已有本地 `staleSession` 标记，但两页仍通过共享错误函数导航登录；旧 `onShow` 的 catch 还会提前结束较新页面的加载。

本批只调整共享错误处理和这两页，不做全站生命周期重构：

- `shared.fail` 对本地 `staleSession === true` 早返回，不覆盖错误、不导航。未标记的当前 401/403 保留原错误和导航语义。
- 两页 `onShow` 捕获账号及可见代次，隐藏或重新显示后旧成功不能继续发起刷新，旧失败不能清新请求的 loading。
- 两页 `refresh` 同样捕获账号、请求代次及可见代次，旧 catch/finally 不再污染较新页面状态；真正当前失效即使会话已清理仍显示错误。
- 保持正常 hide/show 的缓存模型及未保存草稿恢复，不改命令、撤销、曲线、阵型数据、画布尺寸或任何 UI 模板/CSS。
