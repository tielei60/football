# 阶段39：比赛新建未知回执持久恢复

## 本轮范围
复查发现比赛新建草稿只存在模块内存，重启或重新登录后无法阻止重复新增；旧会话401也可能被误判为确定失败。本轮只修复比赛新建，不扩大至球员和赛季的共享新增账本，后两项仍待后续处理。

在发出新增请求前写入并读回核对标记，按服务来源、账号、球队隔离，仅保存任务编号与时间。草稿、比分、地点、个人资料、登录令牌均不持久化。有效成功或明确拒绝精确清理本任务；未知回执、异常成功编号、过期会话回执及清理失败保留提醒。旧回执和旧确认不能清除新任务。

增加“已核对，比赛已存在”，只解除提醒并返回赛程，不改写比赛。恢复入口受新建/未知状态、在途请求、页面显隐、账号和任务一致性约束。编辑比赛仍走原版本控制PUT。

## 原生操作及发现修复
使用匿名隔离数据库、回环代理和专用开发者工具窗口：

1. 实际输入对手，通过日期组件选择2026-11-20并保存草稿。
2. 服务端成功创建后，代理向客户端返回502。页面显示未知结果并禁用保存。
3. 关闭并重新打开专用运行窗口，新建页面为空白，持久提醒仍阻止保存。
4. 原生检查发现核对提示文字为空，原因是refresh对象重复定义actionError，后一个字段覆盖持久标记文案。已合并为唯一字段，补明确文案断言并重新同步验证。
5. 在赛程的草稿页找到唯一“阶段39匿名恢复对手”，数据库确认状态draft；点击“比赛已存在”确认后只返回赛程，再打开新建页不再显示提醒。
6. 正常退出匿名管理员，确认登录页和服务端会话数0。

新增比赛接口总共1次，数据库仅club_matches新增1条；所有既有比赛、报名、名单、统计来源等其他业务表不变。自增序列表不计入业务内容对照。

## 限制及现场
本轮实际覆盖运行窗口关闭重开，不等于真机系统重启或所有网络故障。跨账号/来源/球队隔离为控制器回归，本轮未再次原生逐项操作。持久标记不恢复原草稿，不构成服务端幂等；“未创建”必须由用户核对列表，不能当作自动查无记录。

存储部分写入后读回失败可能留下保守提醒，但不会发送创建请求；存储恢复后支持人工核对。球员/赛季新增的跨重启保护仍待处理。
