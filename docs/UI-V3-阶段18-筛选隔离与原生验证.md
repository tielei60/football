# UI V3 阶段 18：账号筛选隔离与原生验证

## 修复

球员页和管理球员页切换账号时此前只重置成员状态，没有清空上一账号的搜索和位置，可能导致新账号看到误导性的空列表。本轮清空跨账号筛选，同一账号离页返回、刷新保留筛选。不修改页面结构或设计样式。

## 审查与测试

- 修复前新增两项回归测试均失败，修复后通过。
- 独立只读审查通过；补充同账号位置保留及不同账号返回不同队员列表断言。
- 管理页原业务 SHA 基线未更新；只将唯一完整的已审重置片段投影回旧片段，同时测试拒绝重复、篡改，其他源码继续受旧基线保护。
- 管理页契约与成员状态专项 35/35 通过。
- 与同分支阶段 17H 合并工作树小程序全量 959/959 通过。

## 微信开发者工具本地实操

使用独立临时数据库、匿名球队和随机测试账号；不写入柏林来源库或正式数据库。

实际完成账号与密码输入、登录、首页、球员名册、输入无匹配搜索、空态、切换赛程再返回保留搜索、点击重置恢复 8 名队员、统计、我的、点击退出确认。查看名册原图与运行截图，搜索框边框、空态、重置按钮及列表信息层级无新增明显错位。

退出确认的自动化选择器点击虽报告成功但画面未变化，因此没有算作成功；改用本机界面真实点击后到达登录页，并只读核实隔离库会话为 0。已恢复隔离工程原配置、关闭本轮窗口、停止临时服务。

## 限制与后续

本轮原生覆盖六个页面的上述流程，不等于全部页面、全部异常状态验收。跨账号筛选隔离由控制器回归验证，本轮未在原生工具重复第二账号登录。错误、超长内容及剩余页面交互仍需继续逐项核验，不将自动测试通过等同于真机视觉验收。

本地复核材料位于隔离验证工程的 ui-stage18 目录；仅保留在本机，不提交随机登录信息或测试库。
