# UI V3 第二十四阶段：改密提交与认领边界

## 真实问题与修复

使用项目真实 `utils/api.js` 的请求代次逻辑，在内存传输层控制响应时序，而不是仅伪造 `staleSession` 标记。旧实现 10 个新增场景中 4 个失败：清会话后的旧响应可触发无归属跳转，旧请求最终清理可清空新账号表单。

修复限定于首次改密提交回执归属：当前成功与真正过期仍结束等待并清理输入；旧代次、新账号、隐藏、卸载、新页面轮次不得被旧请求接管。密码长度、一致性、认证 API 及退出规则不变。保留原行为 SHA，通过唯一精确逆投影验证已审修改，拒绝篡改和重复片段。

## 补充自动检查

- 邀请增加 11 项：能力请求 401、`statusCode` 401、同账号刷新并发和旧轮次骨架隔离。公开能力请求本身不一定清会话，不强制当成退出。
- 认领增加 3 项：忙碌时不重复提交/跳转；429保留凭据并要求主动重试；能力请求失败后主动刷新，不自动认领。
- 邀请及认领本轮不改源码；这些测试不是微信平台授权或真实认领联调。
- 改密提交专项由独立审查者复核，相关 57 项通过。

## 原生初始化失败与恢复

全新匿名库、仅本机服务与透明代理：仅一次 `/api/auth/me` 返回 503，其余请求正常转发。真实进入首次改密页后显示“暂时无法加载”；点击重新加载恢复正常表单；真实退出回登录，数据库会话 0。没有修改任何账号密码，也未调用真实微信或 AI 服务。

首次模拟器启动曾超时，关闭专属窗口、确认关闭后重新打开恢复。没有退出整个微信工具或修改其他项目。完成后专属配置逐字节恢复、窗口关闭、代理和服务正常退出。证据在本地 `football-ui-v3-interaction/ui-stage24`。

## 本地发现的附加问题

加载失败时仍显示可点击的提交按钮，首次初始化失败会静默拒绝。此问题追加为本轮修复：加载错误时禁用提交，同时业务守卫拒绝加载错误状态；保留输入、退出、重新加载，普通字段校验错误仍可修改后提交。追加修复已完成：再次使用独立匿名库和单次503代理，原生界面确认提交按钮为 disabled，输入/退出/重新加载仍可用；真实点击重新加载后提交按钮恢复可用，退出回登录。第二次隔离配置逐字节恢复、窗口关闭、会话0，服务与代理退出。证据在 `football-ui-v3-interaction/ui-stage24-gate`。
