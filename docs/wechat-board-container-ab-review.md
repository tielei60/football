# 战术画布容器 A/B 验证记录

## 证据与假设

320 宽按阵型页滚底、赛季阵容、战术列表滚底、画布页进入后，首次截图曾出现原生画布错层，滚动后恢复。此前实际窗口也确认过错层，而布局测量中画布与容器坐标一致。375/430 刷新重入正常不能作为修复成功证据。

本次仅检验“非放大画布不嵌套横向滚动容器”的候选方案，尚未证明根因，更不能将自动测试等同原生合成已修复。

## 最小变更

- 默认、专注、编辑使用普通 view；仅普通只读放大使用 scroll-view，保留两倍画布横向查看。
- 共用一个 canvas 模板，互斥分支在运行时仅产生一个同名节点。尺寸、绘制模型、触摸绑定、角色权限及数据不变。
- 放大/还原/专注切换先停止播放并失活旧绘制、释放旧上下文与触摸矩形，等待视图及尺寸提交后重新查询节点。进入编辑同样释放旧节点上下文。
- 仅精确更新战术画布 JS/WXML 的保护摘要，未改其他页面摘要或样式。

## 自动验证与待验

新增匿名测试验证旧节点回调拒绝、隐藏/换账号/更新切换失效、放大576与还原288宽度、触摸重新使用新矩形；官方模板六种组合均只有一个 canvas，仅普通放大存在 scroll-view。旧战术编辑/拖动/保存回归保持。

这些测试使用节点替身或官方虚拟模板，并不验证真实图层位置。仍需实际按原320页序重复首入/滚底/回顶、375/430、放大横滚与还原、专注、播放暂停及编辑触摸。仅在真实对照结果满足后才判断是否保留方案。

## 实际 A/B 结论：候选无效，首轮停止

在320×640设备上官方刷新候选，然后真实导航阵型设置并滚到底、赛季阵容、战术列表并滚到底、战术画布。进入画布后没有滚动，没有先调用CLI截图；首先取得CUA实际窗口，场地底端仍显示在顶部专注按钮/标题区域，正常场地容器空白。首轮已经失败，因此没有继续三轮或编辑拖动，不以滚动自愈、额外延时、重新打开项目制造通过。

随后才取得CLI失败截图和只读几何：普通view候选确已生效（changeSurface存在，scroll-view.board-wrap查询为空，zoomed/focus/editing均false）。scrollTop=0，canvas left16/top286.383/288×436，外容器top285.383/298×438；原生显示仍与DOM位置不一致。失败图片仅本机保存，未上传仓库。

独立自动专项27/27通过，不抵消上述真实失败。普通view方案不足以解决此现象，候选不作为修复保留，交作者精确回退候选代码及摘要，保留原已提交门禁。放大横滚、专注、播放与编辑拖动取消的本候选后续回归未执行，不记通过。未保存业务数据。

导航方式限定：上述跨页序列使用官方 automation_navigate 的 redirectTo，滚动使用官方 pageScrollTo，并非逐个页面入口按钮点击，也不是编译器指定页面启动。其结果不能直接推广为真实用户点击导航链。作者已核验候选3个tracked文件逐字节回退至保留门禁的版本，新增候选测试移出仓库，26专项/139模板通过。后续优先以实际‘我的→战术→列表点击’对照工具直接导航影响。

## 回退后真实点击导航对照

320设备下官方刷新后，通过CUA实际点击首页“我的”→“球队战术板”，真实滚动长列表到底后回到五人卡片位置，点击既有战术卡片进入。画布首入先看CUA、未滚画布也未先CLI截图，场地与工具位置正常。再以实际返回按钮回列表并点击同卡片，连续三次实际首入均未见遮挡。只读核实目标为战术4，页面栈为me→tactics→tactic-board，基础库SDKVersion为3.17.6。

结论限定：官方redirectTo连续导航/滚动工具链中的异常，与真实页面点击navigateTo栈三次正常同时存在。不能将前者无条件推广为用户实际导航必然失败，也不能据后三次断言永久稳定或真机无问题。原生合成/工具导航差异根因未决；不继续无证CSS补丁。截图只本机保存。

## 后续430真实点击反例：撤销仅工具链推断
回退后完成430宽29页当前态采图，再官方switchTab我的、CUA实际点球队战术板及第二张五人卡片。首入先CUA，未滚动画布、未先CLI截图，场地又覆盖标题/阶段区，原容器空白。此前320三次真实点击正常仍成立，但不足以将异常限定仅redirectTo链。

只读目标战术4，栈me→tactics→tactic-board；scrollTop0、zoomed/editing false；canvas数据398×602，正确tactic-canvas DOM rect left17/top375.039/398×602，容器top374.039/400×604；SDK3.17.6。首次误用旧节点ID查询null，随后按实际模板id取得正确rect，未写状态。失败截图berlin-430-board-real-tap-failed.png只留本机。

修订结论：320/430均存在间歇原生显示错层，真实点击栈也可触发，不称仅工具导航问题或真机肯定正常。候选保持回退，根因未决；保存证据后正常离页退出，未保存模型，不用重开或猜测CSS掩盖。
