# 比赛访客报名与球员转正

## 使用方式

1. 管理员按原流程发布比赛，不需要额外打开访客开关。登录队员使用比赛的微信分享入口，会生成指向本场的卡片。按产品要求，转发图片仍带球员姓名；访客打开卡片不能由此浏览球队通讯录、其他赛程、战术、照片或统计。
2. 访客打开卡片后，页面只展示本场可公开的信息和本人的报名结果。首次微信进入后，主动选择头像，填写或带入昵称，再填写真实姓名，才能提交。真实姓名由本人填写，不代表平台已核验身份；微信登录本身不会自动读取头像和昵称。
3. 临时报名与正式球员共用比赛名额，同一微信身份不能重复占位。访客报名于北京时间开球时截止；未填写开球时间时，于比赛日结束截止。已结束或已取消的比赛不接受新增报名。比赛列表中的临时身份仅用小图标标记，详情页显示具体身份。
4. 管理员可从球员管理转正。转正继续使用原有档案与微信身份，已有头像、报名记录和出场数据都保留；同名不是合并或覆盖档案的依据。转正不会授予管理权限，也不会自动加入所有赛季的阵容。

## 实现边界

- 只通过非顺序的分享凭据到达公开比赛，不用裸比赛编号打开外部报名。公开页面不返回内部名单；卡片图片中的队员姓名是有意保留的展示内容，不通过公共接口额外返回。
- 微信身份由服务端校验。临时球员不是现有「待确认成员」的另一种名称：临时账号只可访问获准的比赛以及本人的报名操作；普通球员和管理员的登录、点名邀请与权限不变。
- 客户端临时身份与正式成员会话隔离。后台不接受昵称、姓名或头像作为登录证明；重复点击、链接已结束、停用以及名额不足不能额外创建账号或占用名额。
- 面向来访者明确说明姓名、昵称和头像用于本场报名和球队管理。首次上传的头像在后端校验、解码并去除元数据。保留报名所需资料，不要求手机号、身份证等额外信息。
- 任何实测只用匿名隔离数据。模拟微信身份验证不等于微信真机授权或线上转发；线上验证不得使用正式库做注册或发送测试分享。
