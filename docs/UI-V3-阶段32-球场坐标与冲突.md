# UI V3 阶段 32：球场坐标移除与并发冲突

## 为什么选择本项

业务总表把编辑球场的坐标移除保存及 409 列为 P1 未验。本轮补齐该闭环，未调用用户定位、实际选点或导航，不修改正式球场。

## 前提与原生操作

存储层辅助创建一个匿名球场（坐标 30/120、A 场、测试地址）并关联一场匿名比赛，之后保存基线。前提建立不计作原生新增。

1. 打开编辑球场，点击移除坐标，地图和查看/移除按钮消失。
2. 不保存直接返回，再次打开，原坐标及地图恢复，数据库无写入。
3. 再次移除并点击保存，重新打开为无坐标、版本 2，名称、编号、地址及可选状态不变。
4. 原生输入新的本地名称；另用同一隔离库的存储层把地址修改为并发版本（版本 3），制造真实过期版本条件。
5. 点击保存得到 409，原名称草稿保留，保存禁用，并提示返回球场列表核对。
6. 点击核对入口再重开，读取版本 3、并发地址，冲突状态解除；没有覆盖并发修改。
7. 打开关联比赛详情，仍显示原球场名称及地址，读取的地点快照仍保留原坐标。

## 独立复核

全表比较只有 `club_venues` 变化，目标记录只改变版本、纬经度和并发地址。比赛及其地点快照等其他表完全不变。请求只有一次业务 PUT 200 和一次 PUT 409；并发 B 为存储层辅助，不冒充另一真实终端操作。

小程序 1220 项测试与 140 次模板虚拟渲染通过。没有发现本轮需要修改的生产代码缺陷。

## 现场与尚缺范围

本地 `football-ui-v3-interaction/ui-stage32` 留存基线、页面状态、截图、并发版本及请求日志。正常退出会话为 0；配置恢复、专用窗口关闭、临时服务停止且端口拒绝连接。用户原工作区和正式数据未改。

仍未验：球场写入响应丢失的原生恢复、跨进程未知结果、真实地图选点/定位导航/权限拒绝，以及相关真机布局。显示地图不等于这些外部能力已通过。其他 P1 项仍包括报名截止边界、名单409/未知回执、赛季阵容增删与未知回执、战术导入跨账号恢复。
