# 第十七阶段 H：战术导入收据与重试兼容修复

## 原因及实现

此前服务端只根据 `collectionName` 查收据，同一名称即使携带不同战术或历史也返回旧 ID，容易把冲突误认为成功。本轮增加可空内容摘要，命名导入原子记录原始战术和历史；对象键序与顶层导出时间不影响摘要，数组顺序保留。相同内容重试仍返回原 ID，不重复写入；不同内容返回 409，原记录与收据不变。即使原战术随后编辑或删除，重试也不覆盖或重建。

旧库仅增加可空列，旧收据保留 NULL，不能从已编辑战术或第一次重试猜测摘要。旧收据返回 `legacy-unverified`，保持防重复但不声称本次内容已核验。原生和网页均显示需到战术列表核对的提示；新收据明确区分首次新增和已验证重复。HTTP 明确透传重复标记，避免存储单测通过但界面取不到状态。

终审还发现网页转换会补当前时间或随机演示 ID，导致相同文件重试误报冲突；现标准备份原样保留，旧快照用文件内稳定演示标识，缺时间由服务端首次插入补齐。本机迁移复用同一路径。导入已完成但列表刷新失败时单列警告，不把已写入误报为未写入，避免用户重复导入。

网页原来的格式转换还丢弃输入 `collectionName`，本轮保留明确提供的名称，无名备份不自动造名，错误类型仍由服务端拒绝。不会自动换名绕过冲突。

## 限制及后续

历史无摘要收据无法补证本次文件与原内容相同，这是明确保留的兼容边界，不标为已核验。未命名的传统追加接口仍没有幂等保证。17G 的系统另存 IDE 限制及真机文件选择仍待单独验证。
