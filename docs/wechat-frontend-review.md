# 微信邀请原生前端接线与验证边界

## 实现范围

新增 `wechat-invites` 管理页、`wechat-claim` 认领页，小程序由26页增至28页。原26页的历史验收不代表新认证路径已全部通过。

- 登录页读取公开能力布尔值，默认关闭时保留原密码登录，不自动调用微信登录。开启后增加用户主动的微信登录与接受邀请入口。
- 球员管理页仅在能力开启时展示邀请管理入口，管理页再核服务端身份、角色与目标球员。管理创建、当前邀请置顶、审批核验编号、拒绝/撤销、解绑和历史分页由现有后端契约处理。
- 明文邀请只在创建页私有内存，管理员明确确认复制后交付；不自动发微信、分享或创建二维码。丢失创建响应后核对，不假装可恢复hash-only凭据。
- 认领页使用原邀请码和fresh微信code提交；未知结果由用户主动再次提交原凭据及新requestId，服务端恢复本人申请。状态刷新仍使用已知inviteId，不增加无编号查询接口。
- 历史approved不是当前有效绑定证明，必须用户主动再次登录，服务端重新核授权。未批准没有业务会话，不提供公开注册。
- 微信专用账号 `passwordEnabled=false` 隐藏改密并在handler拒绝；旧账号未返回该字段时保持旧密码能力，不强制关闭现有入口。

## 取消、凭据与身份保护

`beginWechat`捕获服务地址、会话epoch及输入字符串快照，再调用wx.login。预认证不携带旧Authorization或Cookie。隐藏/卸载/主动取消使attempt失效，迟到code不发送请求；已经签发的迟到登录响应只向原issuer尽力撤销，不覆盖后来账号。主动退出后的onShow仅获取能力，不自动重新登录。

邀请码不写page.data、本地存储或日志；原生密码式输入在提交时卸载、结束后重新建立空控件，私有原值只供用户显式重试。替换邀请码清旧状态/确认编号；离页清私有凭据和申请编号。若接受路由credential参数，微信路由传输本身可能被平台处理，不能宣称秘密在任何环节均不出现；当前管理交付只提供主动复制，没有自动构造或发送分享链接。剪贴板是用户明确交付的系统区域，非本应用私有存储，用户应只交给目标成员。

未选择或读取AppSecret，不改正式微信AppID，不调用真实code2Session，不外发真实邀请码。所有wx.login和服务端交换测试使用匿名替身；后端默认关闭及真实配置前置仍适用。

## 布局与回归约束

沿用紫色token、共享业务弹框、骨架屏与按钮规格；新页不覆盖原输入高度/竖padding或Canvas几何。注册与模板数量精确更新至28页，新增一个认领输入模板实例37，尚未实际IME/caret验证。管理审批复用共享弹框输入，不重复计算为新模板。

旧页面结构摘要未整体重设，只在旧摘要校验前剔除明确新增的微信入口块/按钮与密码能力条件，并由独立测试验证这些新增入口及门控；登录新增独立微信容器padding-top例外单独限定，不放宽全页几何规则。

## 首次进入球员管理的能力读取修复

阶段B实测发现启用服务时首次进入球员管理未出现微信入口：`onLoad`启动异步刷新，而`onShow`的管理helper首载不会等待已有刷新，旧逻辑在权限尚未返回时提前结束。现将首载能力结果纳入`refresh`的返回对象，由原有`admin.load`统一执行管理员、会话token、视图代次和epoch校验；能力关闭或读取失败保持原密码管理可用。隐藏时清入口，返回或更换账号按原有加载门禁重新读取，不修改公共管理helper。

新增6项VM直接加载真实`admin.load/show`，延迟身份响应模拟`onLoad`与`onShow`并发，覆盖启用、关闭、读取失败、隐藏后恢复、换账号和非管理员拒绝。此为逻辑回归，不替代实际界面。修复后已通过工具刷新并重新首次进入，入口立即显示，实际点击进入正确目标球员的邀请页。

## 微信专用账号的密码能力边界

最终独审发现两处旧密码假设并作小修：注销请求失败后，密码账号仍提示重新登录并改密；微信专用账号改为联系管理员解除绑定撤销旧会话，并说明之后需要重新邀请。提示使用退出前会话的能力快照，不因退出清理而丢失依据。

原球员接口只有`hasAccount`，不能凭此认定可重置密码。后端本批补充同球队目标账号的`passwordEnabled`布尔投影，列表/详情/保存返回一致，无账号为false，`hasAccount`也按同队目标查询，不返回账号名或密码散列。管理页在已有账号且该值明确false时隐藏重置按钮及表单，handler和确认回调再次拦截；无账号仍可开通原密码账号，旧服务未提供字段时保持兼容。后端既有禁止隐式启用密码规则不变。模板保护只归一化这两个明确新增条件，原结构摘要未重设。

新增8项VM/模板约束覆盖true/false/缺字段、无账号和两种注销失败指引。本小修自动化已通过，未将它倒填为此前A/B实际界面已测。

## 自动化与待验

API专项验证能力只返回布尔、无旧Bearer、输入快照、wx.login取消、旧issuer迟到撤销、并发旧新登录、主动退出、审批非会话、密码能力和无效配置。页面专项验证隐私输入、换凭据清状态、隐藏迟到、显式审批后登录、已登录账号拦截、未知结果恢复提示、开始异常busy恢复及禁用改密。管理页另有18项匿名VM专项，包含未知创建经明确撤销/拒绝/解绑后重建使用新的请求编号、撤销失败保留旧编号，以及旧请求返回凭据不可重现时明确提示本次未新建且不自动重试。提示在刷新后仍检查原会话与页面代次，避免被刷新清空或进入后来页面。

最终完整450项测试、0跳过，官方28页/4组件共123次虚拟渲染通过；git diff --check通过。这些结果是逻辑与模板检查，不代表28页所有状态已实际验收，也不代表真实微信授权、正式AppID/code交换或实际人工身份核对成功。
