# 战术加载及错误态编辑门禁

## 证据与最小修复

匿名 VM 使用实际编排/设置页和编辑模型复现：已有缓存模型时启动刷新，`loading=true` 但旧 `allowed()` 仍返回真，编排新增阶段可改变命令且结束 loading，随后保存可发 PUT；设置页旧保存也能发 PUT。重载失败的 error 态存在同类入口缺口。

仅两页 `allowed()` 增加 `!data.loading && !data.error`。不改 UI 模板、尺寸、画布、模型、命令、权限、会话或数据库。

## 自动验证

新增 4 项匿名页面回归，分别覆盖两页挂起刷新与读取失败：

- 编排旧输入、拖动、直接命令和保存不改变模型/命令，不发 PUT。
- 设置旧输入、选择、槽位及保存不改变草稿/模型，不发 PUT。
- 完成重载或错误后成功重载，正常编辑恢复。
- 精确更新两页 JavaScript 摘要；CSS 与模板基线不变。

完整小程序测试 **584/584**，官方模板 **139 次渲染**，`git diff --check` 通过。

这是迟到事件的 VM 防御验证，不代表已在实际微信界面用手指穿透加载遮罩复现；绘制使用测试替身，不据此声称 Canvas 视觉全过。实际正常编辑往返由独立 UI 验收者后续确认。未操作真实资料、凭据或服务配置。
