# 共享业务弹框生命周期专项复核

## 发现的问题

这是共享 API 的潜在队列问题，不是已经确认的现有页面必现故障。当前业务页面没有调用带遮罩的 showLoading。

在隔离 VM 中模拟延迟 setData：确认弹框后，关闭遮罩的提交回调尚未完成，又出现带遮罩的 loading。新渲染版本使旧提交回调失效，原实现丢弃该回调及其结算逻辑。loading 关闭后，原 Promise 仍未结算，后续弹框也被 settling 集合阻止。

## 修复边界

- 修改仅在 miniprogram/utils/ui.js 的渲染与待结算管理，不改页面、样式、权限或业务请求。
- 保留渲染版本检查。被更新版本取代的提交不能触发旧界面操作。
- 待结算回调独立保存，必须等当前不阻挡状态真正提交后才执行；遮罩仍在或关闭提交尚未完成时不调用业务回调。
- 关闭钩子如果再次打开遮罩，也继续等待，不提前绕过业务编辑保护。
- hide/unload 的 abort 清空等待队列并结算为 aborted；账号改变后，等待恢复时仍核对原身份，不调用旧成功或 complete 回调。
- 已显示 loading 如果没有被业务关闭，确认任务仍等待它关闭，符合遮罩阻挡语义；本次不自动隐藏新 loading。

## 证据与限制

business-ui.test.cjs 专项 25/25 通过，包含新增 5 项回归：更新版本后的关闭结算、下一弹框恢复、隐藏、卸载、换账号以及关闭钩子重新阻挡。测试验证 Promise 和业务回调顺序及次数。

这是隔离 VM 的异步逻辑验证，不是实际微信界面、真机辅助技术或真实网络测试。未操作 UI、业务数据、账号密码，未提交或发布。原元素审查计划文档保持不动。
