# UI V3 阶段 31：赛季、自然年筛选与边界

## 原生操作结果

在独立匿名演练库中，通过微信开发者工具界面实际点击统计范围及年份选择器：

| 范围 | 结果 | 关键语义 |
| --- | --- | --- |
| 全部比赛 | 2 场完赛、1 场完整比分、1 胜、进球 3 失球 1 | 草稿、取消及未结束比赛不算完赛 |
| 2026–2027 跨年赛季 | 同上 | 一个自定义赛季可跨自然年 |
| 2026 自然年 | 1 场完赛、1 胜、3:1 | 已确认出场 2 次，待确认 1 次 |
| 2027 自然年 | 1 场完赛、无完整比分、进球 0、失球未知 | 0 与未知不同，不凭缺失比分计平局，名单未录入 |
| 2028 自然年 | 0 场完赛、进失球未知、暂无交锋 | 无旧年份数据残留 |

从 2028 年打开范围选择、选择赛季后取消，保持 2028 年；再次选择并确认恢复赛季 2 场数据，年份控件隐藏，没有把旧年份与赛季条件混用。

独立审查者使用 SQLite 原始比赛及名单重算五组数据：比赛数、报名统计范围、比分覆盖率、个人进球/助攻、已知记录场次及出场次数均一致。23 张业务表相对基线不变。

## 新增可重复边界测试

`server/statistics-stage31-boundaries.test.mjs` 使用每次新建的匿名临时库，覆盖：

- 全部比赛、赛季、自然年互斥参数的所有组合；非法年份、赛季及 all 值被拒绝，合法查询不受影响。
- 闰日赛季首尾日期均包含，同日其他赛季和未归属比赛不串入。
- 草稿、取消比赛不计入完成场次；超出赛季日期和非法闰日的写入被拒绝。

新增 2 项存储层测试通过；既有相关 HTTP 业务测试 3 项重跑通过。小程序完整 1220 项测试及 140 次模板虚拟渲染通过。本阶段没有发现生产代码缺陷，提交为测试增强与验收记录。

## 现场及限制

证据在本地 `football-ui-v3-interaction/ui-stage31`，含各范围页面状态、截图、数据库基线及请求日志；未提交数据库和账号。正常退出会话为 0，配置恢复，专用 s2 窗口关闭，临时服务停止且端口拒绝连接。正式数据及用户原工作区未改。

原生验证覆盖上述具体组合；闰日、非法参数与重叠归属是自动化存储层测试，不冒充原生实操或真机验证。页面详情的每一种年度跳转、强制杀进程和全部时区边界仍需独立验收。
