# 成员状态确认的兼容展示

新增 `membershipConfirmed` 只表示资料中的成员归属是否已核实，不代替现有 `status` 权限和归档状态。字段缺失按旧版已确认语义兼容；仅明确 `false` 显示“状态未确认”。不能据此推断年龄、健康或真实参加比赛情况。

## 跨端映射

- 小程序球员列表、管理列表首次载入若无确认在队但有待确认成员，默认展示待确认；用户主动选择后刷新不覆盖，换账号重置首次选择。
- 小程序球员列表、管理列表增加“待确认”，涵盖技术状态为 active 或 inactive 的未确认来源。原在队、历史列表只纳入已确认成员。
- 首页在队人数只统计已确认且 active，另行列出待确认人数；不改变后端比赛统计。
- 球员详情使用确认状态优先的标签。
- 小程序与 Web 管理编辑均提供“状态未确认 / 在队 / 已归档”三项。选择未确认仅写 false，保留原技术 status；明确选择在队或归档才同时写 true 与相应 status。沿用原 PUT 与 revision，冲突不自动重试。未确认时隐藏小程序快捷归档，避免语义矛盾。
- Web 球员表状态、顶部人数及比赛选人标签同步；不阻止原本可选成员、不修改账号或名单权限。

## 验证边界

新增匿名测试检查两种技术状态均进入待确认、缺字段兼容、三项映射、同账号与冲突门禁。旧文字结构检查仅精确排除新增控件和标签；业务选择器数量增加一项。

当前为代码及自动化阶段，真实工具截图、三项选择保存重入、来源展示副本仍待验收。没有修改任何真实球员数据；源成员确认值由授权隔离展示构建步骤决定，不默认把所有球员改为未确认。
