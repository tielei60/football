# 比赛相册顺序接口

管理员同队调用 `PUT /api/matches/:id/photos/order`：

```json
{"revision":7,"photoIds":[3,1,4]}
```

`photoIds` 必须完整、唯一地列出该比赛当前所有有效照片的正整数ID，最多9个。缺失、重复、已删除、其它比赛或无效ID均400；其它球队比赛404；非管理员403。`revision` 是既有比赛版本，缺失428，过期409；顺序及版本增加在同一个事务内，失败全部回滚。

成功返回与照片列表相同的 `{revision,coverPhotoId,photos}` 元数据对象，数组按新顺序排列。排序不改变封面、不新增图、不返回图片载荷。读取权限、草稿隐藏和比赛历史字段均沿用既有规则。客户端网络失败不得猜测是否提交，应重新GET核对当前完整列表和版本。

兼容迁移为 `club_match_photos` 增加 `sort_order`。旧行一次性按ID保留原先顺序；重复初始化不重置已排顺序。以后上传追加末尾；删除当前封面按剩余排序第一张回退。旧客户端仍可照常读取、上传、删除和选封面。

8项媒体专项（原4项加新4项）通过，新增覆盖HTTP排序、完整集合、CAS、跨队/球员拒绝、事务故障回滚、追加/删除回退和迁移幂等。均为隔离匿名图片与数据库；真实系统排序交互尚待前端验收。
