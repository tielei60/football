# 战术备份旧数据兼容与历史上限保护

## 已复现与修复

### 服务端旧演示无法从小程序导出

现有服务端测试支持一阶段演示保留 `fromStage:0` 曲线，并且保存和导出不删除该内容。小程序原校验要求曲线必须有下一阶段，导致这类已存在数据阻止整份备份导出。

本次仅允许曲线引用实际存在的末阶段，无下一帧时不用于播放，但备份完整保留。负数、非整数、真正超出阶段范围、未知参与者和非法坐标仍拒绝。未笼统放宽所有引用校验，也不静默删旧曲线。

### 超过服务端历史保留上限的导入

服务端每套战术仅保留最新 50 个历史版本。小程序此前能选择更多，页面展示全部数量，但服务端导入可能裁剪旧版本。

现在在本地解析导入文件时按每套战术计数，超过 50 个明确拒绝，解释未导入的原因，要求先保留原备份。不会发出该文件的导入请求。多套战术各自不超过 50 个不受影响。导出不执行此上限裁剪，保持既有数据完整。

## 验证

- 旧演示往返、历史上限两项回归修复前失败，修复后通过。
- 追加两套各50版本可解析、导出不裁剪已有101版本的边界断言。
- 小程序全量 **948/948 通过**。
- 未改变页面结构、UI绑定、服务端权限或存储保留策略。
- 以上是控制器/格式兼容验证，真实文件选择、系统保存与导入落库由后续17G独立实测，不将单测称为完整原生流程通过。

## 仍待独立处理的接口语义缺口

内存库复查发现：同 `collectionName` 重复提交但内容不同，服务端仍按既有收据返回旧ID和 `importedCount:0`，未报告内容冲突。当前原生未知结果重试保持原任务内容不变，不会主动改变该内容；外部调用仍需防误用。

后续需设计收据内容哈希及历史无哈希收据的兼容策略，再实现同名异内容409。本轮不贸然迁移数据库，不把这个缺口标为已修复，也不改变既有同名同内容幂等行为。
