## 重点核对

- **旧账号迁移**：新增 `password_enabled` 默认值为 1，保留旧密码账号；迁移测试覆盖既有原生与 Cookie 会话。新建微信专用用户为 0，并使用随机不可用密码占位值；管理员重置与本人修改路径不隐式开启密码登录。审批复用既有球员账号时不替换原密码。
- **身份与权限**：可信身份必须来自服务端验证流程；AppID 在邀请、绑定、会话边界受约束。管理操作仍受管理员、球队及归档状态约束，客户端不能自行指定可信 OpenID 或角色。
- **迟到交换与撤权**：绑定、解绑及归档相关入口更新全局 epoch；交换前后与签发事务中的核验阻止旧交换结果在撤权后重新签发会话。全局失效是保守设计，会同时影响其他在途交换。
- **事务与冲突**：审批涉及账号、身份绑定及邀请消耗的写入处于事务内；唯一约束冲突不能留下部分成功状态。修订号与请求标识用于冲突和重试保护。
- **终态恢复**：原凭据散列匹配且验证后的 AppID/OpenID 相同，才可只读返回历史终态。恢复不调用绑定、不签发会话；派生过期也不借恢复流程改写邀请。解绑后恢复历史 approved 不等于恢复授权。
- **默认与资源边界**：未配置时功能默认关闭；应用密钥仅服务端使用。上游超时与错误响应受到约束，速率限制及在途交换表有容量上限。限流为单进程边界，不代表多实例统一配额。

## 实际测试与补充证据

首次独立执行四个认证专项文件，共 **41/41 通过**。提出的证据补强建议是增加 HTTP 接线层的“批准后解绑，再用原凭据恢复”回归，而非已发现授权复活漏洞。

作者补充后，独立复读新断言并再次执行：

```sh
node --test server/wechat-foundation.test.mjs \
  server/wechat-auth-api.test.mjs \
  server/wechat-migration.test.mjs \
  server/wechat-rate-limit.test.mjs
```

结果：**42 项通过，0 失败、0 跳过**。测试使用临时隔离数据库与模拟微信响应，没有调用真实微信服务或读取生产配置。

新增证据包括：

1. 每类终态分别拒绝另一个经过模拟验证的 AppID，即使 OpenID 相同；同时覆盖不同身份、伪造身份对象和错误凭据。
2. HTTP 流程批准后解绑，原凭据重新 claim 只返回历史 approved，响应不含 token；再次登录为 403。
3. 上述恢复前后邀请行、绑定表、epoch 与会话表完全一致，证明该测试场景没有重新绑定或签发会话。

这里没有把其他线程报告的全服务端测试数量当作本次亲自执行结果。
