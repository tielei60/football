# 比赛保存与微信 Page 保留属性修复

## 两类问题分别记录

隔离演练曾出现首次新建比赛保存后回首页，数据库只有一条已提交记录；这次现象的根因仍未定位，不能归因热刷新，也不能用以下修复声称它已解决。

独立代码检查发现比赛编辑页隐藏后迟到保存仍可导航。匿名 VM 复现 `save → onHide → success` 仍调用详情跳转。现以保存操作、会话和页面可见代次共同保护回调，隐藏后返回仅展示结果，不自动跳转。创建合法成功后保留进程内 savedId，重入可以进入已保存比赛；导航失败有明确入口，禁止再次 POST。已保存记录不能经“未创建”确认解锁。响应编号必须是安全正整数，编辑时须对应原比赛；异常响应进入结果核对。未知创建的人工赛程核对语义保留，未新增比赛幂等 API。

仅进程内保存操作与结果编号，不新增持久化个人资料。不同登录不能读取旧表单或保存结果。跨进程丢失待核对创建记录仍是原有边界，不宣称此次增加了持久恢复。已有编辑隐藏后409/5xx返回保留冲突，不能盲目重放。

## 微信保留属性

真实工具首次进入新建战术发生 `_this.options is not a function`，原因是微信 `Page.options` 路由参数覆盖同名业务方法。已改为 `rebuildFormationOptions`；VM 创建页面时注入真实形态 `options={}`，避免仅桌面 JavaScript 对象测试掩盖冲突。

同时静态发现邀请管理及 AI 页使用 `route()` 业务方法，与 `Page.route` 路径属性冲突。改为 `apiPath()`，所有请求路径保持不变，相关 VM 注入 `route='pages/…/index'`。全页检测不再定义这两个保留属性方法。这是同类静态修复，不声称此次已经实际重新操作微信邀请或 AI 全链路。

## 自动与实际边界

新增比赛专项覆盖隐藏成功后返回、先返回再收旧结果、卸载跨实例接收成功、换账号、非法响应编号、编辑隐藏409/500。原未知结果测试中的旧实例复用补明确可见状态，以区别真实新实例与已经卸载/隐藏对象。旧表单尺寸和样式未改，仅新增已保存详情按钮及禁止重复保存条件；排版保护仅精确排除此新增入口后继续核对旧结构。

本轮完整原生自动回归508项通过、0跳过，官方30页/4组件共131次虚拟渲染通过，diff检查通过。补充验证换账号手工确认不泄露旧savedId，以及初载隐藏重入和已保存恢复不遗留loading。真实新建战术首屏修后重试、比赛保存正常导航及隐藏往返需由唯一 UI 操作者另行验证。单测、模板渲染不能代表系统页面栈导航已通过。
