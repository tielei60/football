# 第十三阶段：系统账号与强制改密验证

## 13A：首次强制改密（原生已完成）

全新匿名隔离库，启动服务前对显式传入的临时数据库调用既有初始化导出函数，建立匿名系统管理员，强制改密标记为1。这是测试前提，不算UI创建系统管理员；未执行会默认访问正式库的脚本CLI。临时凭据只保存在本地受限文件/内存，不进入仓库或报告，原生密码框均掩码。

| 真实操作 | 核验结果 |
|---|---|
| 初始密码登录 | 实际进入首次修改密码页 |
| 新密码不足10位、两次不一致 | 页面阻止，改密PUT为0 |
| 当前密码错误 | 服务端403，未改密码 |
| 新密码等于初始密码 | 服务端400，未改密码 |
| 正确填写并修改 | 204，返回登录页 |
| 再用原密码登录 | 401，不能登录 |
| 新密码登录 | 200，正常业务首页 |
| 正常退出 | 登录页，活动会话0 |

成功改密后account_revision仅1→2，must_change_password变0，该用户所有旧会话均撤销；额外独立旧会话实际请求/auth/me返回401，不仅靠界面退出推断。其他球队、球员、比赛、相册和战术业务摘要不变。

## 收尾与范围

正常UI退出后会话0，隔离配置原字节恢复，只停止本次代理与后台；未改变真实账号或用户预览。产品源码无变化，不把本轮测试前提当新增功能。

关联球员角色切换及非系统账号权限入口继续下一批；未覆盖项不记通过。真实微信登录和外部平台能力仍未验证。


## 13B：独立管理员创建与启停（原生已完成）

另建匿名库并按13A方式建立测试系统管理员。真实从“我的”进入系统账号页，系统管理员自身为只读，不出现角色/停用操作。创建普通独立管理员先取消，无POST及数据库记录；再确认恰好一条role=admin、is_system_admin=0、must_change_password=1、无关联球员的账号。同名再创建实际409，不产生重复账号。独立管理员卡片没有撤销管理角色入口。

停用取消无PUT，确认账号revision1→2，辅助旧会话实际401；启用取消无PUT，确认revision2→3，旧会话仍401而非复活。授权epoch按启停两次的代码规则1→3，已单独精确核验；不能把预期授权变更称为完全所有表不变。其他比赛、球员资料、相册和战术业务摘要保持不变。

早期CLI选择器误入球队设置，失败截图05保留且不计系统账号页通过；之后实际界面进入正确页面重验。正常UI退出后会话0、原配置恢复、自有服务停止，没有操作真实账号。

本批未把辅助旧会话401扩大为“停用后密码登录/启用后新登录已验证”；新建管理员首次登录闭环、关联球员角色变化及非系统权限继续另批。产品源码未变。


## 13C：关联球员角色与权限隔离（原生已完成）

全新匿名库中，系统管理员实际选择关联球员账号：授予管理先取消零写，再确认player→admin，账号revision1→2；额外旧会话实际401。该球员真实重新登录，显示普通管理入口，但没有系统账号入口；直接进入系统账号页显示无权访问，无账号列表和管理控件。

系统管理员再真实撤销该账号管理角色，admin→player、revision2→3，旧管理员会话实际401；重新以球员登录没有普通管理入口，直接系统账号页仍拒绝。playerId关联始终保持。两种非系统身份辅助GET/POST/PUT系统账号API均403，用户表摘要未被拒绝请求改变；辅助接口检查不冒充UI操作。

普通非强制改密球员直接进入force-password发生立即重定向，官方导航等待超时，未把超时本身算成功，也未重复写操作；随后实际截图与runtime都确认已返回业务首页。失败工具返回与后续证据保留。

授权epoch按两次角色变化1→3，其他业务摘要不变。四次正常UI退出、最终会话0，配置原字节恢复，自有服务停止。产品源码没有修改。停用状态密码登录拒绝、启用后新登录以及新建独立管理员首次改密闭环仍由13D补齐。
