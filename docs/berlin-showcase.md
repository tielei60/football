# 柏林花园干净本地展示

## 与业务演练的区别

此入口只展示项目历史资料中的20人姓名、位置和原有队徽，不附带虚构比赛、比分、赛季、场地、战术、照片或球员测试账号。原 `start-berlin-rehearsal.mjs` 继续用于模拟业务，两者不互相覆盖，也不复用已有数据库。

球队名称沿用 `app/src/data/berlinGarden.ts` 的“柏林花园 FC”；队徽使用 `app/public/team-badge.png`。该图片没有透明通道，不把烘焙背景称作透明图片。

姓名和位置来自项目中交叉核对的历史字面量，不等于已核实现在的成员情况。号码、头像、惯用脚等继续保持未知。展示副本明确设置 `membershipConfirmed=false`，保留来源的隔离 `inactive`，界面应呈现“待确认”，不得据此宣称实际离队，也不强行改为在队来增加可见性。此字段不改变原有身份权限、报名或统计规则。展示副本仅在逐条确认备注恰好等于生成器固定技术说明后清空该说明，页面只保留简短的状态提示；遇到不同备注立即停止，不擦除真实用户备注。原来源库的备注、来源记录及私有清单仍保留说明。

## 启动

安装项目依赖并使用项目要求的Node.js，在仓库根目录执行：

```sh
node scripts/start-berlin-showcase.mjs
```

不接受任何参数。每次创建新的私有临时来源库，再通过SQLite backup API生成独占展示副本 `showcase.sqlite`，核对源库摘要不变。只有副本进行待确认标记和球队名称、队徽设置。不会覆盖生产库或此前的来源、演练、展示资料。

服务只监听随机端口的 `127.0.0.1`，微信与AI关闭，不调用外部地图、不读取生产数据库配置、不修改小程序配置。终端仅打印地址与私有清单路径。目录0700，数据库与清单0600。

`showcase-private-manifest.json` 中的管理员为随机密码的本机操作凭据，不对应任何真实球员身份；不存在额外球员账号。不要把清单、数据库或真实名单上传、提交Git或贴进日志。回环地址不表示手机真机可访问。

历史合影仍只保留在另行授权的私有文件中，此入口不读取或导入合影，也不把它们关联到虚构比赛。若需增加球队相册，应另按真实资料用途和权限设计。

## 查看与停止

操作者自行将本地小程序连接到打印的地址，使用私有清单里的管理员查看名单。需要包含未确认状态的筛选；确认成员现况必须由管理员核实后显式保存，不通过修改备注或状态自动确认。

按Ctrl+C或SIGTERM停止服务，等待连接、异步任务及SQLite资源完成关闭。正常停止保留本次目录便于核对，但系统临时目录不是长期备份。启动失败仅尝试清理本次独占新建目录，不批量删除其他资料。
