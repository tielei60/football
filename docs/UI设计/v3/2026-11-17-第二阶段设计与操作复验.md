# 第二阶段：设计差异与真实操作复验

## 范围与隔离

沿用 `codex/ui-design-v3`。源码修改仅涉及七页展示及回归测试。原工作区、真实柏林球队数据库、用户预览均未改。真实控制器验证使用专门生成的匿名临时数据库，关闭微信和AI外部能力；以下结果不能替代正式数据、真机或外部服务验收。

## 按设计修正

- 首页：圆角主视觉改为斜切下沿，快捷入口图标恢复更醒目比例；装饰层不接收点击并预留正文空间。
- 登录：队徽扩大，短屏仍清晰，不固定页面高度阻止滚动。
- 赛季编辑：阵容管理改为白色入口卡，左图标右箭头，保存仍是主操作。
- 球队设置：队徽标签移到预览框外，选择图片为描边图标按钮，移除弱化。
- 赛季管理：新增按钮补加号；说明保留跨年、独立赛季归属并明确重叠周期不会自动合并统计。已核对后端按season_id统计。
- 球场管理：新增加号，位置状态与右箭头分离，去除重复说明。
- 球场编辑：地图选点改为描边次操作，保留主保存按钮及危险移除语义。

独立审核发现新选择器覆盖按钮禁用视觉，已补充高优先级禁用态。原有事件、条件、禁用、数据绑定均保留。

## 真实控制器验证（不是静态夹具）

1. 管理员登录：实际输入账号、密码并点击登录，进入首页。首次自动化调用遇到页面尚未就绪，重读当前页后重试成功，不将工具报错归为产品缺陷。
2. 登录后30个页面逐个打开、截图并记录loading/error。四个战术页首次使用旧脚本硬编码ID返回未找到，随后采用本次种子清单ID逐页重试，均正常。普通管理员访问系统账号页正确显示无权限。
3. 赛季日期：真实点击开始日期，选择次日后取消，原值保留；再次选择并确认，表单更新；点击保存显示成功。只读SQLite核验起始日期更新为所选值，revision由2增至3。
4. 球员登录：先从界面退出管理员，再实际输入球员账号密码登录。比赛详情canReply为true。
5. 球员报名：真实点击参加、待定、请假，各次页面状态分别yes/maybe/no；SQLite最终为no且该球员/比赛只有1条记录。
6. 球员权限：直接进入球队管理页，authorized=false且提示“仅管理员可操作”。
7. 结束从界面退出球员，临时数据库club_sessions数量为0。
