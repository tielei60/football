# 原生球员照片集：实现与验收边界

## 本批实现

新增 `pages/player-photos`，管理球员页进入维护，球员详情进入只读查看（管理员仍按服务端角色可维护）。目标姓名/号码由相册服务端响应确认，不信任URL姓名。头像保持独立，照片封面不会覆盖头像，也不会改变出场或比赛统计。

支持最多9张独立上传照片、逐张说明、上下排序、出场封面、确认移除；球员仅看授权照片并预览大图。第一批不做比赛相册关联、不做AI生成；对应能力仍是后续方案。沿用紫色token、共享业务弹框、骨架屏及现有单行输入几何，动作按钮可换行且最小44px。

## 接口与安全处理

- 使用 `/players/:id/photos` 及逐张/cover/order子路由；相册使用独立revision，不借球员资料版本。所有变更由服务端鉴权。
- 客户端只保存元数据与本地短图片路径到page.data；原图仅临时私有内存，读取按顺序进行，旧读取通过代次失效。图片类型/大小客户端预检不替代服务端真实解码。
- 同登录上传保存内存任务与requestId，未知结果跨页重进继续同一次请求，防重复点击。文件选择/图片预览触发hide/show时保留草稿；换账号的迟到选图、读取及写入结果不能进入新会话。
- 发送前持久化仅requestId核对收据，键绑定服务地址/账号/球队/球员，不含照片、姓名、token或密码。重启丢失私有图片后不自动重传，显示核对状态，用户明确检查列表后才允许重新选择。存储写入失败不发起上传；旧进程可能已受理的结果不能假称失败。
- 409保留输入并阻止继续写入，重新载入会确认丢弃未保存说明；未确认上传保持。后台预检未发出时取消，不创建上传收据。
- 上传只使用用户选择的图片。现阶段没有上传真实个人照片或调用第三方AI；开发测试仅虚构数据。

## 动作区实际问题与最小修正

375实际截图发现五个按钮挤成一行：全局 `.page .actions>button.ui-button[size="mini"]` 的高优先级规则覆盖局部flex-basis，导致“保存说明/设为封面”折行。现已换用独立类，两列保存说明/设封面，下一行三列上移/下移/移除；事件、权限及44px触控下限保留，未混入缓存改造。

此为浏览器CSS级联回归，不是微信原生计算样式或真机证明；修正后的375宽微信实际截图已复核，见下方记录；320/430原生与真机仍未验。此样式修正未更改演练照片、服务或共享缓存。
