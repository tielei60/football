# 比赛日体验与数据说明

本轮在既有管理端/球员端、浅紫设计系统和 SQLite 后端上完善日常操作，不增加教练端、财务、训练签到或小程序。

## 安排比赛

- 开始日期与开球时间在一个自定义面板选择，显示星期；可选常用时长或自定义 1–1440 分钟。预计结束时间会跨日/跨年计算，不需要再次输入结束时间。
- 时间按球队日常使用的本地墙上时间保存，不暗中换算 UTC。日期、时间待定和未知时长分别保存；旧比赛不会被自动写成 90 分钟。新比赛的 90 分钟仅是可修改的表单起点。
- 赛事、对手优先复用已录入值，但可创建新值；球员位置优先多选。必要的新名称、地址、说明、比分仍允许输入。
- 球场优先从球队场地库选择，临时场地仍可只填文字。首次关联保存场地名称、地址与坐标快照；后来修改或归档场地不改旧比赛。需要新信息时明确切换/重新关联，不在普通保存时偷换历史。

## 球场与地图

管理员可新增、编辑、归档或恢复球场，球员只读。归档不删除历史。场地坐标使用 **WGS84 经度/纬度**，经纬度必须成对保存；不能直接混用高德/腾讯的 GCJ-02 或百度 BD-09 坐标。

地图使用 Leaflet 和 OpenStreetMap 标准瓦片，无需 API 密钥。只有主动打开地图才加载第三方瓦片；不自动读取设备定位，也不调用地址搜索服务。地图支持缩放、移动和点选，保留 OpenStreetMap 署名。无网络或服务不可达时，仍可输入地址/坐标或暂不设置坐标，不影响球场保存。

外部地图加载会向瓦片服务发送常规网络请求及视图区块编号。不要把私人住址当作公开球队场地资料。遵守 [OpenStreetMap 瓦片使用政策](https://operations.osmfoundation.org/policies/tiles/)；不预取或离线下载地图、不去掉署名。此服务不是商用可用性保证，正式部署如需中国大陆更稳定的地图或地址搜索，应自行选择供应商、依法配置其域名与密钥后再集成；当前不包含这类配置或自动坐标转换。

## 比赛须知

由管理员填写纯文本，球员可查看。可用于集合时间、装备、场地规则等，不预填免责或责任条款，不强制勾选同意，不把报名记录当作合同签署或责任豁免证据。若要使用正式责任文件，应另行由适当专业人士审阅并设计明确的签署流程。

## 报名与数据

参加、请假/不参加、待定、未报名四类分开。撤回报名删除本人本场回复，回到未报名；只对已发布比赛开放操作。重复点击或变更回复不会累加次数，次数按符合说明范围的比赛逐场统计，草稿和取消比赛不计入报名汇总。

比赛名单、首发/替补、实际出场、比分、进球和助攻保持独立；不把报名当出场，不把未记录当零。数据录入仍由管理员完成，历史战术和阵容快照保持不变。

## 头像与相册

- 管理员维护球员头像；可筛选有/无头像，从名单快捷进入上传、预览、移除，保存后生效。球员不因此获得修改其他人资料的权限。
- 每场比赛最多 **10 张** 静态 PNG/JPEG/WebP/GIF（不支持动图，最多 1600 万像素），单张不超过 **2 MiB**，总量不超过 **16 MiB**；服务端校验编码、格式与尺寸，拒绝 SVG 和远程图片地址。界面可以预览、调整顺序、设置或取消封面、删除并保存。
- 图片与说明保存在 SQLite；访问需要同队登录及该比赛的查看权限，草稿图片不向球员开放。相册保存有独立按钮，但与比赛共享版本冲突保护，不会静默覆盖其他页面刚保存的内容。
- 列表只取封面地址和数量，不下载全部图片；图片接口使用私有不缓存响应，不公开提供永久外链。相册不是公共图库。

## 升级、演练与回退

升级前使用 `npm run backup` 指定全新的备份文件。新增球场/相册表和比赛扩展列以事务迁移，旧地点、旧头像、战术和统计不清空。旧比赛新字段保持未知/空，不推测历史时长或坐标。

`npm run demo` 每次创建隔离新库，包含虚构球场、头像、须知、时长、封面和两张示意图。`--resume` 只继续本脚本创建的演练目录，不重新灌入数据。原 SQLite 一致性备份包含场地和图片 BLOB，无需另复制图片目录。回退旧代码前应恢复升级前一致性备份，不假定旧版本能理解新字段。

浏览器与服务器回归均使用临时虚构数据。地图测试可固定瓦片响应验证点选/备用输入，不能将其称为第三方网络服务长期可用性验证；最终实测与 CI 结果见对应开发分支的 GitHub Actions。
