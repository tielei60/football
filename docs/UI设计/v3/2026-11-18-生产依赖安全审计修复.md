# 生产依赖安全审计修复

## 触发原因

第十七阶段验证文档提交后的 CI 在 `npm audit --omit=dev` 失败。新增披露的 [picomatch ReDoS 公告](https://github.com/advisories/GHSA-fc5q-39xc-vjpf) 影响到旧锁文件中的依赖链。检查时官方尚无修复版本，不能用盲目 `audit fix` 或降低门禁冒充解决。

项目为 Vue 应用，不使用 Nuxt；原 `pinia-plugin-persistedstate@4.2.0` 却强依赖 `@nuxt/kit`，使相关构建工具链被计入生产依赖。

## 改动及取舍

- `pinia` 固定为 `3.0.4`。
- `pinia-plugin-persistedstate` 固定为 `4.4.1`；该版本将 Nuxt 改为可选 peer，不再无条件引入未使用的 Nuxt 链。
- 由 npm 正常更新锁文件可达关系，没有手工改漏洞等级、忽略项或审计命令。
- persistedstate 3.x 缺少现有项目使用的 v4 `pick`、`afterHydrate` 接口，降级会引入业务改写和持久化风险，未采用。
- Pinia 3 的迁移范围参照[官方迁移说明](https://pinia.vuejs.org/cookbook/migration-v2-v3.html)，核对当前 Vue 3、TypeScript 及 store 写法，并专门复验已有保存数据。

## 隔离验证

不在原工程或符号链接的共享 `node_modules` 中安装。使用独立临时副本安装新锁文件并验证：

- `npm ci`、类型检查、构建通过。
- 加入兼容用例后单元测试 56/56，服务端 210/210。
- 动画与战术工作台浏览器操作 16/16，包括保存重载、备份恢复、版本回滚。
- 新增 `app/tests/pinia-persistence.test.mjs`，验证旧 JSON 字段恢复、`pick` 不写临时状态、`afterHydrate` 回调和自定义旧动画格式转换；独立运行 1/1 通过。这是依赖接口兼容夹具，实际页面行为由上述浏览器操作另外验证。
- `npm audit --omit=dev`：**0 漏洞**。
- 原工作区、正式数据、真实照片、密钥未修改或上传。

可复现命令（先在独立工作副本安装）：

```sh
cd app
npm ci
npm run build
npm run test:unit
npm run test:server
npx playwright test tests/animation.spec.ts tests/coaching.spec.ts
npm audit --omit=dev
```

## 尚未消除的风险

完整开发依赖审计仍包含未修复的 picomatch 风险。此次移除未使用的生产依赖链，不代表上游漏洞本身已修复，也不能声称所有依赖均无漏洞。继续保持 CI 生产审计门禁；开发构建环境不要接收不可信的 glob 模式，待官方修复版本可用后再次升级验证。

独立只读复查确认包版本和锁文件根依赖一致、Vue peer要求满足、没有降低生产审计门禁；兼容测试独立重跑通过。
