# 微信原生小程序：实现范围与验收

基线：`main` 的 `0703a5bd872ab127e1f904c719bb398dc7ffe601`。本轮新增独立 `miniprogram/`，未把开发中的 `codex/matchday-experience` 当作已合并主线，也不覆盖它的战术板、场地和照片工作。

## 从参考到本项目

研究来源为 [两款小程序观察记录](research/README.md)。实际查看了京蔚联首页、赛程、球员、统计截图及大志有球活动详情；其余依据研究记录，不声称重新操作了竞品全部功能。仅借鉴信息层级，不复制品牌、截图、头像、个人信息或未知规则。

| 参考特点 | 本轮实现 | 保持的业务边界 |
|---|---|---|
| 下一场突出、日期和报名直达 | 首页球队摘要、下一场比赛、近期赛果 | 不编造倒计时、队服、人数上限或天气 |
| 日期分组、即将开始/已结束 | 赛程状态分段、月份分组、日期和周几 | 草稿仅管理员可见，取消不混入已完赛 |
| 报名、待定、请假可见 | 比赛详情三态本人回应、人数及名单 | 不自动签到或记出场，不引入费用 |
| 球员卡、搜索、位置筛选 | 球员列表和个人档案 | 不推算年龄、身价、能力或荣誉 |
| 年份榜单、数据完整度 | 显式赛季/自然年、出场/进球/助攻榜、覆盖提示 | 未知保留“—”，报名不等于出场 |
| 移动组织效率 | 管理员新建/编辑比赛、发布/取消/完赛、比分复盘 | 名单录入、完整战术编辑等继续使用已有网页，不删除原功能 |

配色沿用球队浅紫体系：主色 `#8845A0`，白色卡片、浅薰衣草底和冰蓝辅助色；统一在 `app.wxss` 管理。采用原生 Page、WXML、WXSS、wx.request 和微信组件，不是 WebView、Vue 或跨端框架套壳。

## 页面与权限

五个主入口：首页、赛程、球员、统计、我的。额外页面：俱乐部账号登录、比赛详情、球员详情、比赛编辑，共 9 页。

- 未登录不返回俱乐部数据，不提供访客公开名单；客户端隐藏不替代服务端授权。
- 球员只修改自己的报名、自己的密码；管理员不能借任意 playerId 冒充报名。
- 管理员可在小程序创建/编辑比赛，包括赛季、日期/开球时间、比赛制、主客场、状态、比分和复盘。现有网页保留所有完整管理能力。
- 历史名单展示保存的身份、号码和实际出场，不以当前资料覆盖旧快照。战术显示历史留档摘要，不冒充已经实现原生完整战术画布。
- 编辑冲突保留输入，需人工核对后重新载入；不盲目重试覆写。加载失败、会话过期、空列表、防重复提交、迟到响应、隐藏 Tab 清理均有处理。

## 登录方案与部署前提

首期使用已有俱乐部账号登录，**不是微信一键登录或微信身份绑定**。页面对此明确命名，不自动建号，不依赖 AppSecret。管理员仍通过现有网页建立球员账号。

新增 `POST /api/auth/native-login`，JSON `{username,password}`，请求头 `X-Football-Client: native-v1`。返回 `{token,expiresAt,user,team}`。后续原有 API 使用 `Authorization: Bearer <token>`。

- 原生会话与浏览器 Cookie 不能互换。服务端保留原 Cookie/Origin 防护，原生请求拒绝 Cookie、Origin 和浏览器 Sec-Fetch 头；微信自动 Referer 不被误拒。
- 令牌为 256 bit 随机值，带 `native_` 前缀，数据库仅存 SHA256；7天过期，登出、改密、管理员重置、归档沿用统一撤销。
- 客户端不保存密码，不把 token 放URL或页面data；会话缓存与服务地址绑定，换服务器不会把旧token发过去。微信本地存储不是硬件加密保险库，设备解锁后的本地提取风险仍存在。
- 不开放任意 CORS，不为了小程序关闭现有网页 CSRF 校验。
- 不自动上传发布、不注册微信账号、不接受微信协议。需要所有者自己的 AppID、审核资质、HTTPS服务及 request 合法域名。AppSecret 永远不能放客户端代码或提交仓库。

真正微信登录可后续独立增加服务端 code2session、管理员邀请/本人密码绑定、解绑与撤销。不能仅凭客户端 openid 或球员ID绑定账号。无需为此阻塞现有账号闭环。

## 本地运行

1. 仓库根目录进入 `app`：`npm ci && npm run build && npm run demo`。演练只创建隔离的虚构 SQLite，终端给出实际地址和随机管理员/球员账号。
2. 微信开发者工具导入仓库 `miniprogram/`。`project.config.json` 的 `touristappid` 仅供本地开发占位；真实设备/体验版使用自己的 AppID。
3. 在本地 `miniprogram/config.js` 填终端实际端口，例如 `apiBaseUrl: 'http://127.0.0.1:13001', allowLocalHttp: true`。这是服务根地址，不含 `/api`。开发者工具本地调试时按微信工具要求处理域名校验；不要在生产关闭HTTPS校验。
4. 登录终端生成的账号，按下方清单演练。若 demo 绑定随机端口，必须用实际输出端口，不能照抄示例。
5. 真机不能把 `127.0.0.1` 当云服务器；请部署HTTPS服务，将其配置为小程序 request 合法域名，设置 `allowLocalHttp: false`。不默认暴露本机或业务库到公网。
6. 所有后端运行/备份规则仍见 [部署说明](deployment.md)。本轮无数据库schema迁移；回退旧代码不会破坏原有数据，旧版不能使用原生会话。

测试配置不得提交真实服务密钥、密码、生产数据库或私人图片。

## 自动验收

```sh
cd miniprogram
npm ci
npm run check
cd ../app
npm ci
npm run check
npm run test:e2e
```

小程序测试包括：transport与登录竞态、页面业务行为mock、真实HTTP+隔离SQLite全链路和重启、官方 wcc/wcsc 模板样式编译及9页初始渲染。测试依赖只用于开发，不打包进入小程序。

人工微信开发者工具/真机验收仍需补齐：

- 在所有页面查看长队名/无头像/空数据/服务器不可达/过期；切tab、返回、下拉刷新后不残留别人的资料。
- 管理员新建草稿→发布，球员参加→待定→请假；网页刷新看到同一状态。取消后不可报名；管理员再录入赛果与名单，核对统计。
- 两端同时编辑冲突；弱网重复点击；后台切回；改密后旧客户端失效。
- 比赛历史姓名/号码不被现球员资料修改改变；未知助攻与0分辨；跨年赛季与自然年结果分辨。
- 微信键盘、安全区域、原生picker、图片解码和页面长列表的实际表现。
- 合法域名、HTTPS证书、真实AppID与提审隐私声明由所有者配置和复核。

自动模拟不能替代上述微信官方工具和真机验收；没有完成的步骤不得写“全部通过”。

## 后续扩展顺序

1. 先完成真实微信环境体验与现有账号流程验收。
2. 合并已审查的比赛日主线后，对接场地坐标/地图、须知、合影等已授权功能。
3. 如确有需要再做微信绑定、原生只读战术画布、管理员名单录入；保留网页专业编辑器。
4. 人数上限、报名截止、候补必须先定义并发规则；训练签到、付费、预测、虚拟身价、公开招募均不因竞品有入口而默认加入。
