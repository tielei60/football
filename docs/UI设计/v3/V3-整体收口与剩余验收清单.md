## 三、优先收口顺序及通过条件

### P1：无需真实平台账户即可完成，但需要可操作本机
- 球员照片上传/排序未知回执和完整重开：本页自身接口，验证一个任务只写一份、恢复提醒归属正确，不借用比赛相册通过结论。
- 战术创建/画布编辑、比赛名单、赛季阵容、系统账号的尚缺跨进程及未送达场景：先核对已有记录再重试，逐项记录请求数、版本、历史/收据数量及非目标数据不变。
- 邀请管理与AI无费用模拟完整链路：可以用匿名身份/内置几何样本验证，禁止将模拟结果写为真实微信或真实AI成功。

### P2：先验证最近7页，再扫全32页状态
- 41–46列表中7页：原生点击/输入、返回/切换账号、加载错误、图片失败、系统预览、长文字与三宽截图；依据运行提交对照原图，不复用旧截图签收。
- 全部页面的正常/加载/空/失败/长文、角色门禁、键盘/安全区、重复/取消/返回；完成一个场景才关闭对应条目。
- 在可用Mac重跑27项浏览器布局，若失败区分产品问题与运行环境；截图不能替代代码回归，代码回归也不能替代截图。

### 外部独立验收
真实微信登录/邀请绑定、地图定位/选点/导航、系统文件/相册权限、真实AI生成采用，以及iOS/Android真机。当前不配置密钥、不外发真实照片、不发起费用；缺少条件时保持未验。

## 四、云端还能推进什么，为什么此轮不继续小修

可继续只读审查、隔离API/控制器边界、构造本地可复现夹具。现有云副本可运行代码与服务端临时库测试，但无法替代原生控件、地图、真机权限，也不能绕过浏览器启动限制。

本次对历史战术快照、年度报名、统计范围进行了额外只读核对，未发现明确错误；没有为制造进度改变业务规则。上面的高风险未覆盖项主要缺**实际客户端/重开/外部能力证据**，重复相似单元测试不能关闭它们。有新的可复现缺陷时再修复，而非把“未验证”等同“有bug”。

仍有可在云端推进的候选，但应先检查已有自动化，不能仅因原生未验就重复写测试：
- 球员照片上传/排序的未知结果与本页恢复账本，结合隔离API验证数据唯一性。
- 普通/强制改密成功但回执丢失后的旧会话、新密码及重登录隔离集成。
- 模拟微信服务下邀请批准/拒绝/撤销/解绑与成员状态的一致性。
- 战术人数缩减、槽位替换、独立副本未知重试的完整模型/历史核对。
- 系统账号未知结果查询失败再恢复。

已确认仓库有 `player-photos.test.cjs`、改密真实API/生命周期、系统账号恢复、微信邀请及服务端微信认证等相关测试，因此这些是**覆盖核查方向而非确定遗漏或已发现缺陷**。本轮未新增产品代码，避免以细枝末节替代用户要求的全页面设计签收。
