# UI V3 阶段27：赛程权限与首页错误恢复

日期：2026-11-18。分支：`codex/ui-design-v3`。

## 修复

赛程曾在管理员选择草稿后、页面返回时身份变成球员且比赛请求失败的情况下，保留旧 `admin=true` 和草稿筛选。创建入口仍显示，控制器也未阻止跳转。服务端仍校验权限，因此这是旧权限界面残留与交互门禁缺陷，不是后端越权。

本次仅调整赛程控制器，不改变页面结构、视觉主题或业务API：

- 隐藏和刷新开始即清管理展示标志。
- 使用刷新入口捕获的会话 token 与身份校验后的当前 token 比较，不假设 `ensureSession()` 返回 token。
- 确认球员身份后先将草稿筛选恢复为待比赛，即使随后GET失败也不残留草稿。
- 成功加载后按当前身份恢复管理入口；同账号管理员正常返回仍保留草稿选择。
- 创建和筛选处理拒绝隐藏、卸载、加载、错误及无权限状态，拒绝非法筛选值。错误页重新加载按钮仍可用。

首页现有实现无需改动；增加了错误恢复和空态数据回归。本批沿用V3紫色语义与现有状态组件，不为测试修改设计。

## 原生验证

使用新匿名数据库和专属开发工具工程，只通过本机代理注入GET `/api/matches` 503；未连接外部服务、未写正式数据。账号角色变化由隔离SQL建立前提，**不是用户在管理界面完成降权的证据**。

1. 将匿名球员临时设为管理员，实际登录、进入赛程并选择草稿。
2. 实际切到首页；在隔离库恢复此账号的球员角色，并启用GET503注入。
3. 实际进入赛程，确认 `admin=false`、`tab=upcoming`、`loading=false`、有错误、列表为空。截图与原生可访问树都没有创建比赛和草稿入口。
4. 关闭注入，点击“重新加载”，恢复正常球员赛程及比赛内容，没有管理员入口。
5. 再次注入503并进入首页，显示错误状态，没有业务内容；关闭注入后实际点击“重新加载”，恢复球员首页、下一场比赛及2条近期赛果。
6. 正常退出确认回登录页，数据库会话数0。

截图/状态证据位于本地隔离 `ui-stage27`。本批实测的是同token身份变化与真实GET失败，跨账号旧请求隔离由自动测试补充，不将二者混称。无下一场/无赛果/待确认人数在本批只做自动测试，仍需后续原生空数据页面检查。
