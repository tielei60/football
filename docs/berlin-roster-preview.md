# 柏林花园资料只读预览

## 本批已实现

提供本地开发辅助命令，比对前后端现存名单来源，确认稳定来源 ID、姓名和位置一致。只解析源码字面量，不执行来源模块，不打开、创建或修改 SQLite，不读取任何生产库或配置，不生成账号、比赛或统计。

```sh
# 先在 app/ 安装项目开发依赖；从仓库根目录运行
node scripts/preview-berlin-roster.mjs
# 仅在本机需要逐条检查姓名和位置时运行，不把输出提交或外发
node scripts/preview-berlin-roster.mjs --details
```

默认仅显示数量、来源文件和质量说明，不打印姓名。当前来源共20人，其中5人有多个位置。命令不接受目标数据库、输出文件或导入参数；`FOOTBALL_DB_PATH` 对它无效。依赖项目已有 TypeScript 开发包，不作为生产服务启动步骤。

## 未知值与可信范围

原有球衣号码是数组顺序派生，原有健康状态是种子默认值，旧头像路径没有对应受版本管理的图片。预览把号码、头像、惯用脚、健康状态和出生日期保留为空，不将这些值当成现实事实。保留项目来源姓名及位置并不表示已经向每个人确认当前资料。

目前的 `bg-n` 由前端名单顺序构造并与后端显式 ID 逐条核对；若未来两份名单同时重排，本工具不能单凭当前一致性证明历史身份未漂移，导入前仍须比较此前已确认的来源快照。稳定来源 ID 是后续比对依据，不等于某个新数据库中已经存在的业务 ID。现阶段不会根据同名自动合并，不覆盖既有真实资料，不导入虚构赛果。

## 后续仍需实施

选择明确的隔离目标库，建立来源 ID 与业务 ID 对照，再预览新增、冲突和保持项；核对后才可进行事务化导入。导入真实使用库前必须明确目标、备份及回滚。当前工具只完成来源核对，不能称为已经重建球员数据库。

## 验证

`app/tests/roster-preview.test.mjs` 使用虚构单元数据验证未知字段、确定性、姓名去除摘要、来源冲突、重复和异常字段拒绝；同时只读核对仓库现有来源及命令行拒绝目标参数。测试不把名单导出到文件。
