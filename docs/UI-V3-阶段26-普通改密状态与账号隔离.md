# UI V3 阶段26：普通改密状态与账号隔离

日期：2026-11-18。分支：`codex/ui-design-v3`。

## 范围和结论

补齐“我的”页普通改密的错误、切页清理、成功重新登录闭环。依据原图 `05-me-full.png` 保持既有紫色主题、账号区层级与表单布局，本次不调整业务结构或密码策略。管理员无关联球员时不展示球员专属统计与资料入口，不能据此认为与球员设计稿缺少内容。

修复两处页面生命周期问题：

1. 旧账号改密失败后，隐藏页面只清密码而不清展开状态和错误文案，返回或切换账号后残留。隐藏/卸载现在清理表单展示状态，卸载同时清两项密码。
2. A 的改密请求未结束时进入 B 的“我的”，旧 `busy` 会继续锁住 B。现在仅在刷新确认当前登录仍是本次请求归属、且已与旧操作账号不同后废弃旧页面 attempt、解除旧忙态。同账号未完成请求仍保持锁定；不取消请求、不额外清会话，也不修改服务端认证规则。

## 原生操作与数据核对

使用微信开发者工具专属隔离工程、新匿名SQLite库；未改真实账号、柏林来源库或正式数据，未配置微信/AI服务、未外发照片或产生费用。

1. 匿名管理员登录，进入“我的”展开普通改密，输入错误当前密码，实际提交后显示“当前密码不正确。”。
2. 只读核对数据库，原匿名密码仍匹配密码哈希，错误操作未改密。
3. 切到首页再返回“我的”，展开状态为false、错误为空、两项密码长度0、busy为false。
4. 输入正确当前密码和新密码，实际保存后进入登录页。原密码登录被拒；新密码登录成功进入首页。
5. 数据库密码哈希确已变化且匹配新密码；改密后旧会话数0。
6. 正常点击退出确认，最终登录页可见，数据库会话数0。
