# 柏林花园隔离业务演练清单

## 范围、身份与证据规则

本文件记录本轮隔离演练的有限实际结果与后续计划。新增战术创建后共30页；仅标明有实际操作和数据证据的子项，不代表全部页面或状态已通过。既有单元测试、模板编译或历史 UI 通过不自动转为本轮通过。

- 只使用私有隔离数据库副本，不覆盖生产、不上传名单、真人照片、密码、令牌或含真实姓名的截图到 Git。球员与证据统一用 `sourceID` 代称；截图仅记录不含个人资料的证据标识，必要时先脱敏。
- 20 条来源资料用于核对档案承载。未知年龄继续未知，不假定成年；源号码为 `NULL` 时继续为空，不能把显示顺序或派生号码当作来源已确认号码。默认状态不视为健康事实。
- 所有新比赛、比分、报名和统计明确标注“演练”，不得描述为球队真实历史。缺少真实历史统计不通过虚构数据补齐。
- 当前可用于登录的测试球员账号为 **2 个，不是 3 个**。第三种回应可在同一个测试球员上依次切换并核验最终值；若需要同时保留第三人状态，须明确由管理员代录（仅在产品实际支持时）或另建隔离测试账号。服务端预置数据和真实 UI 操作分别记录，不能混称点击通过。
- 唯一 UI 操作者负责实测记录；其他线程不操作模拟器，不在操作期间热更新源码。文档本次建立后冻结并交接，由协调线程指定后续唯一编辑者。

## 合理执行顺序与统计检查点

1. **基线**：只读确认隔离库来源映射、20 条资料、未知字段、2 个测试球员账号；记录基线版本及统计，不在文档写账号密码。
2. **准备**：管理员创建明确演练赛季（跨自然年）、球场、草稿比赛。球员验证草稿不可见；管理员发布后双方重入验证。
3. **回应**：两个球员分别回应，再依次切换参加/待定/请假，核对一名球员一场比赛仅一个最终状态。未回应使用未操作的其他 sourceID；不能把未创建的第三账号写成已登录。
4. **完赛**：管理员独立登记出场、位置、进球/助攻与比分。本轮实际演练比分2:1、名单角色C进球2/助攻1、角色D未出场，其他未登记项保持未知；已核对球队胜1/进2/失1及个人已知覆盖。角色C/D与登录账号A/B不同。个人进球合计是否强制等于球队比分按现有契约记录，不凭空推定限制。
5. **范围**：再创建另一自然年的演练比赛，两场计入同一跨年赛季、分别计入各自然年。榜单进入详情范围不丢；取消/草稿不应冒充完赛统计。
6. **历史**：先保存赛季/比赛名单及战术快照，再修改当前资料或模板，核对历史快照不被静默替换。
7. **扩展及负向**：合成媒体、战术、角色直达拒绝、无数据/重试；受控断网/409/迟到响应单独记录，不能把 VM 当 UI 演练。
8. **收尾**：记录隔离副本的新增/修改、退出结果、配置与临时服务恢复状态；停止服务不等于注销。是否保留演练数据由协调线程明确，不擅自删除来源资料。
