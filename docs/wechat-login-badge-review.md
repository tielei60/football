用户提供的截图已实际查看：左上角为紫色圆角方块与白色 FC 字母，没有图片加载失败标识。该现象与登录页原先把 FC 字母写死在品牌标识中的代码一致，不能描述为真实队徽加载失败。本批改用已确认的项目队徽，直接从 `app/public/team-badge.png` 原字节复制到 `miniprogram/assets/team-badge.png`，不是从登录接口或球队资料请求图片。

来源素材已被 Git 跟踪。原图为 256×256、无 alpha 通道的 PNG，SHA256 为 `67daa96dd61285db3a9616dcb63200c9dfb7a7330516a9b371999af2648b6927`。棋盘格背景是图像内容，不是透明显示；本批未去底、重采样、裁切或生成新图。

保留原紫色标识容器的 88rpx×88rpx 占位及外边距，内部 image 使用 aspectFit。账号、密码及微信入口布局、事件和权限逻辑不变。图片失败显示“队徽暂不可用”，不回退到容易误认球队标识的 FC 字母，不调用网络补图。

新增匿名测试校验素材原字节及固定摘要、尺寸、aspectFit/失败文案，错误事件只改标识状态。把标识子树换回旧字母后的模板摘要仍必须等于原基线，保护其余表单结构；文字基线只更新登录标识子树和新增局部样式，其他页面不变。

本批共 7 个文件：登录页 JS/WXML/WXSS、队徽资源、专项测试、文字基线及本文。全原生 648 项与官方模板 139 次渲染通过。

官方编译后，在 375 宽度开发者工具实际看见完整的柏林盾徽、球及飘带，原 FC 字母已消失。通过官方设备菜单分别切换至 320、430，每次均重载为空登录页；实际截图检查队徽完整、无裁切，输入框、按钮及说明未见明显溢出，320 下说明正常换行。这是三种尺寸重载后的观察，不是同一实例连续响应式验证，也不代表细小文字在所有真机上均清晰。

最终恢复 375 宽度空账号、空密码登录页。没有登录、输入、开启 API 服务或修改配置；本地后端未启动时队徽仍显示。错误回退仅有匿名 VM 证据，未制造真实图片失败，不能称失败态视觉已验。独立相关 67 项测试、Web 构建及类型检查也通过；自动测试与真实显示证据分别记录。

Web 使用的现有本地队徽未改，未修改数据库、凭据或上传发布。本轮验收不扩大为真机、多基础库或真实错误态全部通过。
