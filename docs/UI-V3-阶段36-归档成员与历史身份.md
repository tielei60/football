# 阶段36：归档成员与历史身份

## 既有规则
归档不是删除，也不禁止加入历史赛季。候选列表显示“已归档”。保留在赛季的成员沿用已捕获姓名/位置；移出并成功保存后重新加入，才采用当前资料。本轮不改变业务规则。

## 原生实操
以新建匿名库准备夹具：顾川原赛季身份为门将/1号；当前资料改为归档门将/后卫/88号并设inactive，随后建立基线。
1. 登录匿名管理员，原生赛季仍显示顾川、门将、1号，标注已归档和赛季留存资料。
2. 保存保留名单，身份未被当前资料覆盖。
3. 实际点击移出并确认，保存7人、离开重开核对。候选显示“88 · 归档门将 · 已归档”。
4. 点击添加球员、保存、离开重开，8人中该成员为归档门将/后卫/88号，仍标已归档与赛季留存资料。

## 数据与复核
稳定排序逐表对照：仅club_seasons、club_season_roster变化；revision从2到5（保留、移出、重加三次有效保存），最终8人。当前球员、所有历史比赛、名单快照及其他业务表不变。
独立专项测试2/2：归档成员首次加入；归档后保留旧身份，移出保存后重加才捕获新资料，并逐次确认当前球员及历史比赛原始行不变。完整小程序1229测试与140虚拟渲染通过，无生产代码修改。

## 现场和范围
正常退出至登录页，会话0，恢复原配置并关闭专用s2及本轮临时服务。证据保留隔离工作区ui-stage36。实际归档动作是夹具准备调用存储层，不冒充球员管理页原生操作；真实手机及跨进程恢复未包含。
