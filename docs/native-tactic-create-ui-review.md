# 原生新建战术界面与回归记录

## 实现范围

战术列表新增管理员“新建战术”入口，历史比赛战术和球员身份不开放。新增 `tactic-create` 页面，30 页路由；表单复用现有输入样式、自定义选择器、业务弹框和 page-state，默认空白。管理员填写标题、选择5/6/7/8/9/11人制及可选阵型，成功后进入原竖屏战术板。创建前不增加一套 Canvas。

阵型从管理员目录接口取得，不复制前端目录。阵型仅放置匿名主队棋子，无真实 playerId、头像或个人资料；空白模型没有任何棋子。后续设置与编辑使用现有流程，不修改旧模板或历史比赛快照。接口契约见 [新建 API](native-tactic-create-api.md)。

## 请求恢复与本地数据

POST 前保存同一请求编号与固定匿名 payload；按服务地址、用户、球队隔离，每个作用域仅一份。内容最多32 KiB，7天后移除草稿内容但保留最小请求编号，避免未知请求被当成不存在。退出清理所有此类草稿内容，同样保留核对编号；不存登录token、真实成员引用或图片。读取存储时重新验证人数、标题、匿名棋子、坐标、允许字段及请求编号，不能直接信任本地内容。

未知结果先读取收据；404不自动换编号或再次提交。当前进程无原请求在途且原固定payload仍可恢复时，用户可以显式确认重试**相同请求编号和相同内容**。同一进程内互斥防重复点击；服务端事务幂等承担跨进程去重。已创建后删除的 available=false 明确告知不复活，用户确认知晓后才开始另一套。

过期或退出后的payload已清除，若收据仍404，本页只允许继续核对，不能擅自重造旧payload或自动新建；这是保守恢复边界。成功进入编辑后清除本次本地收据；导航失败保留“进入已创建战术”入口，不再次POST。隐藏/卸载或身份变化后的旧响应不导航、不覆盖新页面。

## 自动检查与真实验收边界

新增VM及纯模型检查覆盖空白和六人数匿名阵型、管理员/球员、目录迟到隐藏与换账号、双击互斥、隐藏成功保留核对、未知404后同请求确认重试、重启恢复、存储篡改拒绝、过期内容清理、明确400保留输入、删除后回执及导航失败。另补 API 退出草稿清理测试。所有样本为匿名合成对象。

页面计数29→30、数据加载页28→29、业务选择器37→39、原生输入37→38，均仅按新增内容精确更新。旧战术排版保护测试只剔除新入口和对应导航方法，再继续比较原摘要，不重置其他战术页。

最终完整原生自动检查493项通过、0跳过；官方30页/4组件共131次虚拟渲染通过，diff检查通过。新建页/模型专项11项及新增退出清理1项通过。此时尚未进行新建页真实 UI 验收；模板虚拟渲染不等同真实点击、IME、不同屏宽或真机通过。需要实际空库新建→竖屏编辑→保存→重入，并分别记录空白及匿名阵型、角色拒绝与取消。不得沿用本轮先前JSON导入成功作为新建入口通过证据。
