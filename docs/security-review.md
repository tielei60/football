# 后端第二轮安全与数据审查

## 结果与范围

本轮对实际服务端代码及隔离 SQLite 数据库进行复核，覆盖战术与球员历史快照、模板删除、赛季名单、权限与球队边界、版本冲突、事务回滚、头像输入与 JSON 容量。仅使用临时测试数据库，没有修改真实球队数据。

本轮验证结果：`node --test server/*.test.mjs` **48/48 通过**。其中新增独立 `server/snapshot-security.test.mjs` **4/4 通过**。此结果来自本轮实际运行，不沿用早先 CI 或恢复前的测试记录。

## 发现及修复复核

### 战术快照容量放大

原关联接口虽限制请求体与战术数量，却会把多个合法大模板复制为完整快照，产生远大于请求体的事务和响应。已加单场新增关联快照总量 32 MiB 限制，超限返回 413 并回滚全部改动。比赛列表不再包含完整 `tacticSnapshots`，详情接口仍保留完整历史内容。

独立回归使用两个各 17 MiB 的合法来源模板，验证失败后比赛资料、revision、兼容链接和已尝试插入的快照均未改变。既存迁移大快照允许保留及普通编辑，不静默截断旧历史；这些历史详情仍可能较大。

### 快照可信来源与历史独立性

客户端提交的 `playerSnapshot`、时间、来源及伪造 `tacticSnapshots` 不被采纳。球员快照从服务端球员/赛季名单生成，战术快照保存当时完整模板内容。既存快照不会随资料或模板修改而刷新；删除模板后比赛仍能读取原快照。旧数据补采明确标为 migration，不宣称恢复了过去未存储的内容。

独立测试验证：伪造字段无效、缺失模板导致整个更新回滚、过期名单版本不能覆盖历史、删除模板后快照保持一致、列表只保留战术编号而省略完整内容。

### 赛季名单权限和原子性

赛季及球员按登录用户的球队查询。球员可读取本队名单但不能写入；另一队管理员也不能读写。赛季资料与名单共享 revision。新增名单姓名/位置取服务端资料，不信任客户端伪造值；号码可独立设置。

独立测试验证：跨队成员、重复成员、过期版本和无权限写入均被拒绝，拒绝后名单内容与版本不变。

### 头像新值与旧数据兼容

新增/变更头像只接受不超过 2 MiB 的 PNG、JPEG、WebP 或 GIF base64 数据，并检查编码与文件签名。既有原值保持不变时不重新收紧，以免旧大图导致改名、归档失败。旧工作台同步入口也校验变化值；它额外允许严格格式的同源本地图片路径，启动迁移保留既存资料。

独立测试逐一拒绝协议相对地址、反斜杠地址、编码斜杠/反斜杠、外链、SVG、伪造 PNG MIME、路径穿越、query、hash、控制换行以及 javascript 地址。相同测试同时覆盖球员接口与工作台同步旁路，并验证失败时资料及工作台版本完全不变。合法本地图片可保留，旧大头像原值可随归档保存。

## 部署边界

- 完整历史详情可能包含较大的旧快照；列表已避免加载它们。
- 管理员仍可明确编辑比赛、撤销关联或调整名单；快照保护不是不可变审计日志，也不声称防止拥有数据库写权限的人改库。
- 会话/可信代理部署与进程内限流限制见 `security-deployment.md`。多实例应在可信边缘使用共享限流。
- 本轮是针对当前范围的代码审查与回归测试，不代替独立外部渗透测试。
