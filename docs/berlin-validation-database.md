# 柏林花园来源资料隔离验证库

## 当前范围

工具仅准备本机私有隔离库，不启动服务，不向外发送名单。2026-11-14 已按用户要求生成一份真实项目来源的本机隔离资料库，并完成下述只读数据核验；未导入生产或既有演练库。

复用 `scripts/preview-berlin-roster.mjs` 对前后端字面量的核对，加载20人的稳定来源ID、姓名、位置。人数或对应关系改变会停止，不执行来源模块代码。

号码、头像为NULL，惯用脚为空字符串；健康、出生日期、成员现况保持未知。`inactive` 只是隔离资料暂不启用的技术状态，**不代表实际离队或健康事实**。默认在队列表为空，需要切换“已归档”查看，不能直接作为已确认的真实在队/比赛名单。

## 使用与数据安全

审核后需要生成时，在仓库根目录执行：

```sh
node scripts/create-berlin-validation.mjs
```

不接受参数、目标路径或选项，不读取 `FOOTBALL_DB_PATH`。使用系统临时目录下随机新目录（0700），独占创建全新数据库（0600），不复用现有演练库或生产库。失败只清理此次自己创建的目录，不接受外部清理路径。

仅创建一个虚构本地验证管理员。随机凭据保存在该目录 `manifest.json`（0600），终端只显示目录、人数与未启动服务标志，不输出姓名或密码。不创建任何真实球员账号，不绑定微信。不要提交、上传或分享数据库、manifest或其目录。成功生成后，由操作者核对该次目录再清理；此工具没有通用删除命令。临时目录可能被操作系统清理，不是长期备份。

## 初始化与来源记录

用现有store建立新库后，先断言旧名单、战术桌、俱乐部球员、赛季、比赛、报名、出场名单、战术历史与会话均为空。未来底层若自动生成资料，将停止而非清除非预期内容。

不初始化旧战术桌，不写 `team_players`，避免旧名单迁移生成顺序号码、头像路径或默认健康信息。只在新库俱乐部球员表写来源资料；隔离库专用 `validation_roster_sources` 表记录来源ID、文件、内容SHA-256、未知字段和未逐人核实说明。

不生成比赛、赛果、进球、助攻、出场、报名或赛季记录。身份、年龄与当前成员关系仍需另行核实。
