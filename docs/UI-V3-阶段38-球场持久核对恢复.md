# 阶段38：球场新增未知回执与运行窗口重启恢复

## 问题与修复
球场新增请求可能已经写入数据库，但客户端未收到有效回执。原有内存保护不能跨运行窗口重启保留，会留下再次新增的风险。

本轮在发出新增请求前保存并读回核对标记，按服务来源、账号、球队隔离。标记仅包含任务编号和时间，不保存球场名称、地址、坐标或登录凭据。有效成功或明确拒绝清理对应任务；未知回执、过期会话回执、清理失败保留提醒。旧回执和旧确认不能清除后来的任务。

增加“已核对，球场已存在”入口：人工确认列表已有记录后，只解除提醒并返回列表，不新增、不删除、不修改球场。“确认未创建”入口仍保留。未完成的内存请求、隐藏或已退出页面不能直接解除。

## 原生操作验证
使用独立匿名演练数据库及专用微信开发者工具窗口，未连接正式数据库。

1. 原生输入“阶段38匿名恢复球场”并保存。隔离代理收到服务端成功回执后，向客户端返回502，模拟成功落库但回执丢失。
2. 页面进入结果未确认状态，禁止直接重复保存。
3. 关闭并重新打开专用运行窗口，列表中可见该球场；重新进入添加页，表单为空但核对提醒仍保留。
4. 核对列表及数据库仅有该条记录后，点击“已核对，球场已存在”并确认，返回列表。
5. 再次进入添加页，核对提醒解除，空白新建表单正常。
6. 正常退出模拟管理员账号，确认登录页与服务端会话数为0。

全过程新增接口仅调用1次。对照操作前数据库，业务表仅 `club_venues` 新增1条，其余业务表无变化；自增序列表不作为业务内容比较。

- 独立复查后补齐三个恢复入口的严格结构断言，未放宽为任意内容匹配。

## 边界与现场
本轮实际验证的是专用运行窗口关闭重开，不是手机系统重启、所有进程异常或真实弱网。跨账号及来源隔离本轮由控制器回归覆盖，未重复进行原生跨账号操作。标记不恢复原草稿，也不是服务端幂等保证；是否已创建需以列表实际核对，不能把人工“未创建”当作自动证明。

空名称和写前存储失败不会发请求；存储部分写入后读回失败可能保守保留提醒，恢复后可人工核对解除，不宣称所有未发出场景都自动无痕恢复。

原隔离配置已逐字恢复，专用窗口关闭，本轮临时服务停止且端口不可连接。用户正式工作区与正式数据未改动。截图、请求计数、数据库差异与清理证据保留在本地阶段38演练目录，不上传数据库或登录信息。
