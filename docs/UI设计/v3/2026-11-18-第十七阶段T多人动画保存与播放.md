# 第十七阶段 T：多人动画保存与播放

## 实际验证范围

使用微信开发者工具原生模拟器、独立匿名演练库，未修改正式数据及用户原工作区。当前分支 `codex/ui-design-v3`。

1. 在编排页选择第二阶段及“移动本阶段球员/球”，通过真实鼠标拖动两名球员及足球，保存按钮依次显示 1、2、3 条变更。
2. 点击保存，变更归零；退出编排重新打开战术画布，数据保持。
3. 点击播放，完整运行到 2 秒并自动停止。两名新增移动球员、原有跑位球员和足球均到达第二阶段位置。
4. 点击时间滑块中点，显示 1 / 2 秒并停止在对应中间帧。
5. 正常退出临时账号，恢复原配置、关闭专用窗口，停止临时服务；会话为 0，端口已拒绝连接。

## 数据及独立复核

- 三条 `move-participant` 命令只改变第二阶段两名球员及足球坐标；初始画布、第一阶段、其他参与者与曲线均保持。
- 保存结果、数据库及重载完整模型一致。播放末帧与中间帧逐字段符合播放模型重算。
- 战术总数不变，旧版本保持，仅新增一个版本；除目标战术及版本记录、SQLite 序列外，其他 21 张业务表不变。
- 请求日志只有一次业务写入：战术命令 PUT 成功；其余写请求仅登录和退出。
- 另一审查者只读复算上述结果，没有发现本阶段阻断问题。

本地证据目录 `football-ui-v3-interaction/tactic-stage17t` 包含截图、拖动命令、保存/重载/播放模型、SQLite 基线、请求日志及可重复运行的审计脚本。数据库与账号不提交仓库。

## 尚未覆盖

本次是两阶段、两名新增移动球员加足球的原生操作验证，不代表所有人数阵型、三阶段以上复杂动画、多人交叉曲线及真机性能全部通过。下一步继续扩展复杂编排场景。功能没有新增改动，本提交记录验证结果，不把文档提交等同于新功能交付。
