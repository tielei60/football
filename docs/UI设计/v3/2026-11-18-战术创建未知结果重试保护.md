# 战术创建未知结果重试保护

## 问题与风险

代码复查及控制器回归复现：首次创建请求结果未知，核对暂未找到回执，用户确认以原请求编号重试。如果新一次重试收到 400、普通 403 或 429，旧逻辑会清除原收据并解除待核对状态。新尝试被拒绝不能证明先前未知请求未执行，这可能让用户以新请求再次创建。

此问题发生于原请求尚在处理中或代理延迟等未知窗口，不是指已提交的单机 SQLite 回执会无故返回 404。401 会话失效另有守卫，本次不将它与普通 403 混淆。

## 最小修复

- `submit` 默认保守保留收据；只有 `create` 的真正首次尝试显式标记 `firstAttempt`。
- 只有首次明确 4xx 拒绝（不含409）可以清除收据、允许修改输入。
- 恢复后/原任务重试遭拒绝时保留原编号和内容，继续待核对，不生成新请求。
- 每次开始提交时收起重试入口，必须重新核对后才能再次确认重试。
- 不改变服务端原子创建、幂等收据和权限验证，不修改页面结构或 UI 绑定。
