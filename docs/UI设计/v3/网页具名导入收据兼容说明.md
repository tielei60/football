# 网页具名导入收据兼容说明

## 范围

仅调整网页本机战术迁移与备份恢复的返回结果处理、提示文案及具名备份标识透传，不修改布局，不清除本机数据或服务器旧收据，不自动换名重导入。

- `verified`：显示真实新增数量；零新增显示“相同内容已导入，本次未新增”。
- `legacy-unverified`：旧收据无法证明本次内容一致，显示待核对警告，不声称完整迁移或恢复成功；保留本机迁移入口和当前战术选择。
- 兼容旧服务：缺少核验字段且零新增，按未核验处理；明确新增大于零保留新增结果。
- 备份明确携带 `collectionName` 时保留该标识，非法类型继续由服务器拒绝；无名历史备份不自动创建名称，保持既有追加语义。
- 标准备份保留原始 board，不经运行时水合补时间或过滤历史曲线；旧快照缺演示 ID 时采用文件内稳定标识，本机迁移复用同一路径。缺失时间由服务端首次插入补齐，不写入随重试变化的客户端时间。
- 已确认导入但列表刷新失败时，明确提示已导入、刷新失败和不要重复恢复，不冒充写入失败。
- 服务端同名异内容的 409 继续显示原错误，不更名、不清除收据、不自动重试。

## 检查

在独立依赖与隔离数据库目录完成类型检查、构建及浏览器回归：`collection-receipt-ui.spec.ts` 8 项、`persistence.spec.ts` 12 项，共 20 项通过；单元测试 56 项通过，资源包预算检查通过（JS 764938/850000 字节、CSS 111624/160000 字节）。覆盖旧收据警告、旧服务兼容、入口及本机数据保留、具名透传、当前战术选择保留、已核验数量、无名不造名与非法名称拒绝。

新增两项真实 HTTP 数据库回归，分别验证缺时间及历史末阶段曲线的标准备份重复导入、缺演示 ID 的本机快照重复迁移。旧收据与列表失败状态通过 HTTP 响应替身验证网页处理；不以此替代服务端真实旧收据升级及内容冲突的数据库测试，也不宣称小程序或真机已完成操作验收。
