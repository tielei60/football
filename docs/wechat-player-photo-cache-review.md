# 球员照片专用缓存小修

## 范围

新增 `utils/player-photo-cache.js`，仅接球员照片页与启动/会话清理钩子。旧头像及比赛相册的共享 `media.js` 未改；它仍有原32MiB限制，新照片缓存另限32MiB，两者合计可能约64MiB，不能宣称本批解决旧共享缓存满额问题。

## 实现

- 专用目录与页面作用域；同页按不可变照片ID复用，跨页不共享路径。不用完整base64作Map键。
- 持久文件仅限专用目录内严格命名白名单；不会删除系统选择原图、其他缓存或头像。图片数据校验类型、base64完整性/填充位及2MiB限额，写后stat核对实际字节；服务端仍负责真实解码。
- 成功删除照片释放本页路径；刷新释放不在服务端现存ID中的缓存；坏图错误先释放再重试。上传结果未知的候选用独立 `pending:requestId`，不与正式照片或其他候选共用key。
- onHide保留系统预览在用文件，onUnload释放本页作用域；换账号先释放，启动/退出/会话失效清专用缓存。失活作用域不能被迟到请求重新写入。
- 删除失败不扣减实际占用，后续重试；stat无效或未知占用时尽力删除并保守拒绝新写，直到清理确认。文件系统不可用不会阻断退出，但不承诺物理文件已删除。
- 原生选择临时路径不属本模块，不因网络错误删除。另一个页面已完成的待确认上传在刷新后清候选，避免旧候选残留成第二次上传草稿。

## 证据与边界

纯模块11项使用匿名图片和虚拟wx文件系统，覆盖独立路径、拒删系统原图、32MiB/删除失败恢复、无效stat、50次9图进出、注销清理、释放后拒写和文件系统不可用。页面新增4项真实模块+虚拟文件系统集成测试覆盖预览隐藏/刷新复用/卸载、服务端移除ID、跨实例候选完成与坏图重试；API测试另断言会话清理钩子。

测试不是真机磁盘、微信系统预览或物理删除证明。实际工具补验结果见下节，未验证范围不得以VM替代；不上传真实个人照片，不修改已有演练资料。

另有3项页面自动回归：已恢复的 pending 候选在明确400/409拒绝后刷新，清除已释放的专用缓存预览并保留说明、提示重新选图；普通系统选图在400后仍保留原临时路径和说明，不因缓存清理误删。该网络故障分支仅虚拟请求测试，不算人工故障实测。

最终全量399项测试、0跳过，官方模板115次渲染通过，差异检查通过。32MiB是模块逻辑预算，不保证微信实际磁盘一定可用。当前选图仍拒绝超过2MiB的原图；手机原图压缩/本地缩图兼容性留待独立验证，未混入本批。
