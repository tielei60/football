# 球员 AI 出场照与头像方案（设计稿，尚未接入）

## 1. 需求与交付边界

推荐首版由管理员在小程序的“管理端 → 球员资料 → 照片管理 → AI生成”上传已获授权的对应球员照片，生成出场照和头像，在小程序内预览、选择、确认启用和删除。本人自助生成作为后续可选权限，不是首版必做；管理员身份本身不代表已取得全队的照片处理同意。当前仅设计：没有选择供应商、上传真实图片、调用生成服务、产生费用或实现真实动画。本文不承诺尚未核验的能力、生成速度或价格。

采用静态图片优先的分阶段方案：

1. 首期生成静态出场照及适合小尺寸识别的头像候选，分别确认启用。
2. 如需轻动效，可在本地展示卡片淡入、轻量切换；这不是 AI 视频，也不把静态图伪称动画。
3. 真正人物动作、视频或动态头像待供应商能力、格式、平台限制、身份还原效果、成本和隐私条款验证后另行设计，默认关闭。

AI 图片只用于资料展示，必须带有清晰 AI 生成标记，不作为真实比赛出场、成绩、健康、年龄或身份认证的证据。

## 2. 与当前产品一致

- 沿用已确定的紫色主题变量、文字层级、按钮规格、共享业务弹窗、选择面板、骨架屏、错误/空态和既有异步交互约定，不新建第二套设计系统。
- 首版入口归于管理端球员资料的照片管理，不打断比赛报名与战术操作，与[下一阶段改进清单](wechat-next-improvements.md)中的“球员出场照片集”管理员维护规则一致。服务端同时校验同队管理权限、目标球员及该次处理授权，不能把管理员角色等同任意代生成许可；不新增注册或收费模块。
- 提供一个明确主流程：选择照片 → 本地预览与用途说明 → 选择已有模板 → 查看费用和处理条件并确认 → 等待任务 → 比较候选 → 分别启用头像/加入照片集。
- 可选择的风格、构图和球衣配置使用统一选择器，不要求用户写复杂提示词。首版模板由系统限制，不接受可改变授权对象或绕过安全要求的自由参数。
- 状态显示简洁；必要的隐私、成本、不可取消费用和删除边界保留，不能为精简文案隐藏这些约束。

## 3. 本人、年龄与第三方授权

上传前管理员明确确认有权使用该照片，并已取得对应球员本人及必要监护人的照片处理授权，范围涵盖指定提供方、用途和条款。优先单人、脸部清楚的照片；含他人或合影不能自动裁出他人代为处理，不自动识别人脸去绑定球员身份。管理员不能仅凭角色批量替全队同意。

现有资料未确认年龄，不假定所有球员成年。涉及未成年人时，必须按适用要求完成必要监护人同意及服务年龄限制核验；未完成前不向第三方发送照片。不能仅凭相片外观推断成年或让普通勾选替代依法需要的监护流程。具体流程与法律文本在确定服务地区、受众和提供方后核验，不在本设计中宣称法律合规已完成。

第一次提交生成前必须明确展示并获得对应授权：

- 具体处理提供方/目的地，发送哪些照片和配置，生成头像/出场照的用途。
- 原图、结果和可能派生数据的保留期限、存储地区及删除方式。
- 是否用于模型训练、人工审核或产品改进，是否可拒绝；未核实条款不得写“绝不训练”或“即刻彻底删除”。
- 费用、计费单位、上限、失败/取消收费及退款规则。

更换提供方、扩大用途或保留/训练条款发生实质改变时重新确认。对非必要资料授权的拒绝不能阻止普通俱乐部登录和使用。不能把登录同意或之前本地调试许可当作向任意 AI 服务发送人像的授权。

## 4. 原图与结果的访问边界

原图默认私有，仅允许获得该次处理授权的上传管理员、照片本人（如已提供经过鉴权的本人访问入口）及限定服务端任务读取。其他管理员不因管理角色自动取得全队原图读取权；读取、审批启用与一般球员资料管理分别授权。不放入公开头像地址、公共静态目录或普通球员列表。其他队员不能因为能看球员资料就读取原图。

上传图片在服务端进行真实解码、格式验证、字节/尺寸/总像素限制，重新编码清除 EXIF 定位、设备信息及其他非必要元数据。仅改扩展名或信任Content-Type不足以完成校验。处理完成前的临时文件也需隔离、限额、超时清理，不能记录原始二进制或base64到日志。

生成结果先进入私有候选区；由具备目标球员照片管理权限且已核验处理授权的管理员明确审批启用，不能自动授权所有管理员读取原图。确认启用后才按现有球队访问权限向授权成员展示。保留来源类型、AI标识、关联任务和启用人/时间，不把提示词或第三方密钥公开到相册元数据。

## 5. 异步任务与可替换提供方

服务端定义内部provider接口，例如提交、查询、取消、删除远端产物、能力说明；这些是待实现的内部契约，不表示任何供应商均支持所有动作。不支持查询/取消/删除的能力必须显式标记，不能用成功空响应冒充完成。

建议任务状态：

`待确认 → 待提交 → 已提交/排队 → 生成中 → 成功待选择 → 已启用`

另有 `提交结果未知`、`失败`、`取消请求中`、`已取消`、`已过期`。业务任务和候选图片分别记录；启用一张不要求删除其他候选，过期清理须有明确策略。

每个任务保存用户/球队/球员ID、原图对象ID、模板版本、提供方、请求幂等ID、外部任务ID、状态版本、费用授权快照、预留额度及时间。数据库不存API密钥、公开原图URL、敏感请求全文或登录code。

- 客户端离开、后台或重启后可查询同一任务，不反复重新发起生成。
- 服务端worker使用任务租约和原子状态转换，重启后恢复查询，不因重复取队列就重复计费。
- 接口幂等ID绑定授权人、原图、模板与费用范围；同ID不同载荷拒绝，同载荷返回既有任务。
- 本地幂等不能单独保证外部服务恰好执行一次。提交超时但可能已受理时进入“提交结果未知”，优先按外部任务ID或提供方幂等键查询；无法查询则提示核对，禁止自动创建第二个收费请求。
- 超时、失败、被拒绝或无满意结果均不覆盖原头像和相册。
- 用户取消先阻止后续自动启用，再尽力取消远端任务；取消不保证停止处理、不保证免收费，也不能伪称远端已删除。

## 6. 配额、预算与成本确认

正式功能默认关闭；仅有明确服务配置和审批过的成本策略才能启用。测试提供方只能用于测试，不能在生产作为“生成成功”替身。

配置每授权上传管理员/球队的并发、每日次数、每任务候选数量和预算上限。创建任务时在事务中预留额度，避免并发穿透；根据可验证的提供方计费结果结算或保留待核，不将所有失败都自动视为免费。

生成确认页应列具体提供方、服务项、币种、金额或严格最高收费上限、一次性/重复生成次数、包含的候选数量、取消/失败收费及退款限制。无可判断总价和上限时不能提交收费任务。超出授权上限、更换计费服务、追加付费重试必须重新确认。不得默认订阅或默认开启持续生成。

服务端以不可篡改的授权记录校验，不信任客户端提交的价格或“已同意”字段。具体采购授权和支付流程按实际提供方及平台要求另行落实，本设计不产生支付授权。

## 7. 头像与照片集分别启用

头像、出场照片封面和照片集是不同用途：

- 头像继续用于名单和小尺寸识别，可以裁剪候选副本，不强制替换原有头像。
- 出场照可加入已授权照片集，是否成为封面由具有相应权限的管理员单独确认；不自动改变头像。
- 生成成功仅提供候选；“使用为头像”“加入照片集”“设为出场封面”分别明确确认。
- 启用时带球员或相册revision，检查目标球员的照片管理与启用权限、处理授权及目标仍有效。冲突先刷新核对，不静默覆盖别人刚保存的图片。
- 账号切换、归档、解绑或权限撤销后的迟到任务回调不得启用照片或向新账号显示私有预览；服务端每次读取与启用重新鉴权。
- AI图片不自动生成或修改任何出场、比分、进球、助攻记录；合影关联也不能证明真实参赛。

## 8. 安全接口与回调

建议新增按授权对象访问的上传、创建任务、查询、取消、候选预览、启用及删除接口。任务ID或对象ID难以猜测不代替权限检查；禁止跨用户/跨队枚举和访问。

- 密钥只在服务端受控配置，客户端仅持已有应用会话；日志不记录原图、base64、登录code、会话令牌或秘密请求URL。
- 若提供方支持回调，验证其官方签名/时间戳/重放窗口、外部任务与本地任务匹配；不能仅信任回调自报状态或userId。必要时主动查询提供方确认，再执行单调的状态转换。
- 生成结果URL仅由服务端在校验后拉取。固定或受控域名、HTTPS、地址解析与重定向每跳复验，拒绝私网、回环、链路本地、元数据服务地址等SSRF目标；下载限字节、时间和解码资源。
- 不接受用户传入任意“原图远程URL”让后台抓取，也不将外部响应HTML或SVG当人像图片直接展示。
- 临时下载授权尽可能短且最小范围，不能写到公开日志；优先使用既有鉴权媒体读取机制。

## 9. 删除与残留边界

分别提供删除原图、删除候选、移除已启用照片的操作，说明影响范围。原图到期策略不应误删用户已确认保留的结果；删除某张候选也不误删独立头像副本。

为原图及每个派生产物保留内部依赖关系。删除授权明确覆盖相关派生图片时，撤销访问、清理缓存及副本、排队远端删除，并记录状态。异步任务在删除后完成不得把已删除图片重新写回可见区；需删除墓碑/版本检查和迟到结果清理。

服务端删除与提供方删除分开显示。提供方备份、审计、已下载副本或训练用途造成的残留依实际条款说明，不能承诺无法证实的物理彻底清除。删除请求失败应可查询/重试且不恢复可访问性。已被其他成员合法下载的文件通常不能由本系统远程召回，需清楚告知。

## 10. 测试与实施顺序

所有自动化和初期演练使用匿名、虚构且有权使用的测试图，不额外上传真实队员照片。不存在真实提供方配置时，用严格测试替身验证任务状态，不伪称 AI 质量或真实计费已通过。

| 范围 | 必须验证 |
| --- | --- |
| 上传 | 真伪格式、超字节/像素、解码异常、EXIF清理、临时文件清理、对象越权。 |
| 身份与同意 | 管理员维护与逐球员授权边界、其他管理员不可默认读原图、可选本人入口权限、年龄未知/监护前置、拒绝非必需资料、目的地与条款改变重新确认。 |
| 幂等与预算 | 双击、并发创建、同ID不同内容、额度预留、跨日恢复、超上限拒绝。 |
| 提供方故障 | 提交超时未知、可查询/不可查询、重复回调、错误签名、迟到结果、取消仍收费。 |
| 账号与生命周期 | 退出、换账号、离队、权限变更、页面隐藏/卸载后回包不写新会话。 |
| 启用 | 失败不覆盖、头像与相册独立、revision冲突、无确认不启用、AI标识保留。 |
| 删除 | 原图/派生依赖、远端删除失败、缓存撤销、删除后迟到结果不复活。 |
| SSRF | 重定向、DNS地址变化、私网/元数据地址、异常媒体与下载上限。 |
| 界面 | 沿用紫色组件、进度/未知/失败/空态、长说明、小屏与读屏、减少动效偏好。 |
| 真实验收 | 实际供应商权限与条款、授权成本、真实生成质量、保存格式、真机；不由mock替代。 |

实施顺序：先审设计与隐私/费用边界 → 私有媒体及默认关闭的任务框架 → 测试provider和安全回归 → 统一小程序交互 → 获得明确目的地/用途/预算授权后真实接入 → 静态生成验收 → 再决定是否实施真正动画。既有头像和比赛功能始终可继续使用。
