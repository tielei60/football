# 微信小程序登录生命周期复核

## 本轮问题与修复

- 登录页隐藏后，旧成功响应仍可能跳转首页；现在隐藏时取消本页在途尝试、清空密码与提交状态。返回页面只恢复可操作，不自动重新登录，也不处理旧尝试的错误或导航。
- 旧登录页卸载时无条件清理全局会话，可能误清新账号；现在页面仅取消自己持有的登录句柄。
- `beginLogin(username, password)` 返回 `{ promise, cancel }`。取消只有在原尝试未结束且其会话周期仍为当前周期时生效；旧句柄不能取消后续登录或清除已完成的新会话。
- `login(username, password)` 继续返回 Promise，保持原调用兼容。
- 已取消或被新尝试取代的旧请求若迟到成功，继续向原签发服务发送注销请求，使用旧响应的令牌，不触及新账号。注销属于尽力执行；网络失败不能据此声称服务器令牌一定已经撤销。
- 已完成登录后隐藏不主动注销已建立的会话，但不触发隐藏页导航；用户返回后不会自动再次登录。

## 静态验证与边界

新增纯内存测试覆盖隐藏成功/失败、旧页卸载只取消自身、取消后新账号成功、旧成功令牌按原服务撤销、旧句柄不能取消新的在途登录，以及成功句柄不能清理已建立会话。原有同步首页跳转触发卸载、登录配置校验及取消行为测试继续通过。

本轮全原生逻辑测试 **324/324** 通过，`git diff --check` 通过。测试使用虚构输入和内存请求替身，不访问真实账号密码、凭据存储或业务数据库，不操作微信工具界面。

待真实工具复验：登录期间退后台/返回、离开登录页、正常成功跳转、取消后重试及网络失败提示。静态回归不代表这些实际界面操作、服务器注销网络结果或真机后台调度已经验收。
