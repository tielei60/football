# 战术编排画布异步生命周期审查

## 已证明的问题与未证明的原因

真实工具观察过画布空白或上移覆盖工具区；随后旧版与新版各三轮对照均未复现，尚不能确定原生合成异常的根因。

本次另用真实页面定义和受控异步回调证明代码缺口：旧 `nextTick` 或节点测量回调等待期间，页面隐藏再显示、或切至属性页后，旧回调仍可能初始化已经失活的 Canvas。旧检查没有重验 `loading`、`tab`、`hasDemo`，隐藏也未作废绘制编号。这个可复现的逻辑问题不等同于已证明上述原生合成异常原因。

## 最小修复

仅修改 `tactic-compose/index.js`：

- `invalidateSurface` 增加绘制编号，清空旧上下文与坐标矩形。隐藏、卸载、刷新进入加载前及切换页签调用。
- 异步绘制重验加载状态、阶段页签、演示存在、原账号、业务弹层、页面生命周期及绘制编号；延迟任务启动前也检查。
- 绘制编号阻止“隐藏后重新显示/属性页再切回”的状态恢复，让旧任务不能借新状态接管节点。
- 不重建 Canvas，不改尺寸算法、DPR、模板、样式、原生位图初始化或触摸投影。
- 隐藏仍按原行为取消未结束手势，保留已完成命令、撤销栈、模型及未应用输入。卸载和明确刷新仍遵循其原有业务清理语义，没有改变保存协议。

战术文字测试基线只显式更新 `tactic-compose` 的 JS 摘要，记录这是文字批次之后独立的生命周期修复，其余页面与样式摘要未更新。

## 回归证据

`compose-surface-lifecycle.test.cjs` 使用真实页面定义，延迟模拟 `nextTick` 和 selector 回调，10项通过：隐藏显示期间、恢复显示后的旧任务、页签切走再返回、loading/tab/hasDemo条件失活、账号切换、刷新、卸载与正常绘制。断言失活节点不初始化，相关旧任务不进入paint调用；隐藏场景下模型、命令、撤销栈及未应用标题保留，新任务可初始化新节点并进入paint调用。

测试边界：该VM的paint是计数替身，只证明prepareSurface到paint的正常调用链可恢复，不证明真实canvas.draw或原生合成器已绘制成功。页签ABA测试把sync/resize替换为无操作函数，以隔离surface失效编号，不能据其保留标题的断言宣称真实跨页签保留未应用表单。实际select仍会对未应用输入询问确认，确认切换会按原语义同步目标表单、放弃未应用输入；本次没有改变该行为。已完成命令与撤销栈的保存语义也没有改变。

真实开发者工具已完成三轮“属性→编排”往返及离开重入，实际屏幕和截图均正常，changes为0且错误为空。测试期间曾因连接中断暂停，恢复后续完，因此不是连续压力测试。展开态矩形为top=291.59375、343×519.0625；专注态为top=150、300.65625×455。未修改业务数据。

联合文字保护14项通过；本轮全量356项通过；官方模板虚拟渲染111项通过。它们不能代替真实原生画布合成、输入、触摸和长期稳定性验证。上述有限实际复核未再出现异常，但不宣称空白/错层已彻底消除，也不把门禁缺陷修复等同于已确定并修复原生合成根因。
