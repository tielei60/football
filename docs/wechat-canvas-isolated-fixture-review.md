# 独立匿名完整控制流画布诊断

## 范围与隔离

本阶段使用项目外的独立临时小程序，区别于前一阶段嵌入原项目的 30 条件诊断。构建者报告：27 个来源文件按 b96d1b1 原字节复制并以摘要核验，保留完整 board 控制流与四个组件；统一只读 fixture 禁止网络、storage 和业务写入，App 为空。仅使用匿名五棋子及本地样本，不登录、不启动业务后端、不读取真实业务数据。上述隔离属于构建事实，不等同本轮网络抓包证明。

首次用 touristappid 官方开窗返回 APPID_ERROR（不存在此 AppID），未绕过错误或修改安全设置。后按明确授权，只读比较原项目公开 AppID 标量与官方可管理清单，确认名称为“九州科技”；仅将该公开标量用于临时夹具配置后开窗成功。未复制 AppSecret、账号或私有配置，没有上传、发布、真实微信交换或新增自动化端口。本文不记录实际 AppID。

## 工具定位边界

CUA 明确显示独立窗口 anonymous-canvas-diagnostic、匿名首页与战术画布。官方 CLI 使用开窗时的项目路径执行只读表达式，却返回首页单层栈与 canvas 为 null，与当时实际可见 board 不符；路径被系统展开为另一等价前缀时另曾返回无法找到 runtime。

已检查 initializer、debugger、automator 文档、工具清单及本机帮助：相关工具仅公开 project 路径选择，没有 window ID/runtime ID 参数。因此没有猜测隐藏参数或关闭原项目来绕开定位。此后本轮交互完全使用 CUA，不使用该定位不符的 CLI 导航、刷新、点击或数值结果；未获得可靠的 canvas rect、节点位图尺寸、内页 scrollTop 或运行时栈数。

## 原项目业务链路：绘制计数与滚动对照

本节记录独立匿名夹具阴性之后，在原项目隔离业务演练中的两轮有限观察。它与前文夹具操作分别计数，不将匿名夹具未复现写成原业务故障已排除。

### 第一轮：唯一有效绘制仍出现错层

原业务长链首次进入画布时，跟踪只记录一次有效 draw、一次 query 和一次 paint。节点矩形为 top 375.039、left 17、width 398、height 602（单位 px），查询位置与预期布局一致，但实际 CUA 画面仍见场地错层。滚动开发者工具外层预览未恢复。节点矩形正确与屏幕实际错位是同时存在的两类证据，不能只凭查询值判定画面正常。

### 第二轮：关闭页面滚动重绘后的恢复

临时关闭页面滚动触发的 draw 后，重复同一业务链，首次进入仍见错层。随后实际滚动小程序内页至 scrollTop 200，CUA 观察到场地归位。日志共 13 条，只新增滚动事件；drawId、query、render、paint 计数均仍为 1，没有新增查询或绘制。

继续实际滚回 scrollTop 0，画面仍对齐。日志增至 14 条，仍无新增 query、render 或 paint。本轮 playing=false，未进入编辑或保存战术；因此不能将恢复解释为本次播放或业务保存触发的重绘。

两轮后的隔离数据核对：本轮新会话为 0，既有旧会话仍为 1；业务摘要前后相同。不能将本轮退出写成全库所有会话均已撤销。

### 可得结论与待查范围

在这两轮有限条件中，内页真实滚动与画面位置恢复相关，恢复不依赖新增应用层 query/render/paint；外层 IDE 滚动未产生相同结果。这为后续区分页面滚动、路由状态与原生位置更新提供线索，但不足以确定根因，更不能认定为平台缺陷。

本节不是手机真机验证，不构成已实现的修复，也不证明所有页面或所有滚动条件具有相同行为。临时关闭滚动重绘仅是诊断变量，不在此宣称为生产解决方案。
