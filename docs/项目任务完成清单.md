## 一、先看结论

- **基础俱乐部业务、网页端及原生小程序已经实现**，小程序当前有 32 个页面；并非还停留在原型阶段。
- **不能宣称所有任务全部完成**：真实微信身份联调、真实 AI 生成、手机端完整验收及正式数据启用仍有未完成项。
- **柏林资料已保存在本机持久目录**：最新名单为 25 人，已处理用户指定的改名、新增 6 人及移除 1 人，25 份头像、25 份原照均有本地副本。私有目录被 Git 忽略，不提交真实照片或数据库。
- **资料准备不等于当前界面已经切换**：本轮核对时，默认 `app/data/football.sqlite` 尚未创建，原查看服务仍使用匿名数据。未替换当前服务配置、未重新登录，也未把旧测试备份永久删除。
- 后面的“已完成”仅指该行写明的交付范围；不把自动测试、模板渲染、截图、开发者工具实际操作、手机真机验证混为一谈。

### 状态口径

| 标记 | 含义 |
| --- | --- |
| 已完成 | 该项明确范围已有实现及对应审查或验证证据；不代表超出该范围的所有设备均通过。 |
| 部分完成 | 已有可用实现或准备成果，但剩余工作仍影响完整交付。 |
| 待验证 | 代码或资料已就绪，仍缺指定环境、真实操作或正式配置的验收。 |
| 未开始 | 仅有方案或需求，尚无对应完整实现。 |

本清单为状态盘点，本次没有重新执行全部业务测试或修改业务数据。旧文档中的“尚未实现”可能仅对应当时批次；本清单以较新的专题记录为准，不篡改旧验收事实。

## 八、建议接下来的执行顺序

1. **本地正式资料收尾**：不打断正在查看的会话，先备份并核定启用库，完成柏林资料切换、指定管理员初始化与登录；核验当前查看服务的数据来源，避免把匿名预览当正式库。
2. **先完成能独立做的验收**：用最终数据核对球队、25 人、头像/原照、权限、空赛程和统计；补最新 AI 页面及姓名头像实际查看，不发真实照片到外部。
3. **补核心操作和 UI 缺口**：依据第六节逐页记录宽度/角色/状态；优先首次保存、输入法、下拉边框、固定栏、画布原长链、照片和文件失败恢复。
4. **正式微信及手机联调**：在受控配置齐备后验证邀请、绑定、撤销、免密码登录、地图选点/导航、文件保存与手机后台切换；不把开发者工具通过当手机通过。
5. **AI 与动画单列交付**：先完成真实供应商授权/配置/费用边界，再做真实 AI 联调。照片关联、卡片动效和 AI 视频分别实施，不拿现有几何测试替代。
6. 每一阶段审查、测试、精确提交并推送；最终更新本清单，写清真实覆盖、外部依赖与尚未通过项。
