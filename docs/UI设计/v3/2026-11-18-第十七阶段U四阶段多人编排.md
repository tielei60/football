# 第十七阶段 U：四阶段多人编排

## 原生操作

在全新匿名隔离库的两阶段演示上，实际通过小程序操作：

1. 从第一阶段“复制追加”，在其后插入“17U 中场推进”，应用默认 3 秒时长。分别拖动左右两名中场及足球。
2. 再次复制追加“17U 终结配合”，在新增阶段后插入另一 3 秒阶段，再次拖动上述两名球员及足球。
3. 此时顺序为初始阶段、中场推进、终结配合、原第二阶段。总共四阶段，过渡时长为 3 + 3 + 2 = 8 秒，首阶段不计时。
4. 额外拖动门将后点击撤销：保存计数从 11 回到 10，完整模型和命令列表恢复到额外操作前。
5. 保存 10 条命令，计数归零。退出编排并重新打开战术画布，四阶段数据与保存结果一致。
6. 实际点击时间滑块，分别定位到 3 秒交界、4.5 秒第二段中途及 6.4 秒第三段中途。随后从起点播放到 8 秒，正常自动停止。

## 数据复核

独立审查从 SQLite 基线逐条重放 10 条命令，结果与保存模型、数据库及重载模型完全一致。两次插入按现有规则移除受影响的原相邻曲线，其他非目标字段不变。

3、4.5、6.4、8 秒抽样帧逐字段符合播放模型；撤销前后的完整模型及命令深相等。旧版本均保留，仅新增一个战术版本。除目标战术、版本及 SQLite 序列外，其他业务表不变，请求日志只有一次业务保存 PUT（其余写请求仅匿名登录和退出）。

小程序 1220 项完整测试、140 次官方模板虚拟渲染通过。未发现本轮需修改的生产代码缺陷。

## 证据与收尾

本地 `football-ui-v3-interaction/tactic-stage17u` 留存基线、命令、保存/重载/定位帧及截图。正常退出后会话为 0；恢复原配置、关闭专用 s2 窗口、停止临时服务并确认端口拒绝连接。正式球队数据及用户原工作区未改动。

## 限制

通过的是本组四阶段、两名球员及足球的多段实操，不是所有人数阵型、全部交叉曲线或真机流畅度均已通过。快照证明抽样帧和持久化结果，不能代替每一帧的性能验收。门将额外拖动及撤销动作以原生操作轨迹为依据，不单凭最终数据库推断。
