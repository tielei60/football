# 小程序系统账号与首次改密增量

## 范围与身份边界

新增两页：`system-accounts`、`force-password`，总路由 32 页。保留既有 `admin / player` 角色，`systemAdmin` 为独立服务端能力，字段缺失不显示系统入口。系统管理员初始用户名和密码由专用本地配置工具私下传入，不写入源码、测试样例或本文。

系统账号页仅管理当前球队。可创建独立普通管理员；有关联球员的账号可授予或撤销普通管理权限；独立管理员不能伪装为球员，仅能启用或停用。系统管理员行只读，前端没有授予系统管理员身份的选项。权限、最后系统管理员保护及同队校验仍由后端决定，页面隐藏不是授权。

## 强制修改初始密码

密码和微信登录后的入口均检查服务端 `mustChangePassword`。受限账号进入独立改密页，只读取本人会话、修改密码或退出，不请求比赛、球员或统计。普通页面的会话检查同样阻止继续加载；API 保留 `PASSWORD_CHANGE_REQUIRED` 错误码，且只有原账号当前请求可以将当前会话转为受限并导航，迟到旧响应不得影响新登录。

改密成功后清理原会话并重新登录；请求途中换账号不清除后来登录。页面隐藏清空密码输入，初始密码和新密码不写本地存储。服务器撤销所有旧会话的行为须与接口联测确认。

## 管理写入与结果未知

所有修改携带列表中原 `revision`，确认内容说明目标、权限变化和会话失效。取消不写，重复点击受忙状态保护，409 不自动重试，要求重新读取名单。

账号创建接口没有幂等回执。前端采用同次登录的私有在途/未知结果锁，丢失响应后只核对用户名，不自动重复提交。查询到同名账号仅说明存在，不保证其密码等于上次输入；未查到后须明确确认未创建，重新输入密码。密码不进入模块记录。此锁不是跨进程持久回执，进程终止后的同名冲突仍由服务器唯一约束处理，不宣称完整幂等创建。

## 自动化与未验范围

新增原生页面逻辑及 API 测试覆盖：普通管理员拒绝、系统行只读、取消、角色版本提交、409、未知创建核对、隐藏创建完成恢复、改密成功与换账号迟到结果。当前完整小程序 534 项通过，0 跳过；32 页、4 组件共 139 次官方模板虚拟渲染通过。新增 5 个输入在独立输入清单标为未实际聚焦验证，旧布局保护只排除精确新增系统入口。

上述自动化与模板结果不等于真实微信交互通过。本轮实际覆盖与受阻项如下，未覆盖项继续保留，不使用最终用户账号测试。
