# 微信免密码邀请绑定方案（设计稿，尚未实现）

## 1. 目标与明确边界

面向已有业余球队的定向邀请，不开放注册。微信身份用于证明当前微信账号，俱乐部用户、球队与球员绑定仍由服务器管理，不能把“能进入小程序”视为球队成员。

推荐流程：管理员选择既有球员并发出邀请 → 对方使用微信身份申请认领 → 管理员核实本人并确认 → 此后可免密码登录。邀请被转发时，持链接者只能申请，不能直接获得该球员数据或权限。

本文全部新增表、配置和接口均为建议，尚未实现或验证真实微信绑定；没有修改数据库、调用微信授权或配置真实密钥。已有调试小程序只获本地调试使用许可，不推定其可用于正式发布、已具备所需资质或可使用其服务端密钥。

## 2. 已有实现与差距

依据 `server/club-store.mjs`、`server/index.mjs` 和 `miniprogram/utils/api.js`：

| 已有能力 | 当前约束及新增需求 |
| --- | --- |
| `club_users` 存球队、用户名、密码摘要、角色和球员ID | 用户名全局唯一且非空，密码摘要非空；球员ID唯一，复合外键保证球队一致。没有微信身份映射。 |
| `club_sessions` 存令牌摘要、用户ID、过期时间 | native令牌为独立格式，现有效期7天；浏览器cookie与原生令牌隔离。没有认证来源或微信绑定ID。 |
| 原生用户名密码登录 | `/auth/native-login` 是当前唯一无Bearer的原生登录白名单，新增微信接口必须明确接入，不能绕过来源隔离。 |
| 每次认证核验球员active状态 | 归档会删除其全部会话；没有独立的用户停用字段、邀请撤销或微信解绑。 |
| 管理员创建账号、重置密码；用户修改密码 | 重置和修改密码会撤销该用户会话，当前均是密码体系。 |
| 客户端会话绑定签发服务地址、取消登录和迟到结果处理 | 新入口应复用这些保障，不另写缺少身份隔离的登录持久化路径。 |

当前一个用户固定属于一支球队。新增映射表不能自动解决“同一微信管理多个球队”的会员模型问题，本期不假称已经支持；未来需要独立账号与球队成员关系设计。

## 3. 身份确认与权限

- 只接受服务器使用登录code换取的微信身份；客户端传入的 `openid`、角色、用户ID或球队ID不得作为认证依据。
- `openid` 按 `app_id` 隔离；不同AppID的相同字符串不是同一身份。
- `unionid` 不作为必需字段，不依据它自动跨应用合并账号。
- 邮箱、手机号、昵称、头像、姓名、球衣号码均不用于自动认证或合并现有球员。
- 身份判定不要求手机号、头像或昵称授权。首次绑定仅展示必要的身份绑定用途、球队邀请与管理员审批说明并由用户确认；拒绝非必需资料收集不得阻止登录。
- 未绑定者只获得自己的申请状态，不返回球队成员目录、比赛名单、内部战术或其他业务数据。
- 普通球员邀请只能形成player身份，不能在认领或审批参数中指定admin角色。
- 管理员应通过既有线下联系或其他可靠渠道核实本人。微信昵称相同、持有转发链接不是充分证据；审批页面应提示此限制。

老账号可在已经登录且近期重新验证密码后绑定自己的微信，或者走管理员确认。不能静默接管同名账号，也不强迫重建球员ID。管理员首期保留原密码登录和恢复渠道，不直接取消最后管理员的可用认证方式。

## 4. SQLite 增量模型建议

### 4.1 微信身份映射

新增 `wechat_identities`：`id`、`app_id`、`openid`、`user_id`、创建时间、撤销时间、`revision`。

- 唯一约束 `(app_id, openid)`；同一user在同一app最多一个有效绑定，使用部分唯一索引。
- 撤销记录保留审计；重新绑定同一微信需明确更新原记录及revision，不新增绕过唯一约束的重复身份。
- 已绑定另一个用户时拒绝自动迁移，进入管理员核验流程。

### 4.2 邀请与认领

新增邀请表记录邀请ID、球队/球员、创建管理员、token摘要、过期时间、状态、revision、requestId。建议状态为待认领、待审批、已批准、已拒绝、已撤销、已过期；认领申请可独立表保存经过服务器验证的app/openid及其状态。

- 随机邀请凭证至少128位随机强度，数据库只存摘要。原文只在创建成功时返回一次，不放普通列表或日志。
- 默认有效期建议24小时，可撤销。重发时撤销旧邀请；已拒绝或过期后需要新邀请，不自动延长。
- 同一球员、同一app最多一个有效邀请；到期状态在事务中重新核验，不能只依赖后台清理任务。
- 单邀请仅允许一个当前待审批认领；被转发冒领时管理员可拒绝并重新邀请，不永久锁住球员。
- 未确认的认领不创建可访问业务数据的会话。

### 4.3 密码兼容

建议新增 `password_enabled INTEGER NOT NULL DEFAULT 1`。既有账号保持1，新微信专用账号设0，仍保留数据库要求的随机内部用户名和不可知随机密码摘要；密码登录显式拒绝disabled状态，对外使用统一失败提示。

不使用空密码或空摘要绕过现校验。重置密码不隐式开启密码登录；开启应是明确独立管理动作。解绑微信与重置密码也必须分别表达。

### 4.4 会话扩展

建议为会话增加认证方式、微信绑定ID等可空或有默认值的列，旧记录默认密码认证。现有 `INSERT INTO club_sessions VALUES (...)` 必须改为显式列名，避免加列后旧插入失效。

迁移应有版本标记、事务、唯一/FK约束检查及可重复启动测试。对现有账号、球员、比赛历史ID不做替换，不重建或覆盖业务库。SQLite索引约束负责最后一道并发防线，不能只靠先查后写。

## 5. 事务、撤销和竞态

微信code交换在数据库事务外完成，不持SQLite写锁等待外网。认领及审批使用短事务，例如 `BEGIN IMMEDIATE`：

1. 重新验证当前管理员仍有效且同队、球员active、邀请未过期/撤销、申请仍待审批。
2. 校验邀请指定球员与微信身份，拒绝参数替换和跨队资源访问。
3. 复用现有球员账号；没有账号才创建player账号。
4. 在唯一约束下写绑定、消费邀请、完成申请、记录最小审计，同事务提交。

不同微信并发认领或批准只能一个成功；冲突返回明确409，不覆盖已有绑定。审批与归档、撤销、解绑发生竞争时，以事务内最新状态决定。

归档应同时撤销有效邀请、取消待审批申请并撤销全部会话。恢复active不复活旧邀请或旧会话。解绑或换绑建议撤销该用户全部会话，以减少残留权限歧义。此前密码重置只撤销会话；增加微信后，密码重置不代表微信身份解绑，界面必须说明。

## 6. 接口建议与传输边界

以下路径为待实现建议：

| 接口 | 用途 |
| --- | --- |
| `POST /api/players/:id/wechat-invites` | 同队管理员创建定向邀请，支持requestId。 |
| 邀请状态查询及撤销接口 | 列表不返回原始凭证，撤销带revision。 |
| `POST /api/auth/wechat/claim` | 提交code、邀请凭证和requestId，仅申请认领。 |
| 管理员审批/拒绝申请接口 | 核实本人后绑定，重新验证同队和资源状态。 |
| `POST /api/auth/wechat/login` | 只为已经批准绑定者签发既有native会话。 |
| 管理员解绑/重新邀请接口 | 明确核验、撤销旧身份和会话后重新开始。 |

新增预认证路由需纳入原生无Bearer白名单；保持禁止混入Cookie/Origin、请求体上限、客户端标识及限流策略。客户端标识不是身份凭证。后台仍用原生令牌与浏览器cookie隔离机制，不用微信标识直接充当业务Bearer。

错误响应不泄露某姓名、邀请码或openid对应哪个球员。按IP、邀请、已验证微信身份及操作类别限流，限制未认证请求体，清理过期申请；正式部署应考虑跨进程和服务重启的限流一致性，不能把当前内存Map当分布式保障。

## 7. 丢响应、重放与取消

- code交换失败不得消耗邀请；客户端不能假定一次性code可反复使用。
- 邀请创建回包丢失时，数据库仅有摘要，不能恢复原始邀请凭证。requestId重放只能返回“已创建但凭证不可恢复”的状态及非秘密邀请ID，提供撤销原邀请并重新生成的安全路径；不为重放保存、推导或回传旧明文凭证。撤销和重发须再次核验管理员及球员状态，并作废原邀请。
- 认领请求丢响应后重新取得code，使用相同requestId重查结果；服务器再次验证微信身份，确认app/openid与已完成操作一致。
- requestId应绑定操作类型、邀请、目标球员、经过验证的身份及有效载荷摘要。相同ID不同内容返回409。
- 审批重复请求只返回已完成状态，不重复建用户或绑定，不返回旧会话令牌。
- 不把code、AppSecret、session_key、邀请原文或全量请求保存到日志、审计、链路记录。
- 主动退出或切换账号与会话自然到期须分别记录。主动退出后，onShow不得静默调用微信登录把用户立即拉回原账号；保持未登录，等待用户再次点击微信进入。会话到期也不能绕过用户主动退出状态，所有新登录尝试继续使用原有epoch/取消机制，旧回包不得恢复已取消身份。
- 客户端沿用原有issuer/owner/epoch保护。切账号、取消或卸载后的旧回包不得覆盖新身份；迟到签发会话按原签发服务撤销，不清理新账号。

## 8. 配置、测试替身与微信能力

微信认证配置默认关闭。未明确启用或缺少合法服务端配置时，新接口不可降级成模拟登录；返回功能未启用，原密码入口继续可用。

AppSecret仅保存在经过授权的服务端秘密配置，不进入小程序包、仓库或前端响应。当前功能若不需解密数据，不持久保存session_key。测试provider只允许通过测试依赖注入使用，正式运行必须禁止选择测试替身或接受客户端自报身份；启动配置冲突应直接失败而不是宽松回退。

小程序码生成依赖真实账号、相应接口能力、权限及发布环境，需接入时核验。不得用普通二维码或虚构码冒称真实微信小程序码已可使用；没有相关资质时，可先开发邀请状态流程与测试替身验证，明确尚未交付真实扫码能力。

本次尝试打开微信官方登录流程及code2Session文档失败，未以第三方镜像替代官方依据断言最新限制。实施和上线前须按实际账号重新核验官方文档、接口权限、code生命周期、合法域名和真机行为：

- https://developers.weixin.qq.com/miniprogram/dev/framework/open-ability/login.html
- https://developers.weixin.qq.com/miniprogram/dev/OpenApiDoc/user-login/code2Session.html

此处是待核验入口，不是已经成功读取的证据。

## 9. 找回、换微信与管理员恢复

球员换微信或无法访问原微信，由管理员通过可靠联系渠道确认本人，撤销原绑定与全部会话后发新邀请；不允许输入姓名、手机号或号码即自助接管。

保留管理员原密码登录。最后管理员的停用、认证删除或恢复必须防止全队失去管理入口。服务器所有者恢复方案应作为明确、受控的运维流程另行实现，不能暴露匿名重置接口，也不能把数据库路径或秘密恢复值显示给普通用户。

更换正式AppID不能自动复制绑定。应按新的app身份重新证明并迁移，不把旧openid跨AppID复用。

| 邀请 | 创建、过期、撤销、重发、拒绝、转发冒领仅待审批；列表无原始凭证。 |

| 故障 | 邀请创建回包丢失只能撤销重发、微信超时、断网、服务重启、提交成功响应丢失、审批失败事务回滚、限流。 |
