# 比赛名单草稿身份预览修正

## 实际问题与范围

匿名演练中，关联赛季号码为 0、当前球员号码为 1 时，新增名单草稿显示 1；保存后的服务端历史快照及重入显示正确的 0。此前保存及统计没有因此损坏，本批修正预览来源，不能宣称重写历史。

仅修改名单页面 JS、其匿名 VM 测试及本文。模板、样式、共享加载器、服务器、权限和 PUT 协议不变。

## 行为

- 已保存比赛快照优先，其次关联赛季名单身份，最后当前球员资料。仅关联赛季时增加一次既有赛季名单 GET。
- 候选标签与新增行使用相同身份来源，号码 0 保留，null 显示未知；季预览不是已保存历史快照。
- 本场位置仍由原位置选项和本场已选值决定，不用季常用位置替换；出场、首替、进球和助攻协议不变。
- 每次保存成功以服务器完整名单重建原始快照映射：未保存移除再加入保留原历史；已保存移除后再加入按新捕获预览。
- 季请求失败沿用既有错误页和重试；内存草稿及私有基线不提前清空，不静默回落成当前身份。明确丢弃后重载的交互不变。
- 新读请求完成前验证 owner、页面代次、隐藏和卸载状态，避免迟到结果污染私有映射。
- 保存响应同样核验 owner、attempt 与页面代次。同次保存隐藏期间完成则返回后重载；返回后才完成则安全读取服务器结果。错误保稿，旧账号响应不更新新页面。

## 自动验证及边界

27 项名单测试使用真实 shared.load/fail 与匿名 API 替身，覆盖原 7 项、季号码 0/null、姓名、缺席回落、历史优先、连续保存增删重加、请求失败、隐藏/卸载/换账号/新读取抢先、当前 401 与迟到标记、保存隐藏/返回时序及返回鉴权挂起时先完成保存。

测试并未调用实际季接口或操作真实成员，也不等同系统点击验收。季资料在预览加载后仍可能并发改变，最终保存快照以服务器保存时读取为准；本批不扩大季版本 CAS，也不修改历史快照。修后新增行、连续保存及重入的有限实际验证见下节，不扩大为全部生命周期或真机通过。

## 修后匿名连续保存实测

新建匿名副本，预置赛季 P1 号码为 0、当前球员号码为 1；比赛初始 revision=5、名单为空。关键前三次保存全部发生在同一页面实例，期间没有离开重入：

1. 候选标签与新增行均显示号码 0，尚无已保存历史；保存一次后 revision=6，历史快照号码为 0。
2. 未保存地移除并重新加入，仍保留历史号码 0。这个中间草稿观察点没有单独 SQL 核验，不描述为一次持久化检查。
3. 移除后第二次保存，revision=7、名单为空；仍在同页重新加入，显示号码 0、尚无历史。第三次保存后 revision=8，历史快照号码为 0。此后才离开重入，显示仍一致。

后台在各次保存后独立核对字段、其他表及来源库；第三次保存的快照与首次仅捕获时间不同。UI 中默认首替状态 unknown、本场位置为空、appeared/goals/assists 为 NULL，均未改动，不能把本轮当作出场统计操作。

全原生 632 项、其中名单 27 项、官方模板 139 次渲染、Web 构建及独立后端 8 项检查通过。自动检查与本节真实同实例操作分别提供证据，不能彼此替代。实际第四次保存将名单清空，离开重入确认空名单后，正常退出至 375 宽度空登录页。独立核验会话数为 0；比赛完整行相对本轮初始值仅 revision 从 5 增至 9 不同，赛季 revision=6、P1 赛季号码 0 及其他 23 张表与本轮预置基线一致，来源库 24 张表不变。配置经双 SHA 守卫恢复原字节，本轮服务执行会话 exit 0、对应端口无监听，数据与环境收尾完成。

此前 Console Errors 显示 1，原因仍待最小只读检查；不以本轮业务验证和收尾声称运行时完全无错误。
