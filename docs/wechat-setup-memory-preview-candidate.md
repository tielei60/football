# 阵容设置内存图片预览：最短链对照与边界

## 状态与范围

本批已完成指定最短复现链的 A/B 与有限交互检查，是待提交的修复，不代表原完整长链或真机全部通过。基线为 `a056bb2`。仅设置页静态预览由原生 Canvas 改为内存图片；战术板、动画编排、表单字段、保存接口、权限、数据及配置保持不变。

独立匿名夹具已证明当前开发工具能将离屏 RGBA 编码为 PNG，再通过 `createBufferURL` 交给 image 显示；放大、人数切换与回收调用已作有限实测。独立夹具本身不证明产品页已验收、所有微信版本兼容或物理内存回落；产品页的有限实测范围另见后文。

## 实现与边界

- 复用原绘制器。查询原预览位置的同尺寸容器，不再查询原生 Canvas 节点。图片和容器使用既有预览宽高，专注模式保留原计算规则。
- PNG 使用 RGBA8、Filter 0、stored DEFLATE、CRC32 与 Adler32。没有外部新依赖、网络、文件导出、文件系统、Storage 或相册回退。
- 输出按同一倍率取整，最大 600×908、544800 像素。398×602 显示时约为 600×907，不能称为固定 DPR2 或高清保证。
- 24MiB 是缓冲区保守估算上限，不是进程峰值测量。同步绘制和编码可能阻塞较弱手机，不用于动画或滚动帧。
- 同 owner、同预览内容和输出尺寸去重；只有一个待处理最新请求。旧图片先从视图清空，再回收确切登记 URL，成功后才创建新 URL。每控制器至多一个登记资源，不承诺无缝切换。
- image load/error 结束在途状态；没有事件时可点“重新生成预览”结束等待。隐藏清理；卸载使旧回调失效。同 owner、版本、代次、可见性检查均保留。
- 内存 URL 回收失败不重复回收或更换 API；模块停止新增资源。错误提示不暴露 URL。缺能力时明确提示，表单仍可使用。
- 业务弹框期间图片隐藏，原表单与选择逻辑不变。没有实验耗时或资源计数展示。

## 自动检查

- 原设置页 10 项生命周期测试保留，节点替身改为容器测量和图片服务；新增版本变化拒绝旧测量。
- PNG 在内存中使用 Node 内置 zlib 与既有 sharp 解码，验证 CRC、跨 DEFLATE 块、像素、尺寸与输入边界，不生成磁盘图片。
- 资源测试覆盖同内容去重、最新请求合并、跨 owner、无加载事件手动停止、旧事件、延迟清空提交、隐藏/卸载、回收失败停止、缺能力及依赖禁用。
- 全原生 **609/609**、官方模板 **32 页 / 139 次渲染**、Web 构建及类型检查、diffcheck 通过。这些不是实际交互、视觉或真机性能验收。
- 保护摘要只更新设置页 JS、去 class 后 WXML、原 CSS 中预览节点选择器变化；其他五个战术页摘要不变，没有放宽断言。
