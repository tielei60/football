# UI V3 阶段48：球员相册迟到回执核对保护

## 明确缺陷
生产 `api.request` 在服务端成功后若发现本机会话已切换，会抛出 `401 + staleSession`。相册上传把全部4xx当作确定失败，清除原上传持久标记。原账号重新登录时没有核对提醒，重新选择照片会产生新请求编号，服务端原编号幂等不能阻止这个新任务重复上传。

先用现有控制器夹具复现：A上传→切B→stale401→A新token重登，原持久标记从应有1变成0。修前回归失败。

## 最小修改
仅在确定4xx清理条件增加 `e.staleSession !== true`，将迟到会话错误视为未知结果，保留原捕获账号/球员/请求编号的核对标记。没有改接口、认证、图片处理、排序或新增业务规则；普通400/409仍按原规则清理。未保存照片到会话或新增敏感数据存储。

## 真正执行的隔离集成
使用临时HTTP服务、SQLite及生产 `api.js`、`shared.js`、球员相册控制器。图片为本机生成16×12纯色PNG，不含真实人物。

1. A实际上传，服务器返回201并已写入，测试暂缓把201交给客户端。
2. 通过真实登录接口切换B，B打开本页无A核对阻挡。
3. 交回旧201，由生产API自身产生迟到会话错误，不是假造成功落库。
4. A持久标记保留且绑定原requestId，B会话及页面不受影响。
5. A重新登录并新建页面，必须先核对，尝试upload不会再POST；界面侧POST总计1。
6. 辅助API以原requestId重放，照片仍1张、revision不增加，照片内容元数据一致。辅助重放不冒充用户在页面完成重试。

真实集成通过。测试使用内存微信存储与照片路径适配，不等同真实手机系统、文件权限或原生交互。
