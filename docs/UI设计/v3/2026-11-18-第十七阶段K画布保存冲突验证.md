# 第十七阶段 K：画布保存冲突原生验证

## 范围与隔离

本批使用新建匿名演练库及专属微信开发者工具工程，不读取或修改正式球队数据库。开发工具门禁为 `versionRelation: equal`、登录有效。阶段21释放窗口后才接管，未与其他原生验收并发操作。

A 为实际小程序管理员会话；B 为明确标记的辅助 API 会话，用于在 A 编辑期间更新同一匿名战术，**不把 B 的 API 操作计为原生 UI 覆盖**。本批未修改产品源码。

## 实际操作及结果

1. A 通过真实账号输入和登录按钮进入，打开战术画布，点击编辑、选择直线并实际拖绘，保存完整未提交草稿证据。
2. B 辅助 API 读取当前版本，以版本条件新增一条独立箭头标注，更新成功后立即注销 B 会话。
3. A 实际点击“保存战术”，收到服务器 **409**。画面提示战术修改已保留、不能直接覆盖；保存按钮及画布编辑工具禁用。完整 A 草稿、原版本均保持。
4. 再次实际点击已禁用的保存按钮，画面不变，未产生第二次写请求。
5. 点击“核对后重新载入”，确认框明确说明丢弃未保存修改；点击取消后，完整 A 草稿仍与冲突前一致，仍处于冲突保护状态，也未重新读取战术。
6. 再次打开确认框并点击确定，回到非编辑状态，读取 B 最新版本。完整模型、版本散列和数据库逐项一致，不含 A 未保存的直线。

以上行为通过实际按钮、真实拖动完成，未使用 `callMethod`、`setData` 或伪造响应替代操作。

## 请求与数据证据

小程序 A 指向本机透明转发代理，代理仅记录请求方法、路径和返回状态，不记录请求头、请求体、Cookie 或令牌；B 直连同一隔离服务，不混入 A 请求证据。

- A 全程对 `/api/tactics/1/commands` 恰好一次 `PUT`，状态为 `409`。
- 确认重载前仅一次该路径 `GET`（初始读取）；确认后累计两次，证明取消未重新读取、确认才读取。
- 冲突及取消重载后完整模型等于原 A 草稿，版本未被偷偷替换。
- 确认重载后完整模型等于 B 更新返回模型，并与 SQLite 记录及 `tacticVersion` 散列一致。
- 初始球员、原标注、演示动画及曲线、比赛附加信息均保留。
- 仅 B 更新新增一条历史快照，内容等于 B 最新画布；原历史记录完整不变。A 的失败保存和重载均未产生历史快照。
- 除预期战术与其一条新历史外，其余业务记录与基线逐表比较一致；会话及登录尝试等认证运行记录另行处理，最终会话为零。

审计脚本与结果位于本地专用证据目录 `football-ui-v3-interaction/tactic-stage17k`：`audit.mjs`、`audit.json`、`requests.jsonl`、`requests-before-confirm.jsonl`、A 各阶段模型、B 返回模型及截图 `conflict.png`、`reloaded.png`。审计已实际运行通过，未把本地数据库、凭据清单或运行截图提交到仓库。
