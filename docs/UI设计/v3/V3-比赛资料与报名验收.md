# V3 比赛资料与报名验收

## 管理员操作

1. 打开「我的 → 赛季管理」。新增或编辑赛季时，图标和图片可分别选择、替换、移除，也可都留空。保存后重新打开核对；未改图片的保存不会清空原图片。
2. 在「我的」分别打开「赛事管理」「对手管理」「比赛须知模板」。例如新增「日常友谊赛」「GSL 黄金联赛」可用于筛选选择。对手至少填写名称，可选队徽、简介和队员概况；停用后不能再用于新关联，原有比赛不变。
3. 打开「比赛 → 安排比赛」。对手、赛事可从目录选、直接手填，或点「新建」并返回自动选中；取消新增应保留原表单。比赛须知可以直接写，也可以选用或新建模板。模板是起草用的正文来源，本场修改不回写模板，后续模板改动不影响已保存比赛。
4. 比赛状态四选一：草稿、发布报名、已完赛、已取消。草稿只对管理员可见；发布报名后，球员可在比赛详情查看须知并报名。「保存草稿／发布比赛／保存修改」固定在屏幕底部，末行内容能完整滑出，不被按钮遮挡。
5. 比赛相册只负责赛后照片、合影和封面。须知维护请用比赛的编辑入口；不会清除旧比赛已经保存的须知。

## 球员与管理员报名

在报名中的比赛打开详情。「参加／请假／待定」记录的是当前登录账号本人的球员身份，而不是管理权限。管理员仍保留比赛编辑、名单和相册管理入口。未有球员身份的管理员不能替他人报名；系统管理员可进入「我的 → 系统账号 → 我的球员身份」，主动选择本人尚未被其他账号关联的在册球员，确认后重新登录。绑定不可在小程序内更换或撤销；不自动修改现有账号或球员档案。若本人已有球员账号，可把该球员账号设为普通管理员，保留其球员身份。

报名成功并由服务端回读确认后，可选「分享比赛」或「暂不分享」。后者不会撤回报名；取消微信分享也不影响报名。请假、待定、原状态重复点击和失败重试核对都不自动发起分享。

## 兼容和验证

- 旧赛季图片及目录关联默认为空；不根据文字猜目录、不创建样例正式数据、不重置库。
- 前端联动、权限、并发、旧数据、媒体验证使用自动化与隔离 SQLite。把正式数据只用于只读检查或隔离副本，不对正式库做演练写入。
- 微信开发者工具补验：320/375/430 宽度下日期、时间、文字框和下拉对齐，键盘打开与收起，底部动作栏与五项导航，不遮挡；管理员和球员分别点报名，检查分享弹层的取消与主动分享；重开比赛核验须知与照片分离。微信真实消息发送不作为模拟器通过项。
