# UI V3 阶段 30B：未出场与统计联动

## 本轮补齐的原生操作

使用独立匿名演练库及微信开发者工具，不操作正式球队数据。此前阶段 30 的“未出场 false”及统计联动本轮补测如下：

- 打开已结束比赛名单，周泽为替补、中场，已出场，进球 1、助攻 1。
- 选择“未出场”，清除个人数据提示选择取消：原出场状态及进球助攻不变。
- 再次选择“未出场”并确认：进球助攻输入隐藏；保存完整 3 人名单成功。
- 重新打开名单：版本由 3 升至 4，周泽仍为替补、中场、8 号，状态为未出场，进球助攻清空。另两名球员保持。
- 切回统计页“全部比赛”：周泽确认出场由 1 变为 0，进球/助攻由 1 变为未知，界面显示“—”，没有错误显示为 0。球队确认出场合计由 2 变为 1。
- 比赛结果仍是 2 场完赛、1 场完整比分、1 胜，球队进球 3、失球 1，不随个人记录清空而改写比分。
- 点击榜单中的周泽打开球员档案：同为全部比赛范围，确认出场 0、进球/助攻“—”，报名请假 2、未回应 1 不变。

## 数据检查与现场

本地 `football-ui-v3-interaction/ui-stage30b` 留存 SQLite 基线、页面只读状态、截图、请求日志。补测后正常退出账号，临时库会话为 0；恢复配置、关闭专用 s2 窗口并停止临时服务，端口已拒绝连接。用户原工作区三个未提交改动未触碰。

独立只读复核按主键对账：仅目标比赛周泽的 appeared=0、goals/assists=NULL，比赛 revision 加 1；其他业务表完全一致。请求日志仅一次名单 PUT，以及登录/退出。由于还有未录名单的比赛，未知值不代表完整年度总数为 0。

小程序完整 1220 项测试及 140 次官方模板虚拟渲染通过。本轮未发现必须修改的功能缺陷，提交仅补齐实际验收记录。

## 覆盖边界

本轮验证管理员将已有个人数据的单名球员改为未出场，以及全部比赛统计和球员档案联动。不是所有赛季、自然年筛选组合、真机、并发管理员冲突及所有页面视觉细节全部通过。历史赛季与更多组合继续按总表逐项验证。
