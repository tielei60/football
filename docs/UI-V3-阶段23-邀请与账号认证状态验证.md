# UI V3 第二十三阶段：邀请与账号认证状态

## 范围

继续检查微信邀请、接受邀请、系统账号管理及首次改密页面的状态与安全操作。本轮重点是失效会话、旧请求、账号冲突和退出；不改变密码要求、权限规则或页面结构。V3 原图 27、28、31、32 保持作为对应页设计参照；本轮不是重新宣称这四页所有平台能力均已通过。

## 修复

- 微信邀请：刷新身份/数据、创建邀请、审批/撤销/解绑、分页、生成邀请卡片在当前请求 401 清空会话后，统一结束等待、清除本页凭据/卡片/名单并进入登录。入口捕获账号和视图轮次，旧账号、stale 响应、隐藏及卸载页不能接管。
- 系统账号：刷新、创建和更新在当前 401 后恢复，不因旧 token 等值检查而一直等待。清除密码、账号列表和授权操作；正常未知创建核对机制不变。
- 首次改密：初始化旧账号响应不再给新账号回填错误或结束其等待；当前 401 仍正常恢复。未改变密码输入、提交和验证规则。
- 接受邀请页：只读审查未发现同类问题。保留 attempt 生命周期及未知结果主动恢复逻辑，没有修改该页。

## 原生开发工具实测

使用本轮新建匿名 SQLite 库和仅本机临时服务，未使用柏林正式数据：

1. 普通管理员进入系统账号页显示无权访问。为隔离演练管理员准备系统管理员身份后，页面正确显示账号列表。
2. 页面加载后仅增加目标测试账号版本号，再真实点击停用及确认：显示“账号已变化，请重新载入核对后再操作”，数据库账号启用状态未改变；重新载入恢复列表操作。
3. 修复源码重新加载后，仅令当前测试会话过期，再点击“重新载入核对”：返回登录页，所有账号的启用状态、版本和系统管理员标记保持原样。
4. 将本批测试账号设为首次改密后真实登录，进入首次改密页；点击“退出账号”正常回登录，密码哈希及首次改密标记在退出前后相同，没有调用改密。

## 收尾与限制

- 专属窗口关闭，配置与本轮开始前备份逐字节一致；临时服务退出；无正有效期会话记录。
- 隔离库保留为复现证据。系统管理员降级被数据库“必须保留最后一位系统管理员”保护拒绝，未绕过保护；仅恢复测试首次改密标记。此库不是用户正式数据。
- 本轮邀请认证分支是自动回归，不是微信真实平台联调；二维码授权、分享、认领及审核全链路仍待真实平台条件。
- 系统账号创建未知结果、首次改密初始化网络失败/提交断响应，仍保留在剩余原生验收清单。
- 已检查原生首次改密页面的表单、按钮和退出入口；没有据此宣称所有页面全部状态或真机像素一致。
