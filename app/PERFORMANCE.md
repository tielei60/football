# 性能优化与验证

日期：2026-09-10。

## 已实施

- Element Plus 改为组件及样式按需导入。应用主 JS 从约 1.39 MB 降至 625 KB，CSS 从约 395 KB 降至 84 KB；gzip 后主 JS 约 228 KB、CSS 约 16 KB。
- Node 静态服务支持预压缩 gzip、流式响应、ETag/304 和带哈希资源的长期缓存。HTML 与 Service Worker 保持重新验证，业务 API 禁止缓存。
- 拖动事件每个渲染帧最多应用一次；结束手势时立即应用最后采样，并清理事件监听及排队回调。
- 自动保存监听编辑数据变化，完整战术快照延迟至保存时生成。测试中连续 30 次编辑的即时快照次数从 30 次降为 0 次。
- 动画球员使用整体平移，复用身份匹配结果，播放时关闭逐球员模糊阴影、暂停后恢复。不改变动画路径或持久化坐标。
- 修复保存未完成时继续修改名称被异步回调覆盖的问题。

## 生产构建采样

使用本机 Chrome、11 对 11 双方球员移动、默认标注及轨迹、内存数据库。平板与手机使用 CPU 4 倍降速模拟，未模拟移动网络。采样窗口为 1.5 秒，数字为单次观测，不是实机性能承诺。

| 场景 | 视口 | CPU 降速 | 动画优化前 P95 帧间隔 | 优化后 P95 帧间隔 | 优化后本地首次就绪 |
| --- | --- | --- | --- | --- | --- |
| PC | 1440×960 | 1 倍 | 33ms | 17ms | 1.56s |
| 平板 | 768×1024 | 4 倍 | 117ms | 67ms | 5.57s |
| 手机 | 390×844 | 4 倍 | 100ms | 50ms | 4.79s |

三种视口均确认实际动画持续移动，无页面 JavaScript 异常。截图和原始指标位于 `test-results/performance/`（不提交）。PC 接近 60fps；降速后的重负载场景仍会掉帧，因此不能据此保证所有低端设备恒定 60fps。实际 iOS Safari、Android 设备及弱网仍需实机验证。

## 复测

在 `app/` 下执行 `npm run build`、`npm run test:bundle`、`npm run test:server`、`npm run test:e2e`。性能测量单独运行 `npm run profile:performance`，避免同时构建或跑测试。

本轮后端 15 项通过。全量浏览器回归的两项失败分别为保存表单竞态及旧手机名单测试假设，已修复并在相关套件中复测通过；后续动画优化相关 16 项测试通过。构建、类型检查和体积预算通过。未修改数据库结构或用户人员数据。
