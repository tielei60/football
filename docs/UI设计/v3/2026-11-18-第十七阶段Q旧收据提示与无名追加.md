# 第十七阶段 Q：旧收据提示与无名文件追加

## 范围与准备

使用新匿名隔离库与专属微信开发工具窗口，未接触正式数据库、真实照片或原工程。没有产品代码改动。

为构造旧版本升级前提，**通过隔离种子辅助插入**一条 `payload_hash=NULL` 的具名收据，指向已有匿名战术，随后建立本批基线。这不是 UI 导入成果，也不是从旧正式数据库迁移验证。待选文件内容与该已有战术不同，用于明确检验旧收据无法验证内容的限制。

两份匿名文件：`a.json` 含旧收据名称；`b.json` 不含 `collectionName`，包含一套战术和一个历史版本。实际通过系统文件选择器选择，未 mock 文件回调、未调用页面方法或修改页面数据制造结果。

## 实际操作与结果

### 旧 NULL 收据

1. 真实选择具名 `a.json`，保持独立副本选项未选，确认导入并核对。
2. 实际 POST 返回 200、`receiptVerification=legacy-unverified`、`repeated=true`、新增 0。
3. 页面显示：“历史导入记录已存在，本次未重复导入。请到战术列表核对内容，勿重复选择同一备份。”
4. 全部业务表与预置后的基线一致，旧收据保持 NULL，原战术未替换。

**这不代表核验了文件内容相同。** 因旧收据没有内容哈希，服务端仅识别已有名称并停止重复导入。本次明确证明不同内容也不被偷偷覆盖，UI 没有宣称内容已验证或新导入成功。

### 无名文件两次追加

1. 实际选择 `b.json`。页面无独立副本勾选，按钮为“确认追加导入”；确认框说明没有导入名称，将作为新的追加任务。
2. 第一次确认返回真实 201，新增一套战术和对应历史、收据。
3. 再次通过真实选择器选择相同 `b.json`，再次确认，返回真实 201，另新增一套。
4. 实际分别进入两个新增战术画布，读取完整模型与版本；与数据库和源文件对账。

这是无名文件原有追加语义，并非去重失败。两个任务收据名称不同，两个战术 ID 不同；每次页面均准确显示新增 1 套。

## 完整数据审计

本批三次真实导入 POST 状态为 `[200, 201, 201]`。

- 旧收据调用后完整业务快照与基线一致；原 NULL 收据逐字段不变。
- 最终战术、历史、收据分别净增 2 条。
- 两个新增战术的完整模型、画布、标题、标签、收藏、阵型、缩略图与源文件一致；页面版本与规范化模型哈希一致。
- 每套历史仅一条，画布、备注、时间与源文件一致。
- 两条新收据分别映射各自战术 ID，随机任务名称不同，内容哈希均与源文件规范化内容匹配。
- 原记录和其他业务表保持不变。本地导入守卫已清除；退出后会话为 0。

审计脚本初次比较遇到 SQLite 行的空原型对象与 JSON 普通对象差异；统一基线快照序列化后通过。该问题属于审计对象类型差异，不是业务数据变化。
