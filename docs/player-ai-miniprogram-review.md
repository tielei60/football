# 球员照片生成原生页面实施与验收边界

## 范围与默认行为

新增 `pages/player-ai`，由管理员的球员照片管理页进入，小程序现有29页。既有球员相册、头像、比赛与历史数据不自动改变。默认未配置时只显示未启用说明，不开放选图、原图上传或生成。

本地模拟模式只可选择服务端内置几何样本，持续显示“本地模拟，不是真实 AI 生成”；样本仍经过服务端素材解码、授权、任务、候选和明确采用流程。它不代表真实供应商调用、真人相似度、手机上传兼容或计费成功。

未来可信 `configured-provider/file` 模式保留系统选图与上传代码。前端要求处理方、目的地、留存、训练、取消规则、策略版本、币种与整数费用上限均完整，否则关闭。具体条件显示于页面和确认中；仍须服务端可信的逐球员授权策略，不以勾选或管理员身份替代本人/必要监护与指定目的地许可。本轮没有配置真实服务、传真人照片或付费。

## 操作与恢复

1. 选择头像或出场封面用途及服务端风格；模拟仅选内置样本，file仅选择最多2MiB的PNG/JPEG。
2. 明确确认后建立私有来源同意、准备素材；准备完成才可另行确认生成。
3. 查看任务状态并主动刷新，不自动重复提交。候选鉴权读取后写入应用专用临时缓存，页面data没有完整base64。
4. 用户明确采用才写公开资料：头像只改头像；封面明确新增一张至相册并设封面，旧照片不删除、头像不变。采用捕获展示时目标revision，冲突不静默更新版本覆盖。
5. 已确认的409且按requestId核对无采用收据后，才提供重新核对目标入口；重新确认使用新请求，网络未知不得自动清除。
6. 删除私有来源使未采用候选不可用，但不自动删除已明确采用的头像或相册照片。正常删除、删除响应丢失后的核对及显式重试均清应用专用候选缓存，不删除系统选图原文件。

每次写前保存非秘密收据（账号/球队/目标作用域的请求编号、对象ID/版本、用途风格及必要请求引用），不保存原图、token或供应商凭据。未知结果先GET核对；显式重试沿用同一请求编号，不自动创建新任务。重启后已丢失原图的file请求不能换图重试；需继续核对服务器结果。来源processing继续等待，failed保留可清理对象，deleted清本地任务状态。

页面隐藏/卸载及换账号使迟到UI提交失效，旧finally不会清后来操作的busy。候选读取独立校验代次、任务、来源和缓存scope；删除、取消或换任务后的旧读取不复活图片，缓存写入后失效仅释放捕获的旧scope条目，不删除新任务图片。系统选图/预览引起的hide不直接销毁在用临时图片；卸载和退出使用既有专用缓存清理。已登记非秘密收据不会因退出而伪称服务端操作取消。

## 来源标记

服务器决定 `avatarGenerated/avatarOriginKind/avatarAiGenerated/avatarSimulation` 及照片相应来源字段，客户端不生成来源事实。球员列表、球员详情、我的头像和球员照片集显示“模拟图”或“AI 生成”。模拟产物不标成真实AI，也不能作为实际比赛出场证据。手动头像更新的来源清除由服务端负责。
