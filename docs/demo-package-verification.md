# 可重复本地演练包验证

本轮把已验证的虚构场景变为项目自带入口，不分发数据库、固定公用密码或真实个人资料。使用说明见 [本地虚构数据与完整演练](demo-rehearsal.md)。

## 实际执行

- 在无 `node_modules`、无 `dist`、无数据库的全新源码副本中运行 `npm ci`：安装 652 个锁定依赖成功；`npm run build` 的类型检查和生产构建成功。
- 在云电脑原生终端运行该干净副本的 `npm run demo`，创建新的独立临时库并监听随机回环端口。原生终端未配置 Node PATH，指定已安装的 Node 后正常启动；使用者应先安装 Node 24 并确认 `node --version`。
- 真实浏览器以本次随机管理员账号登录，查看 5 场不同状态比赛；跨年赛季汇总与文档的 2 场完赛、1 胜、3 已知进球/1 已知失球及覆盖一致。
- 打开首场比赛的独立快照，实际看见横向 7 人 2-3-1、7 名虚构球员与号码、足球、实虚箭头；切换第二步能看到前锋和球的位置改变。
- 进入原战术中心，首次工作台仅含演练库的 8 名球员；加载赛后模板，播放两步动画、修改步骤要点并保存成功。种子坐标经复核改为真实 1250×826 横向场，而非只凭后端 JSON 保存成功认定可用。
- 退出管理员，用随机球员账号登录；草稿不可见，已发布比赛可把本人报名从参加改为待定。
- Ctrl+C 停服后，按打印的 `--resume` 命令继续，网页显示原登录和待定报名保持，未重新灌入初始数据。

上述是新演练入口的实际交互，不等于重跑所有浏览器自动用例。上一轮完整连续空库业务演练见 [最终业务演练](final-business-rehearsal.md)。

## 自动检查和审查

- 最终构建、类型与体积预算通过；13 个单元、57 个服务端测试通过（包括 5 个演练启动/继续/安全/恢复测试）。
- 329 个独立连续 HTTP/SQLite 断言重新通过；真实前后端服务生命周期 1 项通过。
- 演练种子测试核对 8 人/4 账号、跨年名单/号码、比分未知与零、取消/草稿排除、报名和实际出场独立、战术版本与完整快照、两步动画及数据库完整性。
- 启动器测试向生产环境配置植入未打开的哨兵路径，验证路径/Origin/代理/管理员/Host/Port 都不继承；只监听回环地址，不覆盖旧库。缺构建、参数非法、目录无标记、清单不匹配、数据库符号链接均拒绝。
- 按文档调用真正的 `backup.mjs`，备份复制进另一全新且已停服的演练目录；恢复后原账号可以登录、完整战术动画快照保留，修改恢复副本不改变原库。
- 独立安全审查并真实启动临时库，未见安全阻断。审查提出的特殊路径引用问题已修复：POSIX shell 和 Windows PowerShell 分别使用安全单引号引用，并补回归。
- 新文件语法、Prettier、`git diff --check` 通过。CI 已加入 `npm run demo:check`，但未将配置完成等同远端执行通过。

## 仍有限制

- 当前云电脑的 Playwright Chromium 启动受 socket 策略限制。此前对本轮待发布功能的完整 105 用例尝试为 1 个启动失败、104 个未运行；本轮没有把这些写成通过。原生云浏览器真实交互如上。
- 当前云电脑没有 Docker/Podman；此版容器未本地重验。历史分支的 CI、Docker 和截图不能替代待发布代码的同提交 CI。
- 实际干净安装与网页演练在 Linux；Windows PowerShell 命令仅做格式设计和引用单元检查，未在真实 Windows/macOS 运行。
- 手机端与系统打印按用户最新要求不作为当前重点；未访问或改动任何用户生产库。
