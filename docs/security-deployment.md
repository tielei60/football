# 安全部署与会话失效

生产使用 HTTPS 反向代理，配置 `FOOTBALL_PUBLIC_ORIGIN=https://实际域名`。该地址必须与浏览器 Origin 完全一致（不带末尾斜杠），服务会启用 Secure、HttpOnly、SameSite=Lax 会话 Cookie。不要把数据库、环境变量或管理密码置于静态目录。

## 可信代理和登录限流

默认不信任 `X-Forwarded-For`，使用 TCP 直连地址。登录按「规范化用户名 + 客户端地址」限流（15 分钟内 30 次），另有用户名级防分布式猜测限制（15 分钟内 100 次失败）。一个用户名的失败不会封锁同一代理后的其他用户名；达到限制的用户名/地址组合需等窗口过期。

反向代理部署可显式设置 `FOOTBALL_TRUSTED_PROXY_ADDRESSES=127.0.0.1,::1`，列表必须是实际连接 Node 服务的代理 IP 精确值，不支持网段或通配符。也可在服务器工厂传入 `trustedProxyAddresses` 数组。只加入你控制的代理，后端监听本机或由网络规则限制仅代理能访问。

代理必须**覆盖**（不可追加）`X-Forwarded-For` 为经过验证的单个客户端 IP。例如单层 Nginx：

```nginx
proxy_set_header X-Forwarded-For $remote_addr;
proxy_set_header Host $host;
```

只有 TCP 对端位于配置列表内，且该头是单个有效 IP 时，应用才使用该值。含逗号的链或非法值回退到 TCP 地址，默认配置下伪造该头无效。多级代理应在受控的最后一跳完成可信链解析并传入单个客户端 IP，不应把外部提供的链直接转发。

限流计数保存在单个进程内，重启会重置；多实例部署还应在可信边缘提供共享限流。不要把客户端任意传来的地址头当成已验证身份。

## 撤销与慢请求

密码重置、改密、登出和球员归档撤销对应会话。写入先读取完整请求体，再校验当前会话、球员状态和权限，然后同步执行持久化操作。重置之前开始但尚未上传完的请求不能携带旧密码哈希或旧权限继续修改资料。球员创建与更新保留原工作台头像的请求体容量（默认 25 MiB）；其他普通业务写入默认 1 MiB。

## 初始化与备份

仅首次管理员初始化使用 `FOOTBALL_ADMIN_USERNAME` 与 `FOOTBALL_ADMIN_PASSWORD`，现有管理员密码不会被启动变量覆盖。初始化后移除不再需要的启动密码变量。所有备份须包含一致的 SQLite 数据；运行中使用 SQLite 备份工具，或停服后复制数据库。请勿只复制活动 WAL 数据库的主文件。
