# 原生小程序全页 UI 深度优化计划与审查矩阵

## 1. 基线、范围与证据

- 基线：`4626e7f`。依据用户本轮《微信小程序 UI 视觉层级与用户体验全面优化》完整说明、当前 `miniprogram/app.json`、页面 WXML/WXSS、共享 `app.wxss`、组件源码及既有文字层级专项记录。
- 路由为 **32 页**。组件实际为 **5 个**：原有四组件之外，当前新增 `invite-sheet`，不能沿用旧清单漏验。导航栏与五项 TabBar 同时纳入公共检查。
- 本文是新一轮实施计划，不把历史 25 页、旧测试次数或旧截图倒写成当前 32 页已经完成。以下“问题/风险”来自源码结构与样式审查；除专门附证据的条目外，不表示已在设备上复现。
- 保留紫色品牌、页面整体结构、信息顺序、全部必要字段、现有导航与操作语义。只调整表现类、样式及必要的无副作用界面属性；不修改业务判断、接口、数据模型、数据库、认证、权限、保存/重试/冲突协议，不引新框架、字体或外部素材。
- 现有账号、报名容量、综合排行、邀请卡片、AI 流程等均按本次源码保留，不回退到上轮实现。真实资料不进入测试夹具、提交或外部服务。

## 2. 统一标尺与风险边界

### 2.1 文字与颜色

|用途|候选标尺|使用约束|
|---|---|---|
|页主题|36–40rpx / 600–700 / 1.35–1.45|紧凑管理页、画布页可保留现有32–34rpx；不因规范占用球场空间|
|模块/卡片标题|30–34rpx / 600 / 1.4–1.5|一个卡片只设一个主要重点，普通字段不全部加粗|
|核心值|40–52rpx / 600–700|仅比分/主要统计；序号、版本、数量限制不整体放大|
|正文/字段值|28–30rpx / 400–500 / 1.5–1.7|输入原生几何单独保护，必要时沿用已有字号|
|字段标签|26–28rpx / 400–500|与值在字重或颜色上区分，不能仅靠占位符|
|辅助/状态|24–26rpx；极次要22–24rpx|关键限制、未知结果、冲突不得降为不可读浅灰小字；保留文字语义|

复用 `--ink`、`--muted`、`--brand-ink`、`--brand-soft`、`--surface`、`--canvas`、`--danger` 等现有 token。报名参加/待定/请假语义色与现有代码一致；“已结束”不等同成功。普通正文及重要辅助文字按最终前景/背景计算4.5:1目标，不以肉眼截图替代计算。禁用态不冒充可操作态。无须为了凑层级增加色彩或阴影。

### 2.2 间距、控件与兼容

- 以8rpx为步长：相关图文8、字段内16、字段/卡片内24、模块间32；原28rpx页面边距、输入几何、1px细线等有兼容或布局意义的数值可保留，不机械全替换。
- 当前公共样式有多次层叠覆盖，逐项核最终命中规则；本轮不做大规模清理重构。可以补最少语义类，禁止通过删旧断言掩盖变化。
- 普通主要动作保留现有44px小屏触控下限；紧凑战术工具单独测量，不整体放大挤压竖向球场。按钮文字允许换行但不得挤出卡片或覆盖相邻点击域。
- 原生 `input`/`textarea` 已有光标与高度修复，不随意改变竖向padding、固定height、line-height。焦点、键盘、光标必须单独实测。密码仅用匿名测试数据，不留可见凭据截图。
- Canvas、地图、离屏导出与内存图片预览的几何、渲染时机及触摸坐标不属于样式重构目标；其上方文字变更仍须复测原长链和首次进入，不能以DOM矩形正常代替画面正常。
- 已读本机 `modern-web-guidance` 适用说明：采用信息层级、可读对比、明确焦点、触控及溢出检查原则；本项目不是H5，不引入 `showModal`、Popover、DOM、浏览器专用布局或未经微信核验的CSS能力。本轮不安装新依赖。
