# 第十五阶段：比赛新增、状态与异常核对

## 15A：新增与四状态双角色流程（原生已完成）

全新匿名库与唯一对手标识。真实从赛程新增入口选择2026-11-20、跨年赛季，填写对手并保存草稿，比分均留空。一次POST201创建唯一比赛，版本1、比分null/null；从赛程草稿重进编辑，依次真实保存发布、完赛、取消，三次同ID PUT200，版本依次2、3、4。完赛时我方输入0、对方仍空，数据库保持0/null、界面显示0 : —，未将未知补成0。

每一状态均切换为真实球员身份检查：
- 草稿直达详情被拒绝“未找到比赛”。
- 发布显示参加/待定/请假按钮。本批未提交报名，也未保留disabled属性的独立原始证据，因此不单独签收本态点击可用性或RSVP写入。
- 完赛没有报名按钮，0与未知比分显示准确。
- 取消显示警告，没有报名按钮。

唯一ID仅一条，原种子比赛、球员名单、报名、历史快照及其他业务表摘要完整保持不变。430宽原生检查，不扩大为320/375布局通过。

## 工具失败与安全收尾

初次登录桥超时、错误bindtap属性选择器未命中均保留失败，重试前核对无业务写，不把工具success或超时当功能通过。八次正常UI退出，最终会话0，原配置字节恢复，只停止本次代理与后台。无产品源码修改，未触碰正式数据。

## 创建未知结果的能力边界

当前比赛POST没有requestId服务端幂等收据。客户端机制是同登录进程内保留待核对草稿、未知时禁止直接保存、转赛程人工核对。不能照搬照片同ID重试，也不能在已经找到新比赛后点击“确认未创建”再次提交。15A只验证正常流程；15B按下文独立验证未知创建人工核对与编辑409，不改变此能力边界。


## 15B：未知创建人工核对与编辑409（原生已完成）

全新匿名库、唯一对手；代理只对首次真实POST收到完整201后切断下游响应，随后POST硬阻断仅作安全网。页面真实进入未确认状态、保存禁用；实际前往赛程草稿找到唯一新比赛并打开详情，未点击“确认未创建”。不重新编译或换账号，再进入新增仍保留待核对和禁保存。POST尝试总共1次，额外被阻断尝试0次，数据库唯一记录，不是靠代理挡住重复写后冒称客户端正确。

待核对草稿未阻止打开既有ID编辑。A真实输入编辑稿，B独立匿名API以当前revision修改该目标记录并退出；A实际PUT返回409，保留A稿并禁保存。重新载入取消前后请求记录完全相同；确认后只发生会话/赛季/球场/目标比赛GET，没有自动PUT，页面读取B稿及新版本。最终唯一记录revision2，其他业务摘要不变。

辅助B登录脚本前两次使用fetch被native入口403拒绝，没有会话或业务写；改用既有native HTTP协议成功，失败记录保留，不当成功证据。A正常UI退出、B辅助会话正常注销，最终会话0、配置恢复、自有服务停止。

本批没有新增产品代码，不声称同requestId幂等、跨完整重启恢复；没有测试真正未落库时人工确认继续，也未新增窄屏布局验收。
