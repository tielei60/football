## 如何阅读结论

- **原生操作**：微信开发者工具中真实输入、点击、选择或拖动，运行生产控制器，并按需要核对匿名数据库。本表“已覆盖”只采用这类明确记录，不等于真机通过。
- **API辅助**：建立匿名前提、制造另一会话并发、核对权限或数据库，用于支持原生链路；不冒充用户在页面完成该操作。
- **视觉检查**：32页正常态三宽及部分长页、状态图已核对。匿名视觉夹具没有完整业务控制器，其图片/地图/画布占位不证明功能可用。
- **单测/模板渲染**：证明已检查的代码契约与模板可运行，不代替原生业务操作。
- **外部能力**：真实微信绑定、地图定位导航、AI服务、相册/文件权限及iOS/Android真机另行验收，不擅自配置密钥、外发真实照片或产生费用。

第二阶段的“30页打开”仅算基础加载，不推导每个按钮、保存、删除、上传或导入导出都已通过。战术以第九阶段重新验证的**新主题**结果为准，不沿用旧基线失败或旧主题截图。第十三阶段账号初始化是匿名测试前提，不是UI创建系统管理员。

优先级：**P1**为写入一致性、权限和核心业务闭环；**P2**为正常流程与错误恢复补齐；**P3/外部**为补充视觉及需真实平台能力的验证。未列出某个边缘场景不表示该场景已通过。

## 建议后续批次

1. **名单→数据统计闭环**：比赛名单、赛季阵容、球队统计。验证进球、助攻、出场与赛季/年度口径，不只拍页面。
2. **核心资料写入与防重**：比赛新增、球员、赛季、球场。每页先正常保存重进，再核对未知结果与409。
3. **战术真正持久化**：新建→阵型→画布→编排→导入导出。此前战术演练刻意保持零业务写入，不能据此声称保存/导入完整通过。
4. **球员相册异常链路**：可复用比赛相册的隔离代理思路，但须使用球员相册自身API和恢复逻辑，不继承比赛相册通过结论。
5. **微信/AI分层验证**：先完成可本地模拟的权限与恢复，再单列真实平台依赖，保持密钥、照片、费用边界。

通用剩余项包括真实请求触发的加载/失败重试、软键盘遮挡、真机及外部权限。单次375或320截图不代表所有状态三宽均已签收。
