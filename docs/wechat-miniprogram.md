# 微信原生小程序：实现范围与验收

初始实现基线为 `main` 的 `0703a5bd872ab127e1f904c719bb398dc7ffe601`，原生客户端位于独立 `miniprogram/`。当前文档描述本地工作区的后续管理、相册与战术扩展，不表示这些未提交改动已合并或发布。历史阶段记录单独标注，不作为当前实现范围。

## 从参考到本项目

研究来源为 [两款小程序观察记录](research/README.md)。实际查看了京蔚联首页、赛程、球员、统计截图及大志有球活动详情；其余依据研究记录，不声称重新操作了竞品全部功能。仅借鉴信息层级，不复制品牌、截图、头像、个人信息或未知规则。

| 参考特点 | 本轮实现 | 保持的业务边界 |
|---|---|---|
| 下一场突出、日期和报名直达 | 首页球队摘要、下一场比赛、近期赛果 | 不编造倒计时、队服、人数上限或天气 |
| 日期分组、即将开始/已结束 | 赛程状态分段、月份分组、日期和周几 | 草稿仅管理员可见，取消不混入已完赛 |
| 报名、待定、请假可见 | 比赛详情三态本人回应、人数及名单 | 不自动签到或记出场，不引入费用 |
| 球员卡、搜索、位置筛选 | 球员列表和个人档案 | 不推算年龄、身价、能力或荣誉 |
| 年份榜单、数据完整度 | 显式赛季/自然年、出场/进球/助攻榜、覆盖提示 | 未知保留“—”，报名不等于出场 |
| 移动组织效率 | 管理员新建/编辑比赛、发布/取消/完赛、比分复盘 | 名单原生录入；完整战术编辑仍使用网页，不删除原功能 |

配色沿用球队浅紫体系：主色 `#8845A0`，白色卡片、浅薰衣草底和冰蓝辅助色；统一在 `app.wxss` 管理。采用原生 Page、WXML、WXSS、wx.request 和微信组件，不是 WebView、Vue 或跨端框架套壳。

管理员写入球队、球员、赛季、球场、名单、须知与相册；球员按服务端权限查看资料、赛季阵容和比赛内容。原始 9 页与管理扩展阶段的 17 页仅为历史数量。

- 未登录不返回俱乐部数据，不提供访客公开名单；客户端隐藏不替代服务端授权。
- 球员只修改自己的报名、自己的密码；管理员不能借任意 playerId 冒充报名。
- 管理员可在小程序创建/编辑比赛，包括赛季、日期/开球时间、比赛制、主客场、状态、比分和复盘。现有网页保留所有完整管理能力。
- 历史名单展示保存的身份、号码和实际出场，不以当前资料覆盖旧快照。原生战术画布展示当前模板或比赛留存快照；历史快照只读，管理员仅能调整当前模板的初始球员站位，不等同于网页完整战术编辑器。
- 编辑冲突保留输入，需人工核对后重新载入；不盲目重试覆写。加载失败、会话过期、空列表、防重复提交、迟到响应、隐藏 Tab 清理均有处理。

## 登录方案与部署前提

首期使用已有俱乐部账号登录，**不是微信一键登录或微信身份绑定**。页面对此明确命名，不自动建号，不依赖 AppSecret。管理员可通过网页或小程序球员管理建立账号及重置密码。

新增 `POST /api/auth/native-login`，JSON `{username,password}`，请求头 `X-Football-Client: native-v1`。返回 `{token,expiresAt,user,team}`。后续原有 API 使用 `Authorization: Bearer <token>`。

- 原生会话与浏览器 Cookie 不能互换。服务端保留原 Cookie/Origin 防护，原生请求拒绝 Cookie、Origin；Sec-Fetch 默认拒绝，仅兼容实际微信 Electron 模拟器的完整三元组（site=same-site、mode=cors、dest=empty），不接受额外 Sec-Fetch 头。此元数据不用于认证；微信自动 Referer 不被误拒。
- 令牌为 256 bit 随机值，带 `native_` 前缀，数据库仅存 SHA256；7天过期，登出、改密、管理员重置、归档沿用统一撤销。
- 客户端不保存密码，不把 token 放URL或页面data；会话缓存与服务地址绑定，换服务器不会把旧token发过去。微信本地存储不是硬件加密保险库，设备解锁后的本地提取风险仍存在。凭证存储不含大幅队徽，图片单独保存在应用专用可清理缓存，启动/退出时尽力清理（文件系统报错时不保证无缓存残留）；磁盘不可写或缓存达到上限时退回字标。
- 不开放任意 CORS，不为了小程序关闭现有网页 CSRF 校验。
- 不自动上传发布、不注册微信账号、不接受微信协议。需要所有者自己的 AppID、审核资质、HTTPS服务及 request 合法域名。AppSecret 永远不能放客户端代码或提交仓库。

真正微信登录可后续独立增加服务端 code2session、管理员邀请/本人密码绑定、解绑与撤销。不能仅凭客户端 openid 或球员ID绑定账号。无需为此阻塞现有账号闭环。

## 本地运行

1. 仓库根目录进入 `app`：`npm ci && npm run build && npm run demo`。演练只创建隔离的虚构 SQLite，终端给出实际地址和随机管理员/球员账号。
2. 微信开发者工具导入仓库 `miniprogram/`。`project.config.json` 的 `touristappid` 仅供本地开发占位；真实设备/体验版使用自己的 AppID。
3. 在本地 `miniprogram/config.js` 填终端实际端口，例如 `apiBaseUrl: 'http://127.0.0.1:13001', allowLocalHttp: true`。这是服务根地址，不含 `/api`。开发者工具本地调试时按微信工具要求处理域名校验；不要在生产关闭HTTPS校验。
4. 登录终端生成的账号，按下方清单演练。若 demo 绑定随机端口，必须用实际输出端口，不能照抄示例。
5. 真机不能把 `127.0.0.1` 当云服务器；请部署HTTPS服务，将其配置为小程序 request 合法域名，设置 `allowLocalHttp: false`。不默认暴露本机或业务库到公网。
6. 所有后端运行/备份规则仍见 [部署说明](deployment.md)。场地扩展采用增量迁移，新增场地表与比赛场地快照字段；升级前仍须备份。

测试配置不得提交真实服务密钥、密码、生产数据库或私人图片。

## 当前扩展：赛季阵容、相册与原生战术

### 赛季阵容

- 管理员选择球队成员、编辑赛季号码、移出阵容；球员只读。页面明确区分在队/归档状态。
- 姓名、位置采用赛季留存资料，赛季号码可独立调整，不改球员当前号码。空号码为未知，0 是明确值。
- 与赛季名称/时间编辑共享 revision。409 保留输入，不能自动拉新版本覆写；移出不删除历史比赛快照。
- 原生开发者工具已验证：同一虚构球员赛季号码保存为 89，球员当前号码仍为 88。

### 比赛须知与相册

- 须知最多 10000 字；管理员保存，成员按比赛可见性阅读。
- 每场最多 9 张照片，每张 PNG/JPEG 解码后最多 2 MiB。选图由用户操作系统选择器触发；图片逐张鉴权读取，不放外部公开 URL。
- 上传、封面选择、移除与比赛共享 revision。上传另有 requestId 幂等键；不确定响应保留同登录、同比赛的私有内存任务，以原键核对重试，不重新生成重复上传。
- 相册操作不覆盖未保存须知；显式重新载入前确认丢弃，离开有未保存内容时提示。图片 base64 不进入页面 data 或会话持久存储。
- 开发者工具已通过系统文件选择器上传项目测试图（照片 2），设为封面 2，移除后封面回退到照片 1；须知保存也已验证。GET/POST 权限与幂等另外有真实 HTTP/隔离 SQLite 回归。

### 原生战术能力与边界

- 当前模板、比赛历史快照可在原生画布查看，支持演示步骤与训练文字；历史来源标明关联留存或迁移留存，不用现模板替换历史。
- 管理员可编辑当前模板的初始球员位置；服务端只接收已有球员 pieceId 和坐标，保留球、标记、箭头、演示阶段等非本次编辑数据。
- 当前按用户要求改为竖向球场，屏幕坐标与服务端标准坐标双向转换。开发者工具已实际选中门将、向下拖动 15 px 并保存：标准坐标 x 从 135 变为 170.945，y 保持 413；比赛 1 的历史快照 x 仍为 135 且 canEdit=false，2 个演示步骤、2 个标注保留。这证明该次原生触摸、保存及历史隔离链路，不代表完整网页战术功能全部验收。
